# Restricted CPU RAW admission — reviewed decoder integration plan

Source-only plan reviewed against accepted capture/decoder components on main e04fce18. No implementation, compilation, execution, asset generation or new API acceptance. Supersedes only the obsolete decoder-entry assumptions in LIVE-RAW-CPU-PROFILE-PROPOSAL.md; retains its narrow profile and all exclusions. Checkpointable next work is a pure admission plan/tests and an Unsupported scaffold, not a renderer.

## Existing foundation and the missing bridge

Accepted `CapturedRaw::decode_cfa(self, cancel)` consumes the retained capture, keeps the actual native handle inside a private scope, and returns `DecodedCapturedCfa { image: CfaU16, metadata, identity, route }` only after successful cleanup. Original-path replacement cannot redirect those completed reads. Cancellation remains between synchronous native phases; neither unpack nor native allocation is bounded by that component.

`RawImage::new` accepts normalized `CfaImage`, not `CfaU16`. `RawImage::open` must not be used here: it reopens a locator and includes RGB/LinearDNG routing. The missing adapter must consume the owned integer plane and metadata without another file/probe/decode call. `raw-decode/src/lib.rs::linearize` is currently private and takes `libraw_ffi::CfaImage`; it applies full-sensor CFA phase, per-channel black/white normalization and clamp [0,1.2]. Feeding integer samples to `CfaImage::from_linear`, normalizing again later, or silently selecting a different clamp would be wrong. A future conversion should share the existing normalization implementation where practical, preserve its ordering, and validate black/white and sample count with checked arithmetic before allocation. This preserves existing clamped camera-linear sensor normalization, followed later by the proposed display-referred output contract. It does not introduce a signed/HDR sensor-normalization contract.

Important authority limit: `DecodedCapturedCfa` fields are public, so an arbitrary caller can construct or mutate a value/identity. Matching its claimed digest to a descriptor does not authenticate sample provenance. Do not call a public `render(decoded, descriptor)` an authenticated resolver.

## Ownership and visibility

Keep `engine-api` limited to pure value/descriptor validation; no dependency on raw-decode/image-core. Place prospective admission/assembly in image-core (already depends on raw-decode), behind a private module initially. Public existing capture/decoder APIs stay unchanged during the pure scaffold step.

The eventual trusted resolver should own the sequence descriptor → expected-byte capture → closed decode → metadata admission → conversion → CPU render. Only its private continuation consumes the `DecodedCapturedCfa` freshly returned by the decoder; no caller-provided path or forged decoded bundle can substitute between these steps. Before decode, compare the captured digest AND byte length plus its declared route with the descriptor and explicit closed-CFA policy, retaining exact recipe bytes. CapturedRaw.route() is a caller-supplied declaration, not a content classification. decode_cfa performs the actual supported-content classification; verify the returned route and metadata again before conversion. Current descriptor has no typed asset/route accessors beyond its serialized wire; a minimal read-only accessor addition requires review before wiring—do not round-trip untyped JSON in the renderer or change descriptor v1 silently. Pure synthetic tests may construct decoded values, but those prove admission arithmetic, not provenance.

The render worker owns its reservation and input until terminal completion/drain. Dropping an observer or signalling cancellation must not release admission while synchronous work continues. A successful result owns its pixels and profile bytes (and appropriate retained-byte accounting); no renderer/session, capture path, native handle or unbounded callback escape. On failure publish nothing; preserve descriptor and input files. Do not add a public production resolver until the prerequisites below are resolved.

## Admission order and unchanged narrow profile

1. Before capture/decode: descriptor schema/owner/Raw/explicit Native2 and exact current settings validation; expected route; trusted matching environment/output-profile identity; request concurrency/byte reservation. Recipe validation must be immutable. Reuse PinnedRawDescriptor::new/check_shape, which already rejects unknown nested current-settings fields and retains exact recipe bytes, then apply the narrower profile predicate. Preserve accepted omitted defaults and legacy profile-reference representations; do not impose byte equality with a serde projection or silently redefine descriptor v1 compatibility. Preserve original recipe bytes even when refusing.
2. Keep the existing proposed subset: explicit Bilinear/no model, Denoise Off, default camera-profile settings, no local adjustments/retouch, no depth/lens blur, no LUT/point-color/proof/HDR override, neutral recipe geometry. Require exact neutral lens template (profile None and CA false, all remaining values equal specified defaults). Run the existing CPU settings validator as an additional check; it is not by itself dependency/version admission. Supported tone/detail pass unchanged, including default sharpening. No setting is reset to make admission succeed.
3. Capture expected bytes through the accepted owner and decode only its closed CFA route. Bayer-only profile is narrower than the decoder: XTrans/unsupported layouts refuse. No ImageIO/RGB/LinearDNG fallback.
4. After decode, before new sample/render allocation: checked sensor dimensions/count, matching image/metadata dimensions/layout, valid full-sensor Bayer phase and default crop, finite/usable calibration, orientation=1, supported metadata correction semantics, and finite memory plan. The first profile should refuse gain-map/opcode-dependent metadata unless explicit treatment is reviewed; absence of proprietary corrections is not evidence of camera fidelity. Metadata-based refusals necessarily occur after native decode with today's API.
5. Convert once using existing scalar RAW normalization. Construct a fresh `RawImage` and fresh CPU Renderer: explicit Native2, m2 graph, every stage memo flag disabled, cache budget0, threads1, preview approximationsfalse; no injected GPU/ML/depth/DCP hooks or shared session caches. Level0/default active crop only. SceneLinear → existing `display_float` with fixed sigmoid and admitted gamut → finite check → one clamp/round to opaque U16 sRGB. Never use dithered U8 Display as the intermediate. No resize/additional output sharpening/orientation transform.

## Prerequisites to close before any renderer implementation

### Memory and cancellation

Define concrete finite sensor/active pixel caps, request output-byte cap, permitted concurrency (initially one request is the simplest proposed policy), and a checked peak-live-allocation model for this exact route. Do not invent numerical caps without inspecting its live buffers. At minimum account for 2*S owned CFA bytes retained during 4*S float normalization; 8*A output bytes; SceneLinear/display tile payloads, halo padding, stage intermediate vectors, graph recomputation, metadata/opcode payloads and any assembly coverage buffer. S=sensor pixels; A=active pixels. Those terms are a required inventory, not a proven bound. Renderer cache_budget0 is not a working-memory cap; threads1 does not imply tile-at-a-time retention. Current rendering code collects stage batches and returns multiple tiles.

Resolve whether full-frame vectors require a conservative upper bound or an actually bounded assembly path. Reserve before the first new allocation, use checked products/additions and fallible allocations where APIs support them, and hold reservation through drain/output ownership. In tests force low budgets; no giant allocations needed. Bound normalization and assembly cancellation checkpoints, but state existing noninterruptible calls honestly.

A post-decode sensor cap cannot bound LibRaw's already-completed native allocation. The first component may explicitly claim only post-decode application allocations; a whole-decode/process cap requires a separate supported native/preflight or isolated-process policy, including the temporary cfa_data copy currently made by RawSource.metadata(). Do not relabel the accepted capture byte quota as either bound. Root must accept this scope before wiring a pixel resolver.

### ICC

Select and check in reviewed, licensed, fixed sRGB ICC bytes with a declared SHA256/content identity and output-contract version. Verify the profile actually describes the encoding produced by the fixed display conversion. Current Builtin::Srgb generates via LCMS and is not a fixed artifact suitable for an immutable identity claim. No runtime regeneration/timestamp-dependent bytes; missing/changed bytes refuse. Tests can use a synthetic token for pure admission but cannot thereby qualify actual ICC output.

### Environment

Define a trusted host-supplied, verified manifest bound to the actual native artifact, route/wrapper normalization revision, output contract/ICC, target/CPU feature selection, and relevant runtime OS/library boundary. Existing crate/version strings and recipe Native2 are insufficient. Avoid circular self-hashing: use an external packaging manifest verified by a specified bootstrap owner. Caller-supplied strings in a descriptor never authorize an environment. Missing or mismatched identity refuses before capture/decode. A persisted pairing between descriptor input identity and render environment/output profile is needed; descriptor v1 currently stores neither. Keep it a separately versioned proposed request/envelope until its compatibility contract is reviewed. No graph schema update, self-referential executable hash or new packaging implementation in this draft.

## Deterministic acceptance sequence

A. Pure tests/scaffold first: valid narrow recipe and synthetic metadata; table-driven individual refusals for process/schema/unknown nested fields/dependencies/settings; claimed input/environment/profile mismatches; Bayer/layout/crop/orientation/calibration failures; checked-overflow and exact-budget boundaries. Inject counters so early failures prove no capture/decode/normalization/render or publication. Unsupported scaffold produces meaningful RED; no expectation that pixels already exist.

B. Only after memory/ICC/environment decisions are reviewed: adapter controls compare normalized samples with the existing scalar normalization for all Bayer phases, differing black levels, below-black/above-white values and active crop; no duplicate normalization; cancelled conversion has no published output. Private owned-value lifetime tests prove no reopen after decode and reservation drain on every result/error path. Reuse accepted capture/decoder tests; add only seam-specific replacement/mismatch/ownership controls.

C. CPU/output tests: multi-tile non-square active crop, fresh renderer independence, disabled shared memo and absent GPU/ML factories, unchanged supported detail/tone. Compare float assembly with an independently assembled existing CPU reference at a justified stated tolerance, verify full single coverage, finite channels, opaque alpha, one quantization and >256 levels. Existing synthetic c334 test is already integrated and passed; expand only for the newly implemented seam, do not relabel that test as real RAW qualification.

D. Explicit opt-in real Bayer fixture(s): preserve hashes before/after, exact expected recipe/profile/environment, original replaced only in an owned copy after capture, owned outputs survive cleanup, deterministic cancellation boundaries and mismatch refusals. Choose orientation1/default-crop coverage from actual metadata, not a guessed camera family. The accepted decoder's five camera-family tests do not qualify all five for this narrower Bayer/orientation1 renderer.

E. Focused affected-crate tests, full affected suites, strict/fmt and immutable source/artifact/fixture evidence under the coordinator's sole runtime grant. No current draft gate has run. Host-wide performance, peak native memory, persistent cache and GUI remain outside acceptance.
