## Minimal qualified-run protocol

Use a fresh per-run control directory, unique run nonce, copied fixture, disposable app-support directory, and the already source-pinned unique Release app. Keep the existing unique process identity checks (PID, bundle ID, bundle URL, launch date). Use one visible regular window and one captured `DevelopController.timingSession` throughout the measurement.

1. **Warm and prepare outside measurement.** Load the copied RAW, mount the real grid, select the intended photo, open Loupe/Develop, and allow initial decode, surface attachment, and a baseline actual presentation to settle. The current 1.5-second delay may remain as a minimum settling delay, but readiness must also identify the controller session and a positive `drawable_presented` for its current session before signaling ready. No timed input is sent before the permit.
2. **App readiness record.** The app atomically writes a `ready.json` containing the fresh nonce, PID, bundle ID, window number, Develop session UUID, and its `CACurrentMediaTime` ready timestamp. It then waits boundedly for a matching `start.json`. The app must revalidate that the same controller/window still exists, `NSApp` is active, the window is key/visible/occlusion-visible, and the nonce/process/session/window fields match before accepting the permit. Wrong/stale permits, app deactivation, session replacement, or timeout fail closed.
3. **Runner qualification and start.** The runner waits for `ready.json`, validates it against the pinned process, then requires a short stable foreground dwell (for example 500 ms) with repeated WindowServer samples for the exact regular `windowNumber`, frontmost PID, onscreen state, and no reported foreign overlap. Have the Swift probe record `CACurrentMediaTime` on each sample so its samples and trace events share a host monotonic clock. After qualification, atomically write the nonce-bound start permit. The app records `measurement_start` in `PerformanceTrace` immediately before the first test input, using the captured Develop session and its normal `CACurrentMediaTime` timestamp.
4. **Bounded input and presentation interval.** Drive the entire fixed Exposure sequence in every run (currently 121 calls for values 0…1.5). Preserve input IDs and require at least 100 distinct inputs in the captured session whose `input` timestamp is at/after `measurement_start`; each counted input must have its same-session dequeue, callback enqueue, and positive actual `drawable_presented` timestamp, with matching generation/level identity and the existing causal ordering. Do not stop the fixed sequence when the first 100 inputs present: that would shorten the workload and bias its tail. After the last call, allow a bounded presentation drain until the *final input* has its actual presentation; only then record `measurement_end`. The analyzer then counts every causal join within the full interval and requires at least 100. Fewer than 100 joins, missing final-input presentation, no positive presentation timestamps, trace drops, or timeout is a failed/unqualified run, never zero latency.
5. **Visibility qualification across the interval.** Sample foreground/window state throughout the run, not just at completion. Target a 50 ms probe cadence and enforce a maximum *observed* gap of 250 ms using each helper’s `CACurrentMediaTime` timestamp; do not assume requested sleep is achieved, since every probe invocation adds overhead. Require samples to bracket the app's interval markers and match the same PID and `windowNumber`. Also record an app-side visibility check at each input (or a short main-actor cadence): `NSApp.isActive`, the same key window, visible and occlusion-visible. If foreground is lost, a different process/window/session appears, or an observed gap exceeds 250 ms, preserve outputs but reject the run. Report sampled visibility only: 50 ms samples cannot prove continuous visibility or that every pixel was unobscured between samples.
6. **Summary filter.** Extend the analyzer to take the exact session and interval bounds. Count only `input` events inside `[measurement_start, measurement_end]`; require the full causal chain and actual-present timestamp for each counted input to also lie within that interval. Require at least 100 unique `(session,input)` joins, zero dropped records, stable process/window/session identity, and successful ready/start/end markers. Never aggregate inputs from another session or startup warmup. Include interval timestamps, qualifying sample timestamps/gaps, number of in-interval inputs, number of in-interval causal presentations, and explicit failure reason in the result.

A small Python analyzer test should include: 100 valid in-window joins pass; 99 fail; final-input presentation after end fails; an input from a different session cannot contribute; a startup input before `measurement_start` cannot count; missing/zero presentation time, dropped records, reused process identity, wrong window, and a visibility-sampling gap fail. A small Swift protocol test should cover stale nonce, wrong PID/window/session, duplicate start, early end, timeout, and exactly one interval. Keep trace capacity and atomic publication checks; don't silently truncate or retry into a second session.

## Clock and self-test implementation note

`PerformanceTrace.record` defaults to `CACurrentMediaTime`; a small extension can add marker names (`measurement_ready`, `measurement_start`, `measurement_end`) and session ID without changing existing causal fields. Put a fresh run nonce in the control files and summary; because each isolated process has one trace and one Develop session, the session UUID plus nonce-bound handshake is enough to prevent stale cross-run joins. The WindowServer helper should emit its own `CACurrentMediaTime` sample timestamp, allowing post-run interval coverage checks without comparing Python's `time.monotonic` epoch. Keep Python monotonic only for deadlines. If the shared-clock premise is not validated on the target OS, use a start/stop handshake with app-generated timestamps for both app and helper status, or explicitly decline to qualify the interval.

The smallest code seam is an opt-in control-directory argument used only by `--timing-visible --timing-selftest`. Keep current background mode unchanged. Refactor the Developer self-test's fixed loop so the visible mode waits at the start permit and exposes completion only after actual-present drain; don't infer completion from 121 total trace inputs (that count includes unrelated/startup work today). Retain fresh isolated state and an explicit bounded timeout. No change to `LoupeRenderer`'s positive `presentedTime` oracle is authorized by this plan.

## Limits and evidence

This plan defines a minimal next diagnostic, not an acceptance result. Actual presentation can be unavailable on a machine/display even with a visible regular window; such a run should fail qualification and retain diagnostics. Window-server ordering, `NSApp` state and occlusion flags corroborate visibility but cannot guarantee perfect non-occlusion. No P11 evidence, product threshold change, performance pass, or UI acceptance is claimed here.
