## Concrete caller boundary

`open_develop_source` (develop.rs:1025 onward) must finish source/container/journal/recipe/sidecar checks before obtaining reuse eligibility. `validate_proxy_recipe` (smart_preview.rs:701) checks Native2 and captured prefix only: it is NOT the complete external-dependency guard. At selection, apply the explicit conservative predicate above and call the candidate GPU renderer's capability with the same temporary SDR settings as `backend.rs::select_proxy` (160–183). `can_render_resident` (image-core/src/resident_render.rs:455) delegates to proxy validation and derived-map refusal. Checking a selectedCPU renderer would falsely deny measuredCPU hits.

Current scalar validation (pipeline-cpu/src/render.rs:425–480) rebuilds an allowed settings subset: it excludes camera profiles/looks, LUT, proof profile and other unsupported controls. That provides a second fail-closed check; do not rely on it alone for future dependency policy. It must not be loosened to make cache qualification pass.

No active path-only external dependency was found in the presently eligible unmasked/noLUT Native2 proxy tail. The risk is broadening eligibility after resolver/validator changes: ModelRef/StyleId/ProfileId or imported digest strings are not sufficient evidence of consumed bytes. Fixed typed settings serialization protects values, not mutable resources named by those values. Profile/LUT/runtime-mask cases require bypass now; recorded prefix dependencies are instead secured by full container identity and unchanged-prefix admission.

No public API, new resolver or external asset hashing is recommended for this slice. The checklist is for a deny-by-default guard and source review of its placement; existing control-enum tests alone do not qualify real external dependency discovery.
