## Independent reference candidate and provenance

Use **Google libultrahdr** as an independent small-file producer, pinned to an exact immutable upstream revision before execution (e.g. tag `v1.4.0` points to `d52a0d13814ca399fc8a07e23de1d2c63f0e8404` at research time). Its [project](https://github.com/google/libultrahdr) identifies itself as the reference Ultra HDR codec. Its [public API](https://github.com/google/libultrahdr/blob/main/ultrahdr_api.h) documents JPEG output, direct compressed SDR base plus compressed gain-map API, `max_content_boost` and `hdr_capacity_max` in linear scale, decoder probe and separate SDR/HDR output. The [sample application](https://github.com/google/libultrahdr/blob/main/examples/ultrahdr_app.cpp) exercises the compressed base/gain-map/metadata route; the [JPEG implementation](https://github.com/google/libultrahdr/blob/main/lib/src/jpegr.cpp) emits the container. Pin exact source and library binaries; do not imply a file is known-good merely because that encoder returns success.

Generate only 80×16, three flat non-neutral patches, with a clear 1× SDR/base highlight and gain toward 16× (plus 4× lower control), using independent JPEG base/gain input bytes and API-4; select one-channel gain, ISO 21496-1 version 0 plus MPF JPEG, sRGB base, and no Tessera encoder calls. This is a *candidate* until the reference decoder and a second parser confirm the exact output. Keep encoder-generated XMP/ICC/metadata intact for the first cross-vendor comparison; do not strip or rewrite the control to resemble A. Record input bytes, metadata fields, encoder revision/options, generated JPEG SHA-256, dimensions, MPF offsets, ISO rationals, decoded gain patch values and reference-decoder SDR/HDR RGBAf values. Require the reference-decoder measured bright patch to exceed 8×, rather than trusting declared capacity. If its API cannot create this precise ISO v0/MPF case or yields ≤8× actual pixels, stop and choose another control, not a looser assertion.

An alternative preexisting publisher-labeled 4-stop ISO set exists at [Eric Chan's MIT-hosted test photos](https://people.csail.mit.edu/ericchan/hdr/jpeg-gain-map-iso.html), but that page explicitly prohibits copying/reproduction without written permission and its large Display-P3 photos are not suitable for a retained, tiny sRGB fixture. IS&T's [ISO test sets](https://www.imaging.org/IST/IST/Standards/ISO%20HDR%20Images%20Test%20Sets.aspx) are CC BY-NC 4.0 but require account/ZIP checkout and are not a bounded small control. Existing pinned Google Skia JPEGs are valid ratio-4 controls only; they cannot decide the >8 question.
