# Smart Preview opening latency: bounded next experiment

Source-only audit of accepted backend.rs/lib.rs/develop.rs and preserved fbd0f266 Engine/IOSurface qualification. No implementation, benchmark, app/GPU workload or default change. Accepted behavior and fidelity gates remain unchanged.

## Measured baseline and what it means

Existing GPU-integration VALIDATION.md records final SDR proxy-auto open625ms, CPU42ms, forcedGPU74ms; first-surface delivery after open4.2/138.3/26.8ms respectively. AutoEDR open791ms. These are bounded samples from the accepted fixture/host, not latency percentiles, cold-filesystem measurements, or physical input-to-screen results. Open and subsequent surface delivery are different intervals: their rough SDR sums629.2/180.3/100.8ms illustrate why reporting the4.2ms callback alone hides material startup cost, but are not a new end-to-end UI measurement. EDR calibration uses SDR presentation before host headroom is known; EDR output capability was qualified separately.

Current code explains a plausible cost center, not its exact percentage: open_develop_source reserves source ownership and validates/loads the local asset/recipe, then synchronously calls develop_render_resources before returning the session. Proxy develop_renderer calls select_proxy every open. select_at constructs fresh CPU/GPU backends and measures three sequential CPU frames and three sequential GPU frames (initial, exposure, WB) into the real surface sink. The measured winner is returned with its warmed cache; calibration surfaces/results are not the host's first editable surface. Original already uses an Engine-scoped OnceLock backend decision, but proxy selection deliberately does not share it. GPU device is already Engine-shared; stage ops/tile caches are per proxy selection.

## Smallest justified optimization candidate

Experiment with a **small Engine-local cache of successful calibration decisions for an exact previously validated proxy opening**, storing only CPU-versus-Metal decision and measurement metadata, never Renderer/Backend/GpuStageOp/IOSurface or decoded proxy storage. Start with same-session-close/reopen, same Engine, same asset/recipe; no disk-persisted or cross-process cache. This specifically targets repeated opening; it does not accelerate the first-ever opening or guarantee a benefit when edits change the recipe. Do not loosen the key to gain hit rate without separate evidence.

Key must include validated proxy asset identity/incarnation and dimensions/tier, complete current render settings (including full output policy, even though temporary calibration settings normalize HDR), calibration level, renderer config/thread policy and selected device identity/generation. Engine lifetime plus immutable binary can scope implementation-version/device generation. Use a bounded entry count (propose16 for the experiment) and explicit short lifetime/invalidation policy; do not claim a stored timing remains an optimal choice after thermal/load changes. Every open still performs original/local conflict/recipe validation before lookup. No cache entry may authorize bypassing journals, source admission, or asset validation.

Explicit CPU/GPU overrides must bypass the auto-decision cache and retain current semantics. Do not cache transient device/construction/calibration failures as successful CPU decisions. A cache hit creates fresh stage operators and per-session caches, rechecks availability/capability, and still routes mapped geometry/unsupported tails through the existing per-frame CPU capability gate. If device creation fails, use the existing honest fallback. Do not retain heavy resources merely to reproduce the4.2ms warmed callback: current Weak lifecycle tests deliberately require their release.

This is smaller than asynchronous CPU-first publication followed by live GPU migration. That alternative changes renderer/cache ownership, adaptation, generation cancellation and route publication mid-session, and could make the first CPU frame slower than waiting for another path. It requires its own design and measurements. Likewise do not skip WB/tone calibration, reuse Original's decision, or assume forcedGPU is always preferable from one fixture. There is no supported first-ever-open optimization claim in this slice.

## Falsifiable qualification

Before implementation, retain accepted baseline and define one comparable measurement: public open call start through first matching-generation final host IOSurface receipt at the same requested viewport/settings/output. Record open-return time and post-open delivery separately as diagnostic components, plus actual render level/dimensions. The existing harness measures these pieces; extend it explicitly to repeated open/close of the same Engine/key, not fresh-process-only runs. Label listener/surface delivery, never physical presentation. Distinguish fresh process from cold caches.

Use a bounded baseline/candidate A/B sequence, e.g. five paired unchanged-key reopen cycles after one normal cold-decision open for SDR and EDR. Preserve raw samples/order, no tolerance changes. Required cache oracle: first miss still performs normal calibration, exact-key hit performs zero calibration renders, changing each key dependency misses, eviction remains bounded, explicit CPU override bypasses, and failed calibration cannot poison later selection. Record calibration counters test-only; do not add public API just for timing.

Acceptance hypothesis: exact-key reopen median open-through-first-surface improves versus uncached auto on the same machine/fixture/settings, with no first-open regression beyond measurement noise and no material warm-edit regression. If hit startup costs plus cold operator/cache renders erase the benefit, reject the optimization. Specify acceptable regression tolerance before runs from baseline variability rather than selecting a threshold after seeing results. Do not substitute forcedGPU74ms as a predicted cache-hit outcome.

For every delivered frame verify real selected route with submissions/resident receipt/zero timed pixel readback for eligibleGPU, geometryCPU with zero GPU submissions, exact same dimensions and existing SDR/EDR numeric bounds. Exclude unequal adaptive resolutions from ratios and report proxy spatial loss. Re-run same-key and changed-recipe lifecycle cases with Weak Shared/Renderer/GpuStageOp and owned ring release after cache lookup/close; a decision entry must retain none of those objects. Saved HDR/headroom and edited recipe must survive close/reopen; changed asset/recipe must never reuse stale pixels or source authority.

Residual limits: changed-recipe reopen will deliberately miss this conservative cache; cross-photo/device/general settings reuse remains unproven. Original editing-source default and accepted mapped-geometry fallback stay unchanged. Actual desktop first-editable timing would require a later UI-level generation/presentation definition; the proposed Engine gate alone cannot establish it.
