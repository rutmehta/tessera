# RES05: bounded admission for rasterized PSD copy (source-only proposal)

Source: B design `8363c8ae` (`tools/orchestrate/wp/B5-16/PSD-COPY-CANCELLATION-DESIGN.md`), A checkout `/Users/rutmehta/.codex/worktrees/export-integration/tessera` at `78492f7f` plus uncompiled PSD compositor cancellation diff, 2026-09-27. No product edit, build, workload or RSS measurement. This is a *work-admission weight*, not a claim that memory use is capped by it.

## Live allocation path

`document/transform.rs:1093-1125` snapshots committed state, clones a private state, then bakes each enabled smart stack sequentially. Each bake's `native_stack` (`document/filters.rs:600-661`) materializes a full interleaved `Vec<f32>` (nominal **16·P** bytes for `P = width·height`), while compositor tiles, filter inputs/outputs and its per-pass retained filter rasters may coexist. `raster_from_rgba` (`document.rs:2415-2445`) then builds a 4-channel tiled raster (**up to 4·D·P** stored sample bytes, `D=1/2/4` for U8/U16/F32) with one tile's f32 planes; previously baked rasters remain in the private state across later layers. The original source/child rasters and metadata are also retained via Arcs/clones.

`document/io.rs:348-362` passes that private document to PSD export. `compositor/src/psd.rs:2455-2600` clones retained PSD records, emits per-layer raw channels (up to **4·D·P** per canvas-sized pixel layer, plus masks/saved channels), renders another full **16·P** merged RGBA and keeps it while filling `source.composite` (up to **(4+S)·D·P** bytes for `S` saved channels; a temporary **D·P** plane vector is also live). `psd/src/layers.rs:337-395` duplicates/encodes layer channels into a growing `pixels` vector and layer section; `psd/src/lib.rs:136-158` builds a full output vector plus resource and composite compression buffers. The returned encoded `Vec<u8>` remains live with the private document and `PsdDocument` during chunked temp write. Opaque imported metadata, linked smart sources, masks outside canvas, compression expansion, Rayon/Metal workspaces, allocator capacity and kernel memory are not predictable from canvas dimensions alone. A 512 MiB image-cache setting is unrelated to this peak.

## Small implementable guard

1. Add a pure `estimate_psd_copy_weight(canvas, depth, saved_channels, rasterized_stack_count, emitting_leaf_count) -> Result<usize>` used at **run admission before the private state clone or evaluation**. Take the existing cheap committed `Arc<DocState>` snapshot under the state lock, release it, then count from that immutable snapshot and acquire admission. This avoids a count/snapshot race and never nests the process permit mutex with the document state lock. Use only `checked_mul`/`checked_add`, checked `usize` conversion and a checked total. Count groups recursively with checked increments. Reject zero/invalid dimensions, >56 worst-case output channels, and a composite decoded plane above the PSD encoder's existing **256 MiB** `compression::layout` limit *before* spending time baking. Use worst-case merged alpha (4+S), not a current-pixel guess. The estimate should include at least `16·P` bake output, `N·4·D·P` retained baked rasters, `L·4·D·P` emitted raw layer channels, `16·P` merged RGBA, `(4+S)·D·P` composite, and one `D·P` plane; document this as a conservative **modeled pixel payload** with intentional double-counting, not an upper bound on RSS. `N` is the smart stacks being baked and `L` is output raster-emitting leaves. No unknown metadata or encoder-vector size may be represented as zero *actual memory* merely because it is absent from the estimate.
2. Put a small **process-wide** nonblocking permit around these weighted copy operations, with an explicitly configured in-flight weight budget. Per-document one-copy admission from B's operation contract still applies, but is insufficient when two documents copy concurrently. Admit by checked `used + weight <= budget` under one short mutex; on failure return typed `ResourceExhausted`/regular bridge error before any snapshot/evaluator/temp file. Do not wait in a queue or hold this mutex during work. No hardcoded 'safe' byte threshold is justified by this source audit; the deployment policy must choose a budget after measurement and communicate it as an admission setting, not a memory cap. The pure estimator and injectable test budget can land first; enabling a default process budget needs that separate policy decision.
3. The RAII permit belongs to the running operation (not its UI handle), acquired before the private clone and held through conversion, encoding, temp write/sync and persist outcome. It releases only after all local output/snapshot buffers are dropped on success, failure or cancellation. Accepted cancellation does **not** free the permit while an opaque encoder or blocking IO call drains. A pre-cancelled/queued handle owns no weight; terminal cleanup and registry identity are B-owned. No error path may publish a partial destination. On estimator overflow, fail before allocation; on actual allocation failure, this is still not a guaranteed catchable error with existing `Vec`/`Raster` APIs.

This guard bounds simultaneous *admitted modeled work*. It cannot promise process RSS, prevent every OOM, or make a single admitted copy safe: compositor filter workspaces, off-canvas original records, encoder accumulation and full output bytes remain unbounded by the model. True peak enforcement would require measured budget choice plus deeper fallible/streaming allocator and encoder changes; do not label this first slice a global memory cap.

## Deterministic tiny acceptance

- Pure estimator on 2×2 fixtures: exact expected weight for U8/U16/F32, increases with one extra baked stack/leaf/channel, checked synthetic overflow without allocation, and early rejection of PSD composite layout that the writer would reject. Test `budget = weight-1` rejects and `budget = weight` admits; do not infer RSS from these numbers.
- Two distinct tiny document operations gated after admission: first holds process permit; second fails before snapshot/evaluator/temp creation. Release first, retry second succeeds. Per-document duplicate still follows B's separate Busy rule.
- Cancel first operation while a deterministic opaque-stage gate holds it; second remains rejected until first returns and its buffers/permit drain. Fresh retry succeeds. Also inject evaluation, encoder and persist failure and check permit returns to zero, source unchanged and destination sentinel intact except a successfully admitted persist.
- Keep existing B cancellation/commit race tests and compositor PSD pixel/opaque-resource parity tests. The admission test must assert zero calls before rejection, not just an error string.
