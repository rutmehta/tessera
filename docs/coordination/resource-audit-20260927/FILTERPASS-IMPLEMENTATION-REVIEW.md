## Finding

No correctness blocker found for the stated scope. `render_level_premultiplied` creates one pass per call and serializes top-level tiles whenever the document tree contains an enabled smart filter (`render/mod.rs:730-756`); direct `render_tile` remains pass-free (`:600-608`). This removes duplicate first-touch work for an oversized result within that one full-level frame while retaining reachability decisions in normal tile traversal. The detector may serialize a frame whose enabled filter is hidden or offscreen, which is a scheduling cost, not evaluation or admission of that content.

The pass stores an exact-key `Arc<Cached>` before per-object mask blending (`smart_filters.rs:493-665`). The key still comprises smart-object key, child revision, serialized filter digest, and native context digest. Both cold results and persistent-cache hits are charged. The short mutex protects only lookup/reservation/commit; neither it nor the persistent-cache mutex spans `source_raster` or evaluator work. `PassReservation` charges bytes and an entry before the cold source starts, keeps outer and nested charges simultaneously, and releases them on any error or unwind (`:278-350`). `entry_bytes` uses checked area conversion and multiplication (`:379-386`), and the separate 1 GiB / 256-entry per-compositor default is independent of `cache_budget` (`render/mod.rs:130-147`). The charge is for retained unmasked source+result, not all working memory, concurrent frames, or GPU allocations.

Context propagation covers `smart_tile` child refs, `source_raster`, synthetic style refs, and the `render_live_scene` path (`render/mod.rs:410-435`, `render/effects.rs:34-45,82-86`, `text_vector/damage.rs:234-246`). Other `DocRef` constructors explicitly use `None` where no full-level pass exists. The committed focused tests cover the 257×1 oversized first-touch case, cold preflight rejection, nested admission, hidden/disabled/offscreen/clipped avoidance, live scene plus styles, and the existing direct-tile Barrier(2) Rayon deadlock probe (`tests/smart_filter_deadlock.rs`). The uncommitted `same_key_mask_variants_share_unmasked_pass_entry_without_sharing_pixels` and `concurrent_full_level_calls_have_independent_passes` tests are valuable additional controls, but require their own gate before claiming they pass.

## Scope limits and follow-up checks

- The serial path affects *all* top-level tiles of any document containing an enabled filter, including warm root-cache hits or filters that never become visible. This may reduce throughput for such frames; measure separately before making performance claims. It does not warrant a correctness change now because actual tile traversal still decides whether a filter runs.
- The current `render_level` cancellation token is checked before each tile only (`render/mod.rs:739-743`); neither the pass nor `source_raster`/seam loops observe it during a long tile. Do not describe this commit as a cancellation fix. The separate transform cancellation kernel and compositor bridge plan address that gap.
- The 1 GiB admission charge is conservative nominal full-raster bytes. Transient transform planes, unmasked raster clones, mask blending, output tiles, persistent caches, multiple simultaneous passes, and evaluator-private memory can coexist above it. The error is a per-pass retained-result limit, not a process hard cap.
- The unit reservation test simulates an outer error by dropping a reservation; the integration nested test starts a new pass for its retry. Together they cover RAII state and user-visible retry, but a same-pass nested evaluator error/recovery is not explicitly tested. This is optional follow-up, not a blocker given the simple Drop implementation and existing passing gates.

I recommend keeping this committed change scoped as a per-frame duplicate-work and retained-result admission improvement, then integrating the transform cancellation bridge as a separate reviewed change.
