## Source observation and contract

`filtered_source` retrieves one unmasked `Arc<Cached>` from the frame pass, clones `cached.result`, then calls `raster.edit_region(Rect::of_extent(...))` on every reached output tile when `filter_mask.enabled` is true. `Raster::edit_region` calls `render_region`, which reads and rewrites every full-child tile before installing them. For a 257×1 F32 RGBA child, each mask application visits 257 pixels and produces 4,112 bytes of tile payload. A two-tile full-level frame currently performs that work twice, even though unmasked stack evaluation is once. The pass allowance charges source+unmasked result, not these transient masked rasters. This repeated CPU/allocation work predates RES-01; it is not evidence that it caused B's swap.

The tiny RED fixture stores one nondefault F32 mask tile, checks exact source/masked pixels, and requires one mask application, 257 visited pixels, 4,112 produced tile bytes, and a positive count of mask bytes scanned for a future digest. The current source should report 2, 514, 8,224, and zero respectively. Counters describe logical work and exact produced tile payload; they do not measure allocator overhead, total working set, or GPU memory. A separate existing fixture proves two cloned smart objects with the same unmasked key and different masks retain distinct pixel results within one frame.

## Proposed bounded implementation, after RED evidence and review

- Add a second map in `FilterPass` from `(exact unmasked CacheKey, mask digest)` to `Arc<Raster>`. Form the digest from enabled state, finite density/feather bits, raster extent/channels/depth/default, ordered slot coordinates/tombstones, and each stored tile's format/layout/sample bytes. Hash real tile bytes rather than `max_rev`, pointer address, parent `LayerId`, or the unmasked key alone. Validate mask layout/density/feather before lookup so an invalid mask cannot hit a prior result. If a stored sample is invalid, preserve today's error behavior; do not publish its masked result.
- Digesting a dense mask on each `filtered_source` call still scans O(stored mask bytes). Increment `mask_digest_bytes_visited` for those bytes. The mitigation bounds full-image blending and output tile creation to once per exact mask variant per pass, not all mask CPU work. Sparse default masks have cheap digests; the RED fixture's stored tile makes the scan observable.
- Before materializing a cold masked variant, reserve one additional entry and the checked sum of F32 RGBA output tile payload bytes against the **same** per-pass 1 GiB/256-entry allowance. Hold RAII charge while rendering; retain the completed `Arc<Raster>` until pass end. Return `ResourceExhausted` before mask pixel work if the allowance cannot admit it. Keep the unmasked source+result charge, so a 257×1 source with one masked variant needs 8,224 + 4,112 = 12,336 retained bytes and two entries. No pass mutex is held while hashing samples, blending pixels, or creating tiles; no per-key wait is introduced. Direct tile calls remain pass-free and may repeat work.
- Apply a mask-specific key, not the unmasked key, to preserve different masks on cloned smart objects. Mask-only edits in later frames have fresh passes and are re-evaluated appropriately. Mask pixels are blended before the existing smart-object affine sampling/mip path, preserving current interpolation/halo order. Reuse the same unmasked and masked rasters only within a single immutable document snapshot/pass.
- Keep the whole masked result out of the persistent cache in this slice. This is per-frame work reuse, not a global memory cap. The pass entry bound should count both unmasked and masked retained entries; error paths release both reservations. Test exact pixel parity with direct-tile rendering and masks across normal, styled, nested, and edited-frame paths before integration.
