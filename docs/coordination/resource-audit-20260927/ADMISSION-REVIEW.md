# A read-only review of B resource admission (2026-09-27)

Source: `origin/wp/B5-16` at `131af17d735c648bb5d335e9f79b7b6b2b063c1b`; audited `tools/orchestrate/wp/B5-16/RESOURCE-AUDIT.md`. This review used `git show`/`git grep` only. No B process, build, test, or product edit was started.

## Smallest safe first change

Move cold **cacheable** CPU smart-stack evaluation above the tile `par_iter` in `Compositor::render_level_premultiplied` (`crates/compositor/src/render/mod.rs:690–723`). On the caller thread, traverse the requested document's reachable group/smart-object graph, deduplicate by the exact key already built by `filtered_source` (`render/smart_filters.rs:288–302`), and pre-evaluate enabled stacks deepest-first before spawning tile workers. Bound traversal to objects whose transformed bounds intersect the requested canvas/region, and check the caller's `CancellationToken` before and between stacks. Keep `filtered_source`'s current lock-free evaluation path (`:303–415`): `source_raster` recursively composites nested objects, and `TransformOp::apply` itself uses Rayon (`transform/src/op.rs:84–125`). Holding a mutex or waiting for a per-key `OnceLock` from tile workers can deadlock a two-worker pool. Publish only a complete validated result, as today.

**Admission is a prerequisite to calling this a resource fix.** The persistent cache only retains `source + result` when `area * 32 <= budget` (`smart_filters.rs:388–413`). A prewarm call for an oversized result is immediately forgotten; subsequent tile workers recompute it, adding one extra full-image evaluation. The first patch should preflight this size and skip prewarming oversized entries, while routing affected full-level renders through a bounded single-evaluation pass or returning a distinct resource-limit error until a pass-scoped retained result exists. Merely serializing tiles limits simultaneous copies but still repeats the expensive seam transform per tile. The robust follow-on is a pass-scoped `Arc` result/lease, with one admission permit accounting for source, transform planes, mask, intermediate stage, and output, released on success, cancellation, and error. Its lookup must not wait while inside a Rayon tile worker. Preserve the exact cache key (child key/revision, parameter digest, child profile/canvas digest); do not replace it with layer ID alone.

This initial prepass covers `render_level`/`render_level_rgba`, not direct `render_tile`, independent concurrent callers, or resident GPU fallback. It should be described as a bounded mitigation, not closure of the B incident. `crates/tessera-ffi/src/document/filters.rs:578–608` already warms one affected tile before a PSD stack's parallel full-level render. Its comment at `:593–596` says the compositor holds its filter lock during evaluation, but current `smart_filters.rs:313–331` explicitly releases it; update that comment during implementation. The frozen stack proves full-image work occurred, but the audit capture does not count duplicate attempts in that specific incident.

## Why cancellation and memory admission need separate work

`render_level_premultiplied` checks cancellation only before each tile (`render/mod.rs:700–703`). `render_level_rgba` creates an unreachable fresh token (`:726–729`); the PSD rasterization path exposes no caller cancellation (`tessera-ffi/src/document/transform.rs:1088–1123`). Neither `SmartFilterEvaluator::evaluate` nor `evaluate_transform` receives a token (`smart_filters.rs:81–89,197–240,346–350`). Content-aware resize loops over each removed/inserted seam without polling (`transform/src/seam.rs:152–184`); each seam allocates a full energy, cost, and parent field (`:242–307`). A prepass without token plumbing can move the same long uninterruptible work earlier. Add a cancellable transform entry point with checks at least between seams and during energy/cost row loops, propagating a dedicated cancellation result through the compositor. Keep the old public trait/function path compatible or add a default cancellable adapter; a default wrapper alone cannot interrupt a long evaluator.

`Compositor::new` grants the same nominal budget to live, filter, and tile caches separately (`render/mod.rs:115–123`). The filter cache's `area * 32` charge omits transform input/output planes, stage copies, protection masks, seam fields, and concurrent misses (`smart_filters.rs:199–240,332–388`; `seam.rs:14–20,242–266`). The reported 64 MiB PSD compositor (`tessera-ffi/src/document/filters.rs:590`) can cache only roughly 2.1 million pixels by that charge; it is not a 64 MiB process cap. `ResidentRenderer::new` gives each renderer 2 GiB (`resident/mod.rs:528–536`), nested children instantiate their own renderer (`:820–834`; `resident/filters.rs:294–310`), and `ensure` grows beyond budget after eviction (`resident/mod.rs:1015–1051`). GPU accounting is a separate confirmed policy gap, not established as the captured CPU stall's cause. A shared hard permit for active CPU/GPU working memory is needed before claiming an overall bound.

## Small tests and acceptance evidence (on A, at two workers)

1. Tiny multi-tile filtered smart object: use an atomic evaluator attempt counter and peak-active counter, cold `render_level` with a cache large enough for one entry. Assert one actual evaluation, unchanged pixels, no worker wait, and warm reuse. `filter_evaluations()` is unsuitable because it omits discarded duplicates (`smart_filters.rs:280–285,394–400`). Exercise nested smart objects and a filter mask; ensure the deepest-first prepass neither changes blend/mask output nor reuses an incorrect revision/profile key.
2. Below-cache-budget and above-cache-budget cases: verify the first has one attempt; the second is admitted once per render pass under a measured pass lease or fails before allocation with a resource-limit error. Do not count an extra prewarm as success. A deliberately tiny cache should expose the current recomputation cliff without large fixtures.
3. Cancellation: cancel before prepass, during a multi-seam transform, and between stages. Assert prompt `Cancelled`, no published partial cache entry/output, and permit release. Include evaluator error and nested recursion paths. Run the deadlock regression in a bounded subprocess with a two-worker Rayon pool so a hang cannot strand the main test process.
4. Record attempted evaluations, discarded duplicates, simultaneous evaluations, and estimated/observed transient bytes separately from accepted `filter_evaluations`; compare against baseline on the same small fixture. Validate direct `render_tile` separately because full-level prepass does not cover it.

No test result is claimed here; all four are proposed gates for the implementation.
