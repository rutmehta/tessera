# FilterPass proposal review (source only, 2026-09-27)

Scope: `/Users/rutmehta/.codex/worktrees/render-resource-bounds/tessera`, no edits or builds. I reviewed the proposed per-`render_level` CPU filter pass against the current call chain. The tiny RED case has independently shown two cold stack attempts for a 257×1 source whose `Cached` source+result costs 8,224 bytes against an 8,223-byte persistent filter-cache budget; the existing direct-tile nested Rayon deadlock test remains a required control.

## Verdict and required boundaries

The serial, first-touch full-level path is the smallest credible fix for duplicate cold whole-image filter work *within one CPU `render_level` call*. It retains actual-tile reachability: `smart_tile` checks bounds at `render/mod.rs:394-399` before calling `filtered_source` at `:411`, and normal compilation retains layer visibility, masks and clipping. A graph prepass is unnecessary and would risk evaluating hidden/offscreen content. Existing direct `render_tile` stays pass-free; two concurrent `render_level` calls each own a different pass and can duplicate work. This is not a global working-memory, GPU, or cancellation bound.

**Admission must reserve, not merely check.** For a cold exact `CacheKey`, compute a checked source+result charge from `so.state.canvas.area() × 32` and reserve *both* one entry and its retained-byte charge under a short pass mutex **before** `source_raster` (`render/smart_filters.rs:378`). Hold an RAII reservation across source compositing, recursive child filters, transforms, and evaluator calls; commit it to the pass map on complete validated success, release on every error. Outer and nested reservations must coexist. A check that releases the mutex/charge before work is invalid because nested work can consume the same allowance. No pass mutex, persistent cache mutex, or per-key wait may span source/evaluator work: evaluator reentrancy and Rayon work stealing are existing supported patterns (`smart_filters.rs:375-398`). Serial top-level tile iteration prevents same-pass first-touch races, so no in-flight wait mechanism is needed. Use checked arithmetic (`checked_mul`/`try_from`) rather than the current lossy `area() as usize * 32` at `:452`; overflow is `ResourceExhausted`, not wraparound.

The approved **1 GiB / 256-entry default** is sound as an explicit *per-pass retained-result admission policy* if the configured values are independent of `Compositor::new(cache_budget)` (`render/mod.rs:119-130`). The 8,223-byte test cache budget must still permit an 8,224-byte pass entry. A 20 MP entry costs about 640 MB by this accounting; an entry over 1 GiB, the 257th simultaneously retained entry, or recursive outer+inner sum beyond the limit now returns `ResourceExhausted`. Document this behavioral limit and that it excludes transient rasters/planes, tile output, caches, concurrent frames, GPU allocations, and evaluator-private allocations. I see no source-level reason to reject the chosen default, but it is an explicit new API behavior for very large previously accepted frames. Keep the override per-compositor (e.g. a `FilterPassLimits { retained_bytes, entries }` constructor/builder or setter before shared use), not a process environment variable or global mutable test hook; validate/define zero values. Keep persistent-cache budget and eviction semantics unchanged.

**Propagate the context through every ordinary composite path.** `DocRef` is currently only `{ state, key }` (`render/mod.rs:37-41`). The optional pass must flow from an internal `render_tile_premultiplied` helper to `TileJob`, through `smart_tile`'s child `DocRef`s (`render/mod.rs:411-421`), `filtered_source` into `source_raster` (`smart_filters.rs:378-381`; `effects.rs:34-45`), and the synthetic `DocRef` in layer-style rendering (`effects.rs:82-85`). The live-scene branch at `render/mod.rs:592-594` calls `render_live_scene`, which currently creates a fresh pass-free `DocRef` (`text_vector/damage.rs:234-239`). Missing that edge silently bypasses the pass for documents with any text/shape. Prefer passing the same context into `render_live_scene` and preserving its dirty-region/cache behavior. Routing scoped frames through normal `composite_premult` is a bounded alternative, but then compare pixels and cache/damage behavior for text/shape plus smart filters; `has_live` is recursive and can be true even for content not rendered. New `DocRef` sites in `render/exec.rs` and public direct paths should explicitly use `None`.

The pass map must use the existing exact `(so.key, so.state.rev, params digest, native FilterContext digest)` key (`smart_filters.rs:350-369`) and retain `Arc<Cached>` **before mask blending** (`:478+`). A mask-only change should still reuse the unmasked entry and apply the new mask on each use. Preserve persistent cache hits/publication; the pass may retain an existing persistent hit to protect the full-level call from later global eviction, but that hit must be charged consistently and can trigger the documented pass limit. Do not silently exclude warm hits from the allowance while claiming stable per-frame reuse. Avoid holding both pass and persistent locks at once; clone an `Arc`, drop the first lock, then reserve/insert under the second. If a result is already pass-resident, use it before consulting the persistent map or admission counter.

## Focused validation after source freezes

1. Keep the 257×1, 8,223-byte persistent-budget RED fixture; with a pass allowance above 8,224 bytes, a full-level render must succeed with exactly one attempted stack/stage and equal pixels. A second full-level call is a different pass; do not assert a cross-call bound. The existing Barrier(2) nested Rayon direct-`render_tile` test must still pass; do not serially gate those calls.
2. Set a separate per-instance pass cap below 8,224 bytes and assert `ResourceExhausted` before `attempted_stacks`/`attempted_stages` increase for that key. Then test nested outer+inner costs: both fit succeeds; combined cost exceeding the cap errors before the inner attempt, and all reservations are released on errors. Repeat after an evaluator error to catch leaked entry/byte reservations.
3. Exercise a text/shape live scene and a styled smart layer with a cold oversized filter over two tiles; each must use the same pass and evaluate once. Compare pixels against the unchanged tile path. Keep a hidden or offscreen invalid filtered smart layer in a frame with zero/small allowance: it must remain unevaluated and not fail admission. Add a mask-only edit case if the cache path changes.
4. If two full-level calls are made concurrently, verify they do not share a pass or deadlock; their total retained charges may exceed one pass cap. Check cancellation error paths release reservations, but do not claim the pass fixes late cancellation in `source_raster` or transform/seam work.

No result in this review certifies the implementation; it identifies the minimum invariants for the source agent's change and its later gates.
