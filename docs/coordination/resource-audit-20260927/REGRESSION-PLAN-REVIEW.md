# Critical read-only review of resource regression plan

Reviewed `/tmp/tessera-resource-regression-plan.md` against `origin/wp/B5-16` (`131af17d735c648bb5d335e9f79b7b6b2b063c1b`). No test or build was run.

The counters-first patch is a sound bounded start, provided the metrics describe **actual full-image source attempts**, not merely filter stages that reached publication. Increment `stack_attempts` and start its RAII active guard before `source_raster` at `smart_filters.rs:315`: two cold callers can duplicate that full-image composite, then the second cache check at `:319–325` can coalesce before any stage runs. `stage_attempts` begins at `:346` after parameter validation, and `duplicate_publications` at `:397–399`; neither alone measures all wasted work. `active_stacks` must decrement on `?` errors, panic-unwind, and cancellation, with peak updated atomically. `oversize_results` should increment only for a fully computed, validated entry that cannot be retained (`:388–413`). Keep `filter_evaluations` as accepted-stage count so old tests retain their meaning.

The proposed two-tile fixture needs two distinct cases. The current `same_key_cold_race` test (`tests/smart_filter_deadlock.rs:68–113`) uses a two-party barrier inside its evaluator and **two direct `render_tile` calls**; retain it to prove direct-tile cold misses stay nonblocking. A new full-level test for caller-thread pre-evaluation must use a nonblocking counting evaluator. Reusing the barrier would hang precisely when the intended fix allows only one evaluation. The 257×1 nominal cache charge is 8,224 bytes; a budget of 8,192 is a clean oversized case. Current behavior should be characterized separately from the future one-attempt-per-frame assertion. With pass-scoped retention, a second frame may legitimately evaluate once again because the oversized result was released.

A prepass cannot naively use `Layer::visit` or a test of `props.visible` alone. Tile compilation (`render/exec.rs:134–180`) skips a hidden base **and its clipped children**, includes visible clipped children of a visible base, and descends pass-through versus isolated groups differently. It also avoids work for smart objects whose transformed bounds miss the tile (`render/mod.rs:391–395`). `Layer::affected_bounds` deliberately returns `None` for smart objects/styles (`document.rs:550–567`), so it is not a usable exclusion test by itself. The prepass must mirror the reached scene graph for the requested level/region; otherwise hidden/offscreen content may run and even fail before any tile would touch it. Add tests with a hidden invalid smart filter, a visible clipped smart child behind a hidden base, disabled invalid stages, and a smart object outside the canvas. For a visible smart object, an enabled stage with zero opacity still enters `filtered_source` today, validates its opacity, and builds a source; changing that behavior needs a separate semantic decision rather than an incidental prepass shortcut.

Keep the cached **unmasked** stack and the final masked source separate. `smart_filters.rs:417–456` applies the filter mask after lookup, and the cache key at `:297–302` intentionally omits mask identity so mask-only edits reuse the expensive stack. A frame-scoped map keyed only by that cache key may hold `Cached {source,result}`; if it holds final `FilteredSource` (masked raster plus `next_doc_key()`), different masks or mask edits can receive stale pixels. Nested stacks should be prepared deepest-first without a lock, but `source_raster` (`render/effects.rs:34–45`) can itself re-enter the same compositor through child smart objects and styles; an external evaluator can also call `render_level_rgba` recursively (`tests/smart_filter_deadlock.rs:33–58`). Tests need nested child filters, mask-only edit reuse with changed pixels, blend opacity, and evaluator re-entry at one and two Rayon workers.

A thread-local render scope is not sufficient by itself: `render_level_premultiplied` sends tile closures to other Rayon threads (`render/mod.rs:718–721`), and nested calls can originate from a worker. Passing an explicit `Arc<RenderPass>` down the call graph is safest, though invasive. A runtime registry must key by pass identity as well as cache key, retain entries until every tile task has finished, and handle overlapping `render_level` callers independently; cleanup and hard memory permits must be RAII on all exits. A global per-key blocking initializer or a lock around the prepass can deadlock when an evaluator re-enters the compositor. With a shared hard memory budget, use nonblocking admission or schedule before workers; never park a Rayon worker while it holds another frame's reservation. Concurrent callers may each evaluate the same key unless coordinated at a higher level; the first patch should say this explicitly. Test two overlapping full-level calls on the same compositor, including one cancelled/erroring call, for correct pixels, release, and no cross-pass lifetime corruption.

These observations strengthen the plan's stated boundary: counters and tiny tests are useful, but they do not yet eliminate duplicated work, bound transient memory, or close B's hold.
