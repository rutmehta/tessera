# Transform seam cancellation: source-only API plan (2026-09-27)

Scope: `/Users/rutmehta/Developer/tessera` at current source, no edits/builds. This is a follow-on resource/cancellation plan, separate from the FilterPass duplicate-work fix and from B-owned FFI changes.

## Current gap and exact boundary

`engine_api::jobs::CancellationToken::check()` (`crates/engine-api/src/jobs.rs:73-115`) already returns `EngineError::Cancelled`. `Compositor::render_level` checks it only before each tile (`crates/compositor/src/render/mod.rs:690-704`); `render_level_rgba` creates an unobservable fresh token (`:727-729`) and direct `render_tile` has no token. The smart-filter transform branch in `crates/compositor/src/render/smart_filters.rs:199-222,340-348` calls `TransformOp::apply`, then maps *every* transform error to `EngineError::InvalidArgument`. `TransformOp::apply` (`crates/transform/src/op.rs:82-105`) calls `seam::apply`, whose repeated `find_seam`, `remove`, `insert_batch`, `transpose`, and final `resample` have no checks (`crates/transform/src/seam.rs:14-338`). A cancellation request during one content-aware stage therefore waits until the entire tile/full-image stage finishes, and an indiscriminate error conversion would misreport cancellation as invalid transform.

## Backwards-compatible Rust APIs

1. Add `engine-api = { path = "../engine-api" }` to `crates/transform/Cargo.toml` (its dependency direction is acyclic on the inspected manifests), and add `transform::Error::Cancelled` to `crates/transform/src/lib.rs`. Keep `transform::Result<T>` and all existing `Invalid` errors. Convert only `token.check()` failure to `Error::Cancelled`; map this variant to `EngineError::Cancelled` at compositor boundary, while mapping `Invalid` as today. Do not stringify cancellation into an invalid-argument error.
2. Add `TransformOp::apply_with_cancel(&self, input, width, height, level, cancel: &CancellationToken) -> transform::Result<Image>` in `crates/transform/src/op.rs`. Existing `apply(...)` delegates to it using a fresh noncancelled token, preserving source compatibility. Check before validation/preparation and before result publication. For content-aware scaling, forward the *same supplied token* to `seam::apply_with_cancel`; do not make a new token in this path. For the non-seam Rayon mapping, use fallible `try_for_each` over rows and check at least every bounded pixel block (e.g. 1,024) so the new entrypoint is truly cancellable during rendering. `prepare()` remains a separately documented late-cancellation gap until its expensive builders gain checkpoints.
3. Add `seam::apply_with_cancel(input, params, cancel: &CancellationToken) -> transform::Result<Image>` in `crates/transform/src/seam.rs`; keep existing `apply` delegating with a fresh token. Also add `apply_with_skin_protection_and_cancel(..., cancel)` and keep the existing skin-hook API delegating, so hook generation is not an uncancellable bypass. Check at entry, between width/height stages, before/after transpose and final resample, before each seam or insertion batch, and periodically inside the long energy/DP loops of `find_seam` and row-copy loops of `remove`, `insert_batch`, `transpose`, `resample` and the skin hook. A row-only check is insufficient for a very wide image; a fixed 1,024-pixel cadence is a reasonable bounded check interval. Make private helpers fallible where needed (`find_seam` changes from `Vec<usize>` to `Result<Vec<usize>>`), and propagate `?` without changing pixel math or seam tie-breaking. Recheck immediately before returning the completed image so cancellation during the final copy is observed. Local partially built `Image`s are dropped on error; never publish them.
4. Add `SmartFilterEvaluator::evaluate_with_cancel(input, filter, context, cancel)` with a **default** implementation that checks before and after calling the existing required `evaluate`. This preserves third-party implementations and explicitly provides boundary-only cancellation for ones that do not override it. Change compositor stack evaluation to call this method, checking between stages. For full support, `BasicFilters` needs checks in its Gaussian loops; `filters::CompositorFilters` must override and forward cancellation into its own algorithms. Its current `AtomicBool::new(false)` calls (`crates/filters/src/compositor_adapter.rs:34-79`) cannot be treated as token propagation, and copying `token.is_cancelled()` into a fresh `AtomicBool` is only a one-time snapshot. That adapter migration may be staged separately; do not claim mid-algorithm cancellation for it before it is wired.
5. In `crates/compositor/src/render`, carry the caller's token through an internal tile/`DocRef` render context into `source_raster` (`effects.rs:34-45`), nested `smart_tile` children, style-source rendering, and `filtered_source`/`evaluate_transform`. The source agent is adding a FilterPass context now; extend that context rather than introducing thread-local state or changing its lock semantics. Check before each child source tile and before each smart-filter stage, and invoke `op.apply_with_cancel` from `evaluate_transform`. Keep old `render_tile`/`render_tile_premultiplied` API by delegating to a no-cancellation context, and add `render_tile_with_cancel` for callers rendering a viewport tile loop. Add `render_level_rgba_with_cancel` while preserving the existing convenience method. Never use a fresh token *inside* a method that was passed a caller token. An error must leave the unmasked filter cache unpublished for the failed stack; already completed ordinary tile-cache entries may remain and should not be described as transactional rollback.

## Minimal deterministic gates

- In `crates/transform/tests/seam_content.rs`, a tiny pre-cancelled 3×3 shrink and identity operation must return `transform::Error::Cancelled`; existing uncancelled exact-pixel fixtures remain unchanged. Test both `TransformOp::apply_with_cancel` and `seam::apply_with_cancel` so delegation is real.
- In `crates/transform/src/seam.rs` unit tests, use an internal test-only checkpoint observer or a private fallible checkpoint closure shared by production token checks to cancel a real token after the first width seam, then assert height-stage cancellation on a tiny two-axis resize. A second controlled checkpoint in the energy/DP loop should return `Cancelled` before `find_seam` finishes. This avoids sleeps, background-thread timing and huge fixtures. For `apply_with_skin_protection_and_cancel`, cancel the token from its deterministic hook after a known pixel and assert prompt cancellation. Keep observers private; no test hook in serialized recipes/public FFI.
- In `crates/compositor/tests/smart_filters.rs` or `tests/transforms.rs`, render a tiny content-aware smart object through a cancelled `render_level` token. Assert `EngineError::Cancelled`, no accepted filter result/evaluation publication, and successful unchanged-pixel retry with a fresh token. Add a custom evaluator that cancels in one stage to prove the token is checked before the next stage; do not assert that a legacy third-party evaluator aborts mid-call.
- Check non-seam `TransformOp::apply_with_cancel` with a tiny pre-cancelled affine operation. A bounded internal checkpoint test can prove the Rayon row path checks the supplied token. Keep existing transform pixel fixtures and direct nested-Rayon compositor deadlock test as regressions.

## FFI handoff (coordinate with B owner; no B edits here)

A later B-owned change can give `cpu_present` an existing per-render `CancellationToken`, check it before each tile/surface write, and call `render_tile_with_cancel`. Thumbnail paths at `:1163-1168` and other `render_level`/export paths need the *actual request/job token*, not a new token, whenever the host exposes cancellation. `cancel_advanced_transform` (`document/transform.rs:982`) currently cancels an editing session, not necessarily an in-flight seam computation; treat that as a separate semantic boundary. Preserve UniFFI error mapping so `EngineError::Cancelled` reaches the host as cancellation and does not become a generic transform failure.
