# B rasterized PSD copy operation: independent source review

Reviewed exact commit `7240948537458011fa7640104d5001c960bd7961` via `git show` from `/Users/rutmehta/Developer/tessera`, including `tools/orchestrate/wp/B5-16/PSD-COPY-IMPLEMENTATION.md` and design `8363c8ae`. Source-only; no checkout edits, bindings generation, build, test or desktop action.

## Blocking contract finding

**Real precommit errors can be erased by a racing cancellation.** `crates/tessera-ffi/src/document/psd_copy.rs:182-191` takes `result = run_inner(...)`, then tests only `life.cancelled`; if true it returns `Ok(Cancelled)` even when `result` is an evaluator, path, encoder, temp-write or sync failure. For example, the write fails, then the user cancels before `run()` acquires the lifecycle lock: `cancel()` accepts in Running and the actual write failure becomes “cancelled.” This contradicts the accepted contract that real evaluation/IO failures remain errors. Preserve a typed internal cancellation cause and map only that cause to `Cancelled`; keep other `BridgeError`s as errors even if cancellation arrives before publication. Avoid matching a failure string. Add a deterministic barrier test injecting a non-cancellation error and cancelling before result publication, plus a cancellation-error case proving `Cancelled` still works. Persist failures after Committing are already protected because `cancel()` then returns false.

## Lifecycle and destination findings

The per-document weak registry and `holds_admission` (`psd_copy.rs:95-109,76-80`) retain Running cancellation until `Drain` finishes (`:139-146`); a cancelled Prepared handle can be replaced, but its later `run` is permanently pre-cancelled and identity cleanup cannot clear the replacement (`:56-67,131-136`). Registry/phase locking serializes close versus commit admission (`:111-129`). `DocumentSession::shutdown` invokes registry close before state lock (`document.rs:1062-1066`); post-admission close cannot revoke persist and the operation reports the real Saved/error outcome. `write_copy_atomic` (`document/io.rs:391-415`) writes a same-directory temp in checked chunks, syncs, admits commit immediately before persist and performs no post-persist cancellation check. An error or precommit cancel drops the tempfile, preserving an existing destination. No directory fsync/crash-durability or opaque encoder latency guarantee follows.

Swift ownership is tied to the originating `DocumentController`: panel callback rejects a closed origin, operation preparation precedes queue enqueue (`DocumentTransforms.swift:552-575`), `enqueueCopy` retains the slot while cancellation drains, completion checks owner key + UUID + weak origin before reporting (`:577-602`), and `DocumentController.close` cancels/removes host ownership before backend close (`DocumentController.swift:454-462`). Generic enqueue's current-document failure routing is disabled for this path (`DocumentTransforms.swift:115-133,585-595`). Switching tabs does not migrate completion. The menu can cancel only when the origin is current, a discoverability limitation rather than an ownership failure.

## Mandatory A integration and validation limits

The smart-stack path receives the same `RequestCancellation` through `native_stack` and checked raster conversion (`document/filters.rs:655-666`), but `document/io.rs:379` still calls legacy `compositor::psd::to_psd(doc)`, which creates a fresh token. The B implementation document explicitly assigns this to A: use a narrow borrowed native-token accessor and call A's `to_psd_with_cancel(doc, same_native_token)`; do not replace it with a bool snapshot or new token. Until then, merged-composite conversion is boundary-cancellable only. `PsdDocument::write`, metadata clones and some raster copies remain opaque. UniFFI Swift bindings are also ungenerated, so the adapter's Sendable conformance and protocol mocks require A compilation. No end-to-end cancellation, bounded latency, peak-memory cap or passing-test claim is supported yet.

The added Rust tests cover first-layer cancellation, pre-cancel identity/retry, drain admission and close/commit ordering; IO tests cover sentinel/temp cleanup; Swift fake tests cover origin completion and busy balance. They do not cover the error-masking race above, live token through PSD conversion, actual blocked backend-state close cancellation, or a real opaque encoder. The first of these is the source blocker; remaining points are explicit integration/verification gates rather than defects in B's scoped code.
