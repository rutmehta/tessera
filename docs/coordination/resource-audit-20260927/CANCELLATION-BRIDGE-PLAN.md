## Compatibility and narrow bridge

Source search found no external exhaustive `match` over `transform::Error` in `crates`; consumers call `TransformOp::apply` or map errors with `to_string()`. Adding `Error::Cancelled` therefore has no identified source-level exhaustiveness break, but strict cross-crate compilation remains a separate gate. The current compositor transform stage at `crates/compositor/src/render/smart_filters.rs:199-239,565-574` calls old `op.apply` and maps *all* transform errors to `EngineError::InvalidArgument`. It must call `op.apply_with_cancel(..., caller_token)` and map `transform::Error::Cancelled` to `EngineError::Cancelled`, preserving existing invalid mapping for `Error::Invalid`. A caller token must not be replaced by a new token in this path.

The smallest render-context extension is an optional `cancel: Option<&CancellationToken>` alongside the existing `pass` in `DocRef` (`render/mod.rs:48-55`). `render_level_premultiplied` should pass `Some(cancel)` into its internal tile method (currently `:724-755`), and every nested `DocRef` creation must forward that same option: `smart_tile` child refs (`render/mod.rs:433-445`), `filtered_source` to `source_raster` (`smart_filters.rs:538-543`), layer-style synthetic refs (`render/effects.rs:82-86`), and live-scene refs (`text_vector/damage.rs:234-245`). Public direct `render_tile` keeps `None` for source compatibility; a new `render_tile_with_cancel` can expose caller cancellation for viewport tile loops. The resident CPU fallback's direct `filtered_source(so, None)` (`resident/filters.rs:279`) explicitly remains pass-free and token-free until its owner supplies cancellation. Preserve the FilterPass pass mutex/RAII behavior; no token check may hold that mutex or the persistent cache mutex during evaluator work.

In `source_raster` (`render/effects.rs:34-45`), check before each child tile and after the loop; a cancellation between nested children should stop without publishing a finished `Cached`. In `filtered_source`, check before reserving/evaluating, between smart-filter stages, and just before committing a complete result. Cancellation error unwinds `PassReservation` and `ActiveStack`; a partially assembled source/output raster stays local. Already completed ordinary tile-cache entries may remain, so do not claim transactional cache rollback.

For `evaluate_transform`, check the token before converting a straight `Raster` to premultiplied planes, periodically while reading input rows, after constructing `transform::Image`, immediately before and after `op.apply_with_cancel`, and before/after converting the result back to `Raster`. The current `Raster::edit_region` callback cannot return `EngineResult`; one whole-image callback would delay cancellation until it finishes. If prompt output-conversion cancellation is in scope, write bounded tile/strip regions with a check before each region rather than merely setting a flag inside one whole-image callback. Keep the existing clipping/padding at the original child canvas, alpha unpremultiplication, and filter-cache key unchanged.

`SmartFilterEvaluator` is a public extension trait (`smart_filters.rs:81-90`) with many current implementations, including `filters::CompositorFilters` and test evaluators. Add a default `evaluate_with_cancel(input, filter, context, token)` method that checks before/after calling the required old `evaluate`; existing implementers keep compiling. Call it between stack stages. Document that this default only cancels at method boundaries. `BasicFilters` Gaussian needs an override/checkpoints for mid-kernel cancellation. The filters adapter currently passes `AtomicBool::new(false)` to several algorithms (`crates/filters/src/compositor_adapter.rs:34-79`); a one-time copy of `token.is_cancelled()` into an `AtomicBool` is not ongoing cancellation. Adapter internals need an actual shared-token/checker migration before claiming mid-algorithm support. `ResidentFilterEvaluator` extends the trait, so the default method preserves its API; GPU execution remains outside this CPU bridge.

## Caller gaps to keep explicit

`Compositor::render_level_rgba` constructs a fresh token (`render/mod.rs:767-769`). Add `render_level_rgba_with_cancel` and keep the current method as a compatibility wrapper; only the new method provides externally observable cancellation. `crates/tessera-ffi/src/document/filters.rs:588-609` prewarms one direct tile before `render_level_rgba`; that one tile bypasses FilterPass and any new level token, so an oversized stack may still be evaluated once before the scoped frame. Remove/rethink this historical prewarm only with the B owner and its test coverage. `document/render.rs:992-1004` uses direct `render_tile` in `cpu_present`; thumbnail paths at `:1163-1168` pass fresh tokens; `read_level` at `:747-760` calls the convenience `render_level_rgba`. None becomes interruptible merely because transform and compositor accept a token. B-owned host call sites must pass their actual request/job token and map `EngineError::Cancelled` distinctly. No B Document/FFI edit is included in this bridge proposal.

## Small tests and gate

Use a 3×3 or 4×4 content-aware smart filter with a pre-cancelled `render_level` token: expect `EngineError::Cancelled`, zero attempted stages, no completed filter result, and an uncancelled retry with unchanged pixels. Use a two-stage stack/custom evaluator that cancels its supplied token after stage one; assert stage two is not called and `active_stacks` returns to zero. Test nested smart child and style/live paths with the same token, including one `source_raster` child-tile boundary. Preserve the direct-tile Barrier(2) Rayon deadlock control and FilterPass focused tests. For a real in-seam cancellation through the compositor, use a tiny private deterministic checkpoint rather than a sleeping thread or large image. Strict `CARGO_BUILD_JOBS=2 RAYON_NUM_THREADS=2 cargo clippy -p transform --all-targets -- -D warnings` is prepared but has **not** run; run it in a coordinated compiler slot along with the eventual cross-crate bridge gate.
