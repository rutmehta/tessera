## Blocking teardown edge

`DocumentViewportView.controller` is weak (`DocumentViewport.swift:141`). The new `dismantleNSView` calls `detachFromWorkspace()` (`:563-565`), which calls `attach(nil)` (`:233-235`). But `attach` immediately returns when `doc === controller` (`:201-202`). If `DocumentWorkspace.discard` removes/closes the last document and reassigns `current` (`DocumentWorkspace.swift:344-352`) before SwiftUI dismantles the view, the weak `controller` can already be nil. Then `attach(nil)` is a no-op: `ring`, `current` texture, and `lastPushed` are not cleared (`DocumentViewport.swift:213-216`), and the `ants.rect`/tool-overlay reset at `:217` is skipped. `detachFromWorkspace` still nils `workspace`, but the explicit local resource release it promises does not occur. The retained IOSurface/texture lifetime is then tied to when SwiftUI finally deallocates the NSView, not to dismantle. The new tests retain `doc` through detach and do not exercise this order (`DocumentViewportOwnershipTests.swift:10-27`).

Minimal fix: make `attach(nil)` perform local teardown even when the weak controller is already nil (e.g. return early only for the same **non-nil** document), while keeping `old.viewport === self` as the guard on callback/surface detach. Repeated nil teardown remains idempotent. Add a regression that closes/releases the last `DocumentController` before dismantle, confirms the weak controller is nil, and observes local retained-resource count/reset through a narrow test accessor or injected tiny surface; verify no old callback or timer eligibility remains. Avoid a large canvas or GPU stress case.

## Outline publication and missing integrated coverage

`LatestRequestBuffer` correctly holds one running generation and one replaceable pending value. `invalidate()` rejects the old generation and drops pending; `finish()` starts only the newest pending request (`LatestRequestBuffer.swift:19-39`). `DocumentWorkspace.current.didSet` invalidates on switch, `documentClosing` invalidates before `doc.close`, and `refreshOutline` rejects inactive documents (`DocumentWorkspace.swift:65-68,344-352`; `DocumentTools.swift:162-176,706-734`). I found no source path where an old outline completion is published after a switch/close **provided those callbacks occur**. The four new buffer tests cover scheduling in isolation, but none drives `DocumentTools` against a blocked backend; the viewport tests cover owner pointers/callbacks without surface lifetime or a real SwiftUI dismantle.

Minimum integrated regression before merging: use a tiny stub document and a test-only injectable outline-fetch closure with a gate. Start A's outline fetch, submit a newer A selection, switch to B or close A while the first fetch is held, then release it. Assert the obsolete result never populates `DocumentTools.outline`, at most the newest still-active request starts, and a closed document starts no pending request. Separately exercise replacement viewport attach before old dismantle and the weak-controller-nil teardown above. Avoid sleeps/large masks; use deterministic gates and tiny dimensions. An already-running synchronous engine contour trace is not cancelled by this change, as the B source notes.

Adjacent pre-existing gap, not introduced by these commits: `selectAsync` completion still reloads its captured document and reports through the current `DocumentTools.document` after a switch (`DocumentTools.swift:612-624`); the new buffer applies only to outline fetches. Do not describe these commits as cancelling all document tool work.
