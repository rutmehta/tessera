## Proposed first boundary

Use an explicit profile ID such as `native2-cfa-cpu-u16-v1`: exact schema3 Raw/Native2 recipe, a captured Bayer CFA RAW with metadata orientation=1 and explicit Bilinear demosaic, decoded through the stored `libraw-cfa-v1` route, scalar image-core CPU operators at level zero, no external inference/profile injection, and display-referred opaque RGBA U16 sRGB output. This is a restricted new resolver, not a claim that all current RAW recipes are admitted. Unsupported settings, route, environment, source layout or dependency requirements fail without publishing pixels or changing the pinned descriptor. Preserve recipe settings exactly within the admitted subset; never turn off unsupported settings to force admission.

## Concrete CPU/output route

[Renderer::new](/Users/rutmehta/Developer/tessera/crates/image-core/src/render.rs:309) installs CpuStageOp. Construct a fresh renderer per resolution, with explicit Native2, `PipelineGraph::m2()`, threads=1, preview_approximations=false, cache_budget_bytes=0, and every StageId cacheable flag disabled through [with_cacheable](/Users/rutmehta/Developer/tessera/crates/image-core/src/graph.rs:112). Do not obtain the renderer from a Develop session or attach denoiser/depth/DCP hooks. Do not share this instance or its lens/mask caches across descriptors. This removes dependence on prior ImageId-keyed entries and f16 memo history, without pretending cache budget is an overall decode/render memory limit. A separate finite decoded extent/working-memory admission limit is still necessary.

Pass the parsed pinned recipe through [for_recipe](/Users/rutmehta/Developer/tessera/crates/image-core/src/render.rs:345), after explicitly rejecting every process except Native2: that method selects a family/backend; it does not independently reject every unsupported native revision. The existing image-core code retains admitted detail/tone/color/effect stages; do not use the export CPU fallback as process-version admission proof.

**Do not use RenderOutput::Display as a U16 intermediate.** It delivers [U8 tiles](/Users/rutmehta/Developer/tessera/crates/image-core/src/render.rs:150), and [pipeline_cpu::display](/Users/rutmehta/Developer/tessera/crates/pipeline-cpu/src/display.rs:230) adds ordered 8-bit dither. No additional output sharpening or resizing. This proposed composition still requires the gates below; it has not been executed here.

Image-core RAW input itself does not rotate its CFA; do not claim oriented dimensions merely from output_extent. The output profile must be fixed, reviewed **packaged sRGB ICC bytes** with a pinned content digest. ## Minimal fingerprint and invalidation

Define `RenderEnvironmentId = Digest::derive(fixed versioned domain, canonical manifest bytes)`. The manifest contains: profile/decoder-route/output-contract versions; verified native render+decode artifact content digest (covering linked Rust, vendor decoder and static dependency code); target triple/CPU baseline and feature selection; exact OS runtime build for the system zlib/libm boundary; CPU configuration above; and fixed packaged ICC content digest. Obtain artifact identity from the trusted packaging/build manifest and verify it at engine bootstrap; do not implement self-embedded self-hashing or let arbitrary descriptor strings authorize an environment. Record build/toolchain/source provenance alongside it for audit, without confusing source version names with the exact artifact identity. This is a proposed small packaging/engine identity addition, not an existing API.

Store the admitted environment identity when pinning and require exact equality before resolve/decode. Missing identity or mismatch returns an explicit unsupported-environment/revision result, preserves the descriptor, and does not fall back to current operators. No persistent rendered-pixel cache in the first slice. A later cache must key asset digest+length, canonical render-state digest, route, output contract and RenderEnvironmentId, with mismatches invalidating lookup. An ordinary app or OS update may refuse reopen-render; preserving graph/descriptor permits a future explicit rebase, but this first profile performs no automatic upgrade. Matching fingerprints bind execution provenance and cache eligibility; they are not a theorem of bit-identical floating-point output across arbitrary machines.

External dependencies are refused by the companion admission predicate, not merely tested for presence. In particular no ModelRef-based inference, depth effects, external camera/lens profile or LUT lookup is admitted. The CPU route's [lens resolver](/Users/rutmehta/Developer/tessera/crates/image-core/src/resident_render.rs:522) receives a default empty LensContext; default LensSettings is Auto and may apply embedded or image-derived corrections. Do not equate default optics with neutral optics or silently drop them; the first settings profile chooses and tests explicit neutral optics, refusing Auto rather than rewriting it. A dependency-requiring recipe is unsupported even if a suitable file happens to be installed.

### Aligned first settings predicate

Source-reviewed the writer’s narrow predicate: additionally require Bilinear with no demosaic ModelRef, Denoise Off, default CameraProfileSettings, no local adjustments/retouch, no lens blur/depth, and no LUT/point-color/proof/HDR overrides. Enforce neutral lens by equality to one explicit template: LensSettings::default() modified only to profile=None and remove_chromatic_aberration=false; all other fields must equal the template. This retains harmless inactive defaults while forbidding manual distortion/vignetting/defringe/softness changes. Pass the entire unchanged settings through [pipeline_cpu::validate_settings](/Users/rutmehta/Developer/tessera/crates/pipeline-cpu/src/render.rs:494) too. It copies supported tone and detail in full, and rejects other changed unsupported fields, rather than sanitizing them.

With None and CA false, [lens resolve](/Users/rutmehta/Developer/tessera/crates/pipeline-cpu/src/lens_resolve.rs:470) selects neither automatic image calibration nor automatic CA estimation. Empty LensContext contains no supplied profile/database. Embedded metadata parsing may still reject malformed data; that is a typed decode/render failure, not license to ignore it. No DCP, depth or ML hooks are constructed. The admitted tone/detail execute in [develop_before_geometry](/Users/rutmehta/Developer/tessera/crates/image-core/src/render.rs:735). This predicate intentionally rejects common default Auto demosaic/optics recipes; it is a small first profile, not a claim of current-default recipe coverage. Reject before render instead of changing them to Bilinear/None.

## Required gates, all UNRUN

- Admission table tests: supported positive recipe plus each external/dependency/geometry/process/route refusal before decode; unchanged descriptor and no session/writer construction.
- Decode identity: sealed-stage-only reads and replacement-original control; wrong expected bytes/environment rejected before decode; capture ownership released only after owned decoded data exists.
- CPU isolation: injected GPU/inference/registry factories are never invoked; repeated fresh renders and different unrelated ImageIds produce the same fixture result; all graph memo flags disabled, no shared cache reads. Include a multi-tile fixture so halo/assembly behavior is exercised.
- Output: compare SceneLinear→display_float assembly to an independent float native-display reference at the declared tolerance before U16; verify finite samples, single quantization, opaque alpha, fixed ICC bytes, and no 8-bit plateau/dither expansion. Do not assert exact equality against dithered Display output.
- Extent/orientation: Bayer fixture with active crop differing from sensor and orientation1; orientations2–8 each refuse before render. Preserve admitted recipe detail (including default sharpening). No resize, orientation stripping or hidden settings sanitization. Orientation support is a later profile extension.
- Fingerprint: each manifest component change refuses old descriptor resolution; locator-only relocation with identical captured bytes retains eligibility; app/OS update mismatch does not mutate/rebase the descriptor.

Decision: this is a bounded implementable CPU-only profile with conservative portability. Implementation remains unaccepted until the settings predicate and these targeted tests establish the proposed path; no graph/B-owned adapter or general RAW recipe support follows from it.
