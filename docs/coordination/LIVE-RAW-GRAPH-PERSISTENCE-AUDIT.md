## Established source facts

- **Two graphs, no RAW bridge.** [LayerKind](/Users/rutmehta/Developer/tessera/crates/compositor/src/document.rs:397) contains Pixel, Adjustment, Fill, Group, SmartObject, Text and Shape. [SmartObject](/Users/rutmehta/Developer/tessera/crates/compositor/src/document.rs:359) embeds another DocState; it is not a source-file/recipe reference. The persisted [MKind](/Users/rutmehta/Developer/tessera/crates/compositor/src/format.rs:114) mirrors those variants. `image-core::PipelineGraph` is a separate fixed processing-stage/cache graph ([graph.rs](/Users/rutmehta/Developer/tessera/crates/image-core/src/graph.rs:1)); its existence does not provide a compositor RAW node. `render/live.rs` handles text/vector geometry, not live RAW.
- **Snapshot behavior is concrete.** [open_image](/Users/rutmehta/Developer/tessera/crates/tessera-ffi/src/document/io.rs:244) reads a recipe and renders full-resolution oriented encoded sRGB floats into one U16 Pixel layer. `source_image_id` exists only on the active Opened session; [open_path](/Users/rutmehta/Developer/tessera/crates/tessera-ffi/src/document/io.rs:105) sets it to None when reopening. The graph cannot recover RAW or prior recipe settings from those pixels.
- **Version preflight is already complete.** Current integrated preflight (main372dbbcc, validated final26845eed; earlier source history fb81f279) uses [ManifestHeader preflight](/Users/rutmehta/Developer/tessera/crates/compositor/src/format.rs:687). A future version is rejected before typed MKind decoding. [Roundtrip tests](/Users/rutmehta/Developer/tessera/crates/compositor/tests/roundtrip.rs:234) distinguish future unknown kind→SchemaVersion from current unknown kind→Decode. Do not repeat this prerequisite. FORMAT_VERSION remains1. New RAW variants need an explicit version/reader policy; current MKind has no unknown-variant preservation. This change cannot retrofit clean unsupported-version errors into older deployed readers. [load/save](/Users/rutmehta/Developer/tessera/crates/compositor/src/format.rs:422) preserves graph state/revisions and starts fresh history, not durable document undo. No general migration guarantee follows from accepting versions <=1.
- **Identity and recipe payload are distinct.** [ImageId](/Users/rutmehta/Developer/tessera/crates/engine-api/src/id.rs:91) explicitly covers master files OR virtual copies. [RecipeHash](/Users/rutmehta/Developer/tessera/crates/engine-api/src/recipe/mod.rs:271) hashes source kind/process/settings, excludes image_id/schema/history/unknown fields, and cannot recover a previous recipe. The [index file record/scan](/Users/rutmehta/Developer/tessera/crates/index/src/lib.rs:218) uses size/mtime plus a sidecar stamp; that is not a full asset content digest. [catalog::document](/Users/rutmehta/Developer/tessera/crates/tessera-ffi/src/catalog.rs:16) validates a loaded sidecar's image_id, but alone does not resolve a relocated physical asset or attest unchanged RAW bytes.
- **Future recipe read is not fail-closed.** [Recipe::from_json/to_json](/Users/rutmehta/Developer/tessera/crates/engine-api/src/recipe/mod.rs:420) best-effort reads newer schemas and refuses writing them. A source-layer resolver must explicitly reject unsupported recipe/process semantics before rendering; relying on parse success is insufficient. The native process is2; model representation of Adobe1–6 does not mean all render paths support them. [image-core validation](/Users/rutmehta/Developer/tessera/crates/image-core/src/render.rs:413) validates Adobe3–6; native revision admission needs an explicit contract as well.
- **Do not assume the flattened export path preserves a pinned process.** [render_pixels](/Users/rutmehta/Developer/tessera/crates/export/src/lib.rs:303) validates the recipe but its [CPU fallback](/Users/rutmehta/Developer/tessera/crates/export/src/lib.rs:207) forwards settings to pipeline_cpu without process_version. The [GPU path](/Users/rutmehta/Developer/tessera/crates/export/src/gpu.rs:232) declines non-current-native recipes, so it does not supply version fidelity for that fallback. This is a source-level constraint, not a new runtime bug claim. A pinned node needs a version-aware render boundary such as the explicit [Renderer::for_recipe/for_process_version](/Users/rutmehta/Developer/tessera/crates/image-core/src/render.rs:344), with the necessary denoiser/mask/depth/profile hooks and supported-version checks.
- **Cache identity must change with source.** Compositor [NodeKey](/Users/rutmehta/Developer/tessera/crates/compositor/src/render/cache.rs:20) uses runtime document key, layer, part, revision and tile; [Layer::stamp](/Users/rutmehta/Developer/tessera/crates/compositor/src/document.rs:534) has no external recipe/content revision. image-core [memo_key](/Users/rutmehta/Developer/tessera/crates/image-core/src/graph.rs:206) keys ImageId and stage hashes. A new source snapshot must bind asset digest + recipe render identity + output contract, with stale-result rejection and document content revision invalidation. Keeping the old ImageId/unchanged content_rev while replacing external bytes cannot establish cache correctness.

## Smallest engine-only contract to decide and test

Proposed, not implemented: a `PinnedRawSource` value in an engine-owned contract module contains a schema/versioned descriptor, physical source locator hint and full content digest (separate from recipe ImageId), the immutable recipe payload needed to reproduce settings, recorded recipe schema/source kind/process version and render hash, and explicit output extent/orientation/color/profile/sample semantics. For a first bounded contract, allow only explicitly supported native-process2 RAW inputs; fail closed for unsupported process/schema or unavailable dependencies. Expanding Adobe/HDR/AI-mask support requires its own semantic tests, not silent fallback. This restriction is a proposed scope decision, not a claim about existing product capability.

Resolution consumes the pinned recipe, not whatever current sidecar later contains. Missing source or different bytes at the same path is an unavailable/mismatch result; no unlabelled stale pixel substitution. Locator changes may be accepted only after content identity verification. Read-only recipe snapshot capture can reuse the established [gate→catalog/path revalidation](/Users/rutmehta/Developer/tessera/crates/tessera-ffi/src/develop.rs:1104) pattern without reserving an editor or constructing a writer. It must not invoke open_develop_session for convenience. The physical RAW read and digest need a defined coherent-read policy; the recipe gate alone does not freeze external RAW bytes.

Small deterministic contract tests can precede any B adapter/node work: serialize/reopen the descriptor with exact source+recipe semantics; same file with two recipe ImageIds remains one physical asset with two distinct pinned recipes; change current sidecar after pinning and prove pinned identity/settings unchanged; replace file bytes at the same path and fail digest verification; unsupported recipe/process rejects before render; resolving/rendering does not construct a writer or alter sidecar bytes; source/recipe/output-contract changes cannot share a render identity. These require a new contract implementation only after approval. Existing format v1 tests remain the copy-path control.

This is the minimal contract decision, not authorization for a compositor variant or B Document/FFI/UI change. Fix color/extent semantics before any node implementation: existing U16/sRGB copy output is not a declared scene-linear/HDR boundary. A pinned source descriptor alone does not satisfy UX-05 true live editing or shared undo.
