# Save As destination race — bounded source plan (2026-09-28)

Source-only audit. Repository `/Users/rutmehta/Developer/tessera`, current main read at `1b65c6a6`; B-owned UI read at `93244f8f` (baseline `010617b8`). No product edits, build, or GUI gate were run.

## Actual write path and failure mode

`DocumentWorkspace.finishSaveAs` decides `needsReplacement` using a path existence check at `93244f8f:apps/mac/Sources/Tessera/Document/DocumentWorkspace.swift:487-496`. The owned presenter waits for form/Replace native drain, then calls `admitDocumentWrite` at `:455-477,499-529`. `DocumentBackend.saveAs(path:)` carries **only a path** (`apps/mac/Sources/TesseraCore/Document/DocumentBackend.swift:421-424`; `EngineDocumentBackend.swift:581-582`), so the native writer cannot distinguish “the path was absent when Save was chosen” from “Replace was explicitly confirmed.”

Native `DocumentSession::save_as` holds the session's `saving` lock and calls `save_snapshot` before updating title/path (`crates/tessera-ffi/src/document.rs:2112-2136,2174-2188`). `io::save` dispatches `.tessera-doc` to `compositor::format::save` and PSD/PSB to `write_atomic` (`crates/tessera-ffi/src/document/io.rs:351-366`). The native format writes a deterministic sibling `*.tessera-doc.tmp` then `rename`s over the destination (`crates/compositor/src/format.rs:420-426`); PSD/PSB encode fully, then `NamedTempFile::persist(path)` replaces it (`document/io.rs:338-348`). If the path was absent when Save was chosen but appears during sheet dismissal/encoding, either commit can overwrite it without a Replace confirmation. A second `fileExists` immediately before writing only shrinks, and does not close, that race. When Replace **was** explicitly confirmed, the existing product convention authorizes overwriting that destination path; this bounded fix does not redefine that convention as a version-specific compare-and-swap.

The existing session lock serializes one `DocumentSession`, not two sessions or another process targeting the same path. The fixed native temporary name also collides for same-path concurrent `.tessera-doc` saves. `save_snapshot` changes `saved_node` only after `io::save` succeeds and `save_as` changes title/path only afterward, so a typed commit conflict can preserve those post-save markers.

## Minimal contract and implementation order

1. Add an **opt-in checked Save As** backend/FFI call carrying a two-case destination intent, while retaining legacy `saveAs(path:)` for existing non-UI callers until migrated. The UI-owned B adapter supplies `CreateIfAbsent` when no target existed and `ReplaceConfirmed` only after the actual Replace action. `ReplaceConfirmed` preserves the current destination-path overwrite convention; it does not require an identity token. Never infer intent again from the path inside the backend. An absent-path conflict returns a typed “destination appeared; choose again” result; it leaves destination bytes, document path/title, and saved marker unchanged. The UI must not report Saved or silently choose another path on that result. This is a B interface dependency, not an A patch to `DocumentWorkspace`.
2. Implement `CreateIfAbsent` first for **both** `.tessera-doc` and PSD/PSB via a same-directory unique staged file, full write/sync, then an atomic no-clobber commit. `NamedTempFile::persist_noclobber` is available in the pinned `tempfile` source: on macOS it first tries no-replace rename and falls back to atomic hard-link creation plus temp unlink when the rename form is unsupported. Both branches must fail if the destination already exists; never fall back to replacing `persist`/`rename`. Verify temp cleanup, including the hard-link fallback. For `.tessera-doc`, move away from the deterministic `with_extension("tessera-doc.tmp")` name to unique staging. Clean the temp on conflict and commit failure; retain prior destination bytes. Scope the no-clobber behavior to checked Save As, not ordinary `save()` to an already-owned path.
3. Keep `ReplaceConfirmed` on the existing replacing commit path, using unique staging for `.tessera-doc` so concurrent same-path saves cannot share a temporary filename. This path-overwrite mode is authorized by the user's Replace action, even if an external process changes the destination afterward. Do not claim it protects newer external edits. A future **optional** identity-sensitive Replace policy could carry a captured file identity/revision and use cooperating-writer serialization, but a last-moment `lstat` is not an atomic identity compare-and-replace against arbitrary external writers; installed macOS `RENAME_EXCL` is only no-replace. That stronger policy is not required for this slice and must not disable the ordinary confirmed Replace flow by default.
4. Keep the boundary narrow: `save()` on the document's established path and `save_psd_copy_checked`/`write_copy_atomic` (`document/io.rs:369-419`) also replace paths, but are distinct operations with their own user intent/cancellation contracts. Reuse the safe commit helper later without silently changing copy semantics in this Save As slice. The direct `DocumentWorkspace.write` helper and self-tests continue to use legacy API until their callers declare intent.

## Tiny acceptance tests

* **Race at commit, native and PSD:** hold just before commit after encoding; create `sentinel` at the initially absent destination; resume. Checked `CreateIfAbsent` returns typed conflict, sentinel bytes/identity remain, temp is removed, and session path/title/saved marker do not advance. A retry to another absent path succeeds and reopens correctly. No large image needed.
* **Concurrent same name:** two independent sessions/operations target the same absent `.tessera-doc` and PSD path. Exactly one no-clobber commit succeeds, the other conflicts; output is parseable and neither writer shares a staging filename. Do not infer this from a pre-write `exists` check.
* **Existing/unsafe target controls:** checked `CreateIfAbsent` conflicts on an existing regular file, symlink, and directory without following/mutating them. A `ReplaceConfirmed` control still overwrites the explicitly chosen path and reports success through the existing save flow; no identity-CAS assertion is made.
* **UI boundary once B adds the adapter:** after Save click and native form drain, inject a newly created destination and verify a visible conflict with no Saved status. An actual Replace click chooses `ReplaceConfirmed`, while merely observing an existing file or a stale sheet callback cannot. Preserve presenter completion/membership and writer-drain tests separately.

## Limits

No filesystem-wide conditional identity replacement capability was established by this source audit. The bounded slice gives a strong atomic **create-if-absent** guarantee and preserves existing explicitly confirmed path replacement. Replacement does not protect against a later external edit to the same path; an identity-sensitive mode would be a separate product contract. File durability after power loss (directory fsync) is a separate issue from overwrite admission and is not claimed here.
