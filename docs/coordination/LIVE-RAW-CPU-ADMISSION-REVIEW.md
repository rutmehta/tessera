# Restricted CPU RAW admission draft — source review

Verdict: approved for updating the existing proposal and preparing only the stated pure admission tests/Unsupported scaffold, with two wording/precision corrections below. No renderer implementation, public resolver, numerical memory caps, ICC selection or environment-authority implementation is approved. Read-only inspection; no runtime or source changes.

1. Replace “existing display-referred RAW semantics” in the normalization paragraph with “existing clamped camera-linear sensor normalization, followed by the proposed display-referred output contract.” `raw-decode/src/lib.rs:236–260` black/white normalization produces sensor-linear CFA; display rendering occurs much later. The draft's actual ordering is correct, but that label blurs the boundary the plan is meant to protect.
2. State that descriptor admission already checks recursive unknown current-settings fields through `PinnedRawDescriptor::new`/`check_shape` (`engine-api/src/pinned_raw.rs:118–121,218 onward`) and preserves exact recipe bytes. The new profile should reuse this authority, then apply its narrower predicate. Do not require byte-equivalence to a full serde projection: existing admission intentionally permits omitted default fields and legacy profile-reference representations. A new raw-vs-typed equality rule would unnecessarily redefine descriptorv1 compatibility. If the draft means only semantic coverage/unknown-field refusal, say that explicitly.

Ownership/provenance is otherwise accurate. `capture/decode.rs` consumes CapturedRaw, classifies/opens/unpacks/reads metadata within retained staging ownership, drops RawSource before cleanup, and returns ownedCfaU16/RawMetadata only after cleanup succeeds. Completed phase error precedence and inter-phase cancellation remain intact. Public DecodedCapturedCfa fields do not authenticate arbitrary caller-supplied values; keeping an internal continuation from trusted expected capture through closed decode is necessary. Captured identity/route can be checked before decode through existing accessors, whereas descriptor currently exposes only recipe_json/input_identity/to_json. Minimal typed descriptor accessors need a separate reviewed source change; no untyped serialization roundtrip should become resolver authority.

The conversion gap is real: RawImage::new takes Arc<CfaImage>, while CfaU16 is packedu16 plus layout. Existing private linearize consumes libraw_ffi::CfaImage and uses fullsensor channel_at coordinates, metadata channel black/white and clamp0..1.2. Refactor/share its arithmetic without another native open/unpack/cfa_data read. CfaImage::from_linear explicitly assumes already normalized finite data; passing integers there or relinearizing afterconversion would be wrong. Preserve metadata acquired after unpack. Existing normalization count validation uses usize product; the proposed new checked arithmetic/fallible allocation admission is a legitimate strengthening, not already established by existing code.

Memory limitations are honestly scoped. Neither capture byte quota nor postdecode sensor cap bounds LibRaw native allocations or ownedinteger extraction already performed. RawSource.metadata itself currently obtains cfa_data while building metadata (`raw-decode/src/lib.rs:195 onward`), so any future whole-decode bound must inventory that temporary as well. The proposed2*S retainedinteger +4*S normalized plane and8*A output is only a starting live-buffer inventory. Rendererbatch/halo/output intermediates still require exact analysis; budget0 andthreads1 do not provebounded workingmemory. Keep admission reservation through workerdrain/outputownership and never equate observercancel with completed synchronouswork.

Metadata refusal should concretely inspect gain-map/opcode flags AND retained opcode payloads, checkeddefaultcrop/layout/dimensions/calibration, and orientation1. Those are real fields (`RawMetadata` lib.rs:28–51). Do not promise that their absence establishes camera fidelity. Bayer-only/orientation1 means the five accepted decoder fixturefamilies are not automatically eligible. No privatefixture bytes are needed for the pure nextslice.

ICC prerequisite is grounded: `color-mgmt/src/lib.rs:40–46` generates Builtin::Srgb viaLCMS; it is not pinnedartifact bytes. The fixed reviewed/licensed profile and verified encoding contract remain unresolved. Environment identity is likewise a proposal: existing descriptorv1 has no environment/profilepairing. Preserve a separatelyversioned envelope and externallyverified packaging authority; no callerstring, crateversion or selfembeddedhash substitutes for verification.

Smallest next source slice: private image-core admission value/error types, synthetic recipe/metadata/budget decision contracts and Unsupported orchestration scaffold; engine-api stays dependency-pure. Explicitly distinguish synthetic claimedidentity comparisons from authenticatedcapture provenance. Reuse descriptorvalidation and existing capture/decodercoverage, then stop before normalization-sharing implementation, renderbuffers, actualICCbytes or bootstrapauthority decisions. The current synthetic c334 CPU/output test stays an existingcontrol, not realRAWqualification or authorization to wire pixels.

No additional scope into FFI, catalog, graph/Document UI, automaticrecipefollow, broaddecoderfallback or performance claims is justified by this draft. With the two precision edits it is a sound conservative update to LIVE-RAW-CPU-PROFILE-PROPOSAL.md.

## Route precision addendum

`CapturedRaw::route()` exists before decode (`capture.rs:503`), but returns the declared enum supplied to `capture` at240; it is not a preclassified content result. Compare captured digest/length and declared route with the descriptor/closed-CFA policy before decode. Actual LinearRaw classification/refusal happens inside `decode_cfa` (`capture/decode.rs:49–62`), followed by closed LibRaw CFA decoding. Verify returned route and metadata before normalization. The draft may retain a pre-decode route equality check, but must not call that equality proof that source content has already been classified.

## Publication clarification

The published plan includes both precision corrections and distinguishes CapturedRaw.route() as a caller-supplied declaration from content classification performed inside decode_cfa. Existing decoder return metadata/route still requires admission before normalization.
