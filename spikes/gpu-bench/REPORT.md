# M0-07 GPU spike: wgpu 30 vs native Metal

Generated by `cargo run --release` in `spikes/gpu-bench`. Image 4096x4096 RGBA f32 (demosaic input u16 RGGB); 20 timed runs after 3 warmups, medians reported. wgpu adapter: Apple M4 (Metal, IntegratedGpu). Metal device: Apple M4.

## Method

- **Kernels** (identical math and summation order in WGSL, MSL and the CPU reference):
  1. `demosaic_bilinear_rggb`: u16 RGGB CFA (quantised from a known synthetic linear RGB image) to RGBA f32, bilinear, reflect-101 borders. WGSL reads the u16 data packed two-per-u32; MSL reads `ushort` directly.
  2. `guided_filter_r8`: self-guided filter per channel, r = 8, eps = 1e-3, on a noisy RGBA f32 image; four dispatches (horizontal box of I and I², vertical box + a/b coefficients, horizontal box of a/b, vertical box + output), clipped-window means.
  3. `lut3d_oklab_33`: linear sRGB to Oklab, 33³ trilinear LUT (L^0.9, 10° hue rotation, 1.15x chroma) indexed by (L, a+0.5, b+0.5), back to linear sRGB.
- **GPU time**: wgpu uses `Features::TIMESTAMP_QUERY` with `ComputePassTimestampWrites` at the beginning and end of the single compute pass holding all dispatches, `resolve_query_set`, scaled by `Queue::get_timestamp_period`. Metal uses `MTLCommandBuffer.GPUEndTime - GPUStartTime` of the single command buffer / serial compute encoder holding the same dispatches. Both use 16x16 workgroups over the full image and storage buffers.
- **Wall time** (context only): encode, submit, wait, and copy the full 256 MiB output into a host `Vec<f32>` (wgpu: copy to a MAP_READ staging buffer + map; Metal: `StorageModeShared` buffer, memcpy from `contents()`).
- **Accuracy**: scalar f32 CPU reference (same formulas; `f32::cbrt` where the GPU uses `sign(x)*pow(|x|,1/3)`), max and mean absolute error over RGBA in linear units. MSL is compiled at runtime with default `MTLCompileOptions` (Metal's default fast-math); wgpu/naga generates its own MSL.
- Sanity: CPU demosaic vs the synthetic ground truth: max 3.913e-2, mean 2.355e-3 (bilinear interpolation error, not backend error).

## Recommendation: `go`

Against the rule of thumb (wgpu within 1.5x of native MSL GPU time on all three kernels, max abs error <= 1e-4), wgpu measured demosaic_bilinear_rggb 1.16x, guided_filter_r8 0.99x, lut3d_oklab_33 1.01x of native time, with a worst-case wgpu error of 4.47e-6. wgpu is acceptable for pipeline compute on Apple silicon: keep WGSL as the single kernel source, keep the per-backend tolerance gate (<= 1e-4 vs the CPU reference) in CI, and re-run this spike when kernels change materially or wgpu is upgraded. Presentation stays in Swift/AppKit as planned; MSL passthrough remains the documented fallback if a future kernel misses the bar.
