# WP M3-12 — Tethered capture and live ingest (`tether`)

Read docs/01 §2.21 (tethering), docs/06 §3 ("tethered/ingest culling: scores computed as frames arrive"), crates/index (scanner, incremental), crates/cull (scorers, groups), crates/ml-quality/ml-faces (scores), crates/jobs, crates/tessera-ffi (job/progress/callback patterns).
Implement `crates/tether` (new workspace member), macOS-native first: use **ImageCaptureCore** (ICDeviceBrowser / ICCameraDevice, via objc2 + objc2-image-capture-core if available, else a small Objective-C shim compiled with `cc`) to discover PTP cameras, receive new captures (download to a configured session folder with a naming template), and trigger capture where the camera allows (`requestTakePicture`). Keep the API backend-agnostic (`TetherBackend` trait) so a libgphoto2 (LGPL, dynamic link) backend can follow on Linux/Windows. Live ingest: each arriving file is indexed, embedded-preview extracted, quality/face scores computed as a `Priority::Score` job, and pushed to a live queue the culling UI can subscribe to; a "live view" placeholder returns Unsupported. FFI: `tether_devices()`, `tether_start(session_folder, naming)`, `tether_capture()`, event callback for new frames; `tessera tether list|start|capture` in the CLI.
Tests: a fake backend that emits files into the session folder proves ingest → index → scores → queue ordering and naming; device discovery on this Mac returns an empty list without error (no camera attached); Objective-C bridge compiles and links in CI (macOS runner).
`cargo test -p tether -p tessera-ffi -p tessera-cli --release`, clippy -D warnings, fmt. engine-api unchanged. Allowed: Cargo.lock, Cargo.toml, crates/tether/**, crates/tessera-ffi/src/tether.rs, crates/tessera-ffi/src/lib.rs (register the module only), apps/tessera-cli/**, tools/orchestrate/wp/M3-12/**.
