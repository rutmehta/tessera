# WP M2-28 — Incremental library updates (no full reload on new frames)

M3-12b found that every tethered frame reloads the whole library in the app (coalesced), which resets the undo history and the filter bar; the same happens after imports and index rescans. Read crates/index (scanner, events), crates/tessera-ffi (Engine events, EngineLibrary listing, session.rs cull queue, tether.rs frames), apps/mac EngineLibrary/CullController (how the grid model is rebuilt).
Do: an engine-side change feed (`ImageChange::{Added, Removed, Updated(fields)}` with a monotonically increasing sequence) emitted by the index on scan/insert/update, exposed over FFI as a callback and a `changes_since(seq)` pull; the Swift library model applies changes in place (insert cells at the right sorted/group position, update badges, remove) without rebuilding, preserving selection, undo stack and active filters; groups are recomputed incrementally for the affected burst only; the cull session's queue is updated in place. Tether, import, and background scan all use it. Tests: Rust for the feed ordering and coalescing; Swift for in-place insert/update/remove preserving selection and undo; a tether test-camera run of 20 frames keeps the undo stack and filter state (Swift). `cargo test -p index -p tessera-ffi --release`, clippy, fmt, `(cd apps/mac && ./build-ffi.sh && swift build && swift test -c release -Xswiftc -enable-testing)`. engine-api unchanged.
