# LR-3 / LR-7 read-only scouting (base `68264c74c365d8e7a4c33ddaecebf934f9305b08`)

## Existing path

- `crates/import-lrcat/src/lua_develop.rs`: one-to-one `KEY_MAP`; Lua parser rewrites mapped scalar/structured values into CRS XMP and routes through `crate::xmp::parse`. Both `RetouchAreas` / `RetouchInfo` and `PerspectiveUpright`, `PerspectiveVertical/Horizontal/Rotate/Aspect/Scale/X/Y`, crop keys already enter this path.
- `crates/engine-api/src/recipe/crs.rs`: existing mapping for `PerspectiveUpright` to `/settings/geometry/upright/mode`, perspective slider keys to `/settings/geometry/transform/*`, crop keys, and both retouch names to `/settings/locals/retouch`.
- `crates/sidecar/src/develop.rs`: `PerspectiveUpright` maps integer enum values by ordered list `[off, auto, full, level, vertical, guided]`; scalar geometry fields use generic numeric parsing. Structured Retouch keys delegate to `sidecar::structures`.
- `crates/sidecar/src/structures.rs`: Retouch currently only accepts Tessera `ts:*` native-encoded `id/kind/target/enabled` and native opacity/feather for RetouchInfo, or `crs:Opacity`/`crs:Feather` for RetouchAreas. Header explicitly says the Adobe item grammar is undocumented and these resource items are Tessera extensions. Foreign Adobe examples currently error; `RetouchInfo` is an empty alias if `RetouchAreas` exists.
- Existing recipe data is present: `crates/engine-api/src/recipe/mask.rs` defines Heal/Clone source offset (normalized), targets including Area components, operation opacity/feather/enabled; `settings.rs` stores `Vec<RetouchOperation>` at `/settings/locals/retouch`. However `rg` finds no `RetouchKind` render consumer in pipeline crates. `pipeline-cpu/src/locals.rs` only renders LocalAdjustment. Recipe retouch is not currently wired through CPU development render; smart preview rejects nonempty retouch (`crates/image-core/src/smart_preview_render.rs`). This contradicts the brief's assumption that existing heal/clone operators are available for LR-3 rendering.
- LR-7 rendering infrastructure does exist: `crates/pipeline-cpu/src/geometry_effects.rs` composes transform, crop, and Upright in a geometry pass; transform controls map to normalized coordinates (`p` ranges -1..1; translate uses offset/50, vertical/horizontal perspective coefficients /200). `crates/pipeline-cpu/src/upright.rs` handles Guided normalized guides and image-analysis modes. Existing CPU tests: `crates/pipeline-cpu/tests/lens_m2.rs`, `lens_embedded.rs`; geometry unit tests in `geometry_effects.rs`. Recipe docs (`settings.rs`) call guide lines normalized top-left coordinates.

## Adobe semantics / uncertainties

- Evidence in-repo is weak for literal Adobe RetouchAreas/RetouchInfo schema: only ExifTool-derived key names in brief/docs and `crates/sidecar/src/structures.rs` declaration that the string grammar isn't documented; existing fixtures are opaque or Tessera-native extensions. Do not promote guessed `SpotType`/center/source/brush attribute names into supported parser behavior without authoritative schema evidence (ExifTool source/docs or Adobe-exported synthetic test evidence). External search is needed for genuine schema provenance, but this scout did not browse.
- `UprightFourSegments*`, `UprightTransform_*`, `Upright*` names are not in the CRS key enum / table except current scalar `PerspectiveUpright`; search finds no parser mapping or recipe field for them. `GuideLine` already represents normalized 2-4 user guides, but relationship/order/packing and coordinate frame of Adobe `UprightFourSegments` is unverified. `UprightTransform_0..5` may be matrix coefficients but their ordering, precision, inverse/forward direction, normalized-vs-pixel frame, and composition with manual perspective are unverified. Do not map them as a homography by guess.
- Manual perspective slider geometry uses Tessera normalized image frame and width/height corrections. Any XMP/Lua coordinate that is pixel-based or normalized to a cropped/oriented active area must be converted before importing; tests must use non-square image dimensions and noncentral points to detect x/y swaps, top-left vs bottom-left origin, pre/post crop, and aspect scaling. Retouch source offsets are documented by Tessera as normalized deltas but Adobe source offsets and spot centers/radii coordinate frame are currently unknown. The brief's 1-px tolerance cannot be validated until Adobe normalization convention is sourced.
- `EnableDistractionRemoval` is absent from CRS enum/map and recipe; report explicit unsupported diagnostics with original key/value and user-facing explanation, as brief requests. Its cloud-removal semantics may not be reproducible locally.
