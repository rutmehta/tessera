# LR-4/5/6 integration blockers (read-only)

## Existing seams

- Mask recipes live in `crates/engine-api/src/recipe/mask.rs`: `LocalAdjustment` stores ordered `MaskComponent`s plus group `invert`, amount, params; `MaskKind::is_ai()` classifies subject/sky/background/person/object/landscape/depth as externally rasterized. Brush points are normalized x/y/pressure; brush radius is fraction of image width. `crates/pipeline-cpu/src/masks.rs` documents normalized-to-full-input-extent, top-left coordinate semantics and implements linear/radial/brush, luminance/color/depth range, invert + ordered add/subtract/intersect. Depth is an optional same-level near-to-far plane; missing depth errors.
- `crates/sidecar/src/masks.rs` imports/export CRS group adjustments, gradient/radial, and range controls, but explicitly does not define Adobe dab geometry, color-sample space, or AI raster/model formats. Paint brushes and color-range samples use typed Tessera `ts:` payloads; foreign dab payloads fail atomically. Range masks currently require native kind metadata; some Adobe structures have no established translation. It intentionally treats AI types as selection requests, not serialized raster payloads.
- `crates/mask-store/src/lib.rs` stores generic f32 alpha rasters by caller-provided 32-byte key; no image/recipe provenance metadata or recipe reference is stored. `ml-segment` derives keys from image bytes/dimensions + mask kind + algorithm/model version + prompt + level (`crates/ml-segment/src/model.rs::cache_key`) and persists the mask. Thus it is suitable as a regenerable derived cache, not yet as durable storage of imported Adobe masks: importer has no provenance key/schema/ownership route, and XMP codec has no raster parser.
- `image-core/src/mask_cache.rs` provides renderer `MaskHooks` for external planes and composes via `pipeline_cpu::masks`; `tessera-ffi/src/masks.rs` is the interactive provider. Export's `crates/export/src/ai_masks.rs` already takes injectable `mask_ai::MaskSegmenter`, builds requests, validates/resamples rasters, installs private hooks, renders locals, then effects/geometry. It rejects AI masks combined with unsupported lens warps, and current requests cover built-in model-supported categories only.
- `crates/ml-segment/src/model.rs` exposes subject/background/sky and SAM promptable masks/person/object; sky is expressly a blue-connected heuristic multiplied by subject, not a semantic sky network. Landscape is recipe-classified AI, but Segmenter / `mask-ai::SegmentRequest` have no landscape request/model; that needs explicit unsupported/regeneration diagnosis or a defined model.
- `crates/ml-depth` exposes cached model inference (`DepthEstimator::load_cached`, `estimate`), normalized `DepthMap::from_prediction`, `near_to_far()`, persistent depth cache and `image_core::depth::DepthProvider::from_map` for supplied deterministic planes. Model weights are pinned/cached only; `DepthEstimator::load` is the path that may resolve/download. `crates/export/src/depth.rs` and `crates/pipeline-cpu/tests/depth_render.rs` show supply-map render paths. Depth Anything provides relative inverse depth, not Adobe's original depth/range raster.

## Practical acceptance needs

- LR-4: keep synthetic XMP group → recipe assertions in `crates/sidecar/tests/masks_complete.rs` (or importer Lua integration). For CPU pixels use `crates/pipeline-cpu/tests/masks.rs` / `locals.rs`; assert order-sensitive union/difference/intersection, component and composite inversion, amount/params, edge boundary, and non-square full-extent coordinates. Existing procedural operators do not prove Adobe mask geometry when Adobe dab payloads are not parsed.
- LR-5: absence of Adobe raster blobs is real in current import interface; identify/catalog extraction source before promising exact imported mask pixels. If native `.lrdata`/Masks rasters are available, define import adapter to `MaskRaster` + content/model provenance and hook them before render. If unavailable, emit recipe diagnostic marking category + regeneration. For deterministic CPU acceptance inject a test `MaskSegmenter` (no ONNX weights) via `export::ai_masks::render_with_hooks` tests, or install fake `image_core::MaskHooks`; assert mask resampling/composition and resulting pixels. Existing `crates/export/tests/ai_masks.rs` is the relevant pattern. Real U2Net/SAM inference is model-cache/device-dependent and should not gate recipe codec tests.
- LR-6: for CPU geometry/render acceptance construct `DepthMap::from_prediction` and `DepthProvider::from_map` or pass `MaskOptions.depth`; avoid model inference/weight downloads. Assert near/far convention conversion, depth range selection, lens blur output and explicit warning/provenance that supplied depth is regenerated. A missing weights test should assert actionable model-cache diagnostic; it should not imply model inference succeeded.
- The generic mask store key and segmenter/depth cache keys are derived caches. Persisting a catalog-provided raster as canonical imported state needs a stable image identity + source-raster identity/dimensions/orientation/color-space metadata and recipe linkage; blindly keying it as a model-generated mask risks collisions or stale reuse.
