## Smallest coherent implementation slice

Add an internal, non-UniFFI Develop lease keyed by the existing `recipe_write::destination_key` (`recipe_write.rs:19-60`). Keep `GateState` alive through an RAII lease token that contains a monotonically allocated identity. The identity counter and active-owner slot must be protected by the same gate synchronization used by writes, so checking a lease and beginning its guarded write are atomic. The token retains `Arc<GateState>`; a stale identity cannot clear a newer owner or authorize publication. Return a typed conflict when an owner already exists or a caller uses a stale identity. Exhaustion should fail closed.

Open must acquire the owner under destination-gate → Engine catalog order, revalidate the indexed image ID to the same resolved path, and capture the pre-normalization recipe/owner baseline in that same critical section. Then release the short write/read guard before RAW decode, renderer/model setup, and worker spawn. Keep the lease local until session construction succeeds, then transfer it into the session. Any `?`/spawn failure drops the local token and releases admission. Preserve the existing recipe destination semantics; do not add canonicalization beyond `recipe_write::destination_key`.

Use typed gate writes: ordinary selection writes remain permitted and serialized while an owner is active; direct `set_recipe_json` is rejected while active; Develop full-save and auxiliary repair require the matching live lease identity. `save_develop` continues gate → catalog, path revalidation, last-published OwnerBaseline comparison, selection/unknown merge, and Stage A recipe/XMP/index behavior (`develop.rs:1140-1197`). It must not hold `Shared::state` or `SaveState` while waiting on the destination gate (the current save worker snapshots these before calling Engine save at `develop.rs:1715-1741`). `repair_develop` must also validate the matching lease (`develop.rs:1202-1222`) so stale worker work cannot publish.

Keep the lease through failed close and Stage B recovery. On successful close, release only after the final flush/repair completes, the save worker is stopped/joined, and rendering is closed (`develop.rs:2991-3029`). A failed flush returns the session to open and retains the lease for retry or explicit discard. Drop is the fallback release, but the Drop path must stop/drain the worker before the lease token is dropped. All state mutators continue to use `edit_lock`, which rejects `closing`/`closed` (`develop.rs:1447-1455`); preserve that atomic edit/schedule boundary. A retained session Arc after successful close must neither enqueue work nor hold a lease. Histogram remains independent and does not increment the writer/session counter.

## Dependencies, exclusions, and conclusion

No native prerequisite is outstanding in this source audit: the saved-recipe histogram is already split, current owner conflict and Stage A/B recovery are present, and the Engine exposes one direct whole-recipe setter plus the orthogonal selection writer. The only pending coordination input is Astra's independent current-UI/admission review; use it to confirm conflicts surface through the existing recovery/open flow without converting a failed close into discarded recovery ownership.

It remains an internal engine admission gate, not filesystem CAS or all-writer serialization.
