# WP M1-10 — Develop UI on the engine (Opus)

Read docs/01 §2.1–2.2 (histogram, Basic panel), docs/08 (latency targets), docs/11 §1.2 and §1.5, crates/image-core (Renderer, render_progressive, ProgressiveRenderJob, cache), crates/pipeline-gpu (GpuStageOp), crates/jobs, crates/tessera-ffi, apps/mac (Loupe Metal view with `present(frame:)` IOSurface hook, Inspector custom sliders, EngineLibrary).
Goal: real developing in the app. Dragging Basic sliders updates the loupe at screen resolution in < 16 ms per frame on the M4 (tone-only edits hit the memoized post-WB cache) and refines to 1:1 tiles when the drag settles; edits persist to the recipe JSON + XMP and are undoable.
1. FFI: `open_develop_session(image_id)` returning a session with `set_settings(json_patch)`, `get_settings_json()`, `get_histogram()`, `undo/redo/snapshot/reset`, and `attach_surface(iosurface_id, width, height)`. Rendering: the session owns a `Renderer` (GPU ops when available, CPU fallback) and a `ProgressiveRenderJob` on the shared scheduler at `Priority::Viewport`; on each settings change it cancels the previous job, renders the visible level into the attached **IOSurface** (Rust writes pixels via the IOSurface base address, RGBA8 or RGBA16F; choose and document; use the `io-surface`/`core-foundation` crates or a tiny objc2 shim), then calls back `frame_ready(level)`. Pixels never cross UniFFI as bytes.
2. App: bind the Basic panel sliders (Temperature, Tint, Exposure, Contrast, Highlights, Shadows, Whites, Blacks; Texture/Clarity/Dehaze/Vibrance/Saturation may stay disabled with a tooltip if the operators are not in pipeline-cpu yet) to the session with coalesced updates on a display-link; loupe presents the IOSurface-backed texture through the existing Metal layer with EDR/colour space set from the screen; histogram view (RGB + luminance, 256 bins) from `get_histogram`; ⌘Z/⇧⌘Z through the session; "Reset" and named snapshots; a small "render: L3 → L0, 7.8 ms" debug readout in the status bar behind a preference.
3. Persistence: settings go through `Recipe::edit` (history) and the sidecar crate on a debounce; reopening the image shows the edits; the grid thumbnail refreshes via the previews crate's recipe-hash keyed path (call the existing preview-ready mechanism).
4. Tests: Rust tests for the session API and the IOSurface writer (write a known pattern, read it back); Swift tests that a settings change results in a `frame_ready` callback and that reopening restores exposure; an ignored Rust bench for slider-latency (tone-only at level 2) printing ms.
5. ACCEPTANCE.md: add a "Develop" section (open a raw, drag Exposure, expect visible change and the debug readout under 16 ms for level ≥ 2, undo, quit/relaunch shows the edit).
