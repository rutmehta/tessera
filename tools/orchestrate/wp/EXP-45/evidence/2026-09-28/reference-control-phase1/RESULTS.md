# EXP-45 independent control: bounded A-host diagnostic

Date: 2026-09-28. Host: macOS 26.6.2 (25G83), arm64; SDK 26.5. All compilation used at most two jobs. No Tessera product source or assertion changed, no B host activity, and no application/GUI work.

## Frozen reference provenance

`git ls-remote` and detached source checkout both resolve Google `libultrahdr` tag `v1.4.0` to `d52a0d13814ca399fc8a07e23de1d2c63f0e8404`; checkout status is clean. The upstream CMake defaults in that source are `UHDR_WRITE_ISO=ON` and `UHDR_WRITE_XMP=OFF`, confirmed by `build/CMakeCache.txt`. The reference JPEGs were produced by its `ultrahdr_app` compressed-base/compressed-gain route from locally generated 80×16 cjpeg files; there was no metadata rewriting. Source, inputs, options, binaries, outputs, and direct exits are hashed in `MANIFEST.json`; exact encode/decode command arrays and exits are in `encode-*.json` and `decode-*.json`.

Unmodified upstream outputs: `fixtures/reference-4.jpg` SHA-256 `a4564ba16f3febd8330bc751e181209bf9a8bfd1b4118d7ec004db9a724315ce`; `fixtures/reference-16.jpg` SHA-256 `6c8c2bad6287de3c51ea6b1a5d4ce203b0edd66d046958acd7cb7631109567a4`. Each is 1,895 bytes. Both have primary/auxiliary ISO APP2 URNs and version bytes `00 00 00 00`, MPF two-image association, and ExifTool-extractable 416-byte auxiliary at offset 1479 with valid JPEG SOI/EOI. `ISO-MPF-COMPARISON.json` records exact offsets, extracted auxiliary hashes, metadata flags and rational values. The secondary ISO flag is `0x48` (one channel, base color space, common denominator); encoded alternate headroom/gain max are log2 values 2 for the 4× file and 4 for the 16× file.

Reference decoder requested the documented linear transfer (`UHDR_CT_LINEAR=0`) and half-float RGBA (`UHDR_IMG_FMT_64bppRGBAHalfFloat=4`). It returned opaque right-patch red/green/blue 3.486328125 for 4× and 13.9453125 for 16×; independently decoded base via ImageIO SDR is 0.871337890625 at that patch, a 16.0045 ratio for the latter. Thus the 16× candidate is a genuinely >8 **reference-codec** control, not merely declared 16× metadata. Its status as an ImageIO positive control remains unestablished.

## Same-A-host native result

The scratch `imageio-probe.m` copies the retained `headroom/probe.m` and only adds input-CGImage color-space presence/model/component/ICC-byte/hash reporting. It uses the same SDR/HDR request and extended-linear-sRGB float drawing. In the single three-file run (`native/imageio.json`, direct exit 0), both unmodified Google controls returned `iso_aux_present=false`, content headroom 1, and identical SDR/HDR pixels. Their right patch was 0.871337890625 in both modes. The retained A 4-stop JPEG in that same run returned `iso_aux_present=true`, SDR peak 1, HDR peak 7.983762264251709 and HDR content headroom 8. Its original frozen core gate remains 4 pass/1 fail with requested 16 and unchanged 4% assertion.

The software `coreimage-probe.m` is the retained probe's render logic adapted only to accept arbitrary 80×16 paths. Its same-host run (`native/coreimage.json`, exit 0) found no auxiliary gain image in either unmodified Google control; default expansion remained 0.871368408203125. It found A's auxiliary and expanded A to 16.000003814697266. The ImageIO HDR CGImage reported no copied color-space name, but had RGB model 1, three components and an ICC payload (588 bytes for Google, 26,620 for A); hashes are in `native/imageio.json`. Provider data is packed 10-bit/32-bpp and is not a linear float measurement. Drawing is to explicit extended-linear-sRGB RGBAf; context target 0 is not proof of a requested ImageIO decode target.

## Isolated MPF representative-bit control

`fixtures/reference-{4,16}-representative.jpg` are diagnostic copies, **not unmodified upstream files**. One byte at offset 702 in each was changed, making the primary MP entry attribute `0x20030000` instead of upstream `0x00030000`; this matches A's representative bit. Before/after bytes, source/output SHA-256 and exact one-byte diff are in `mpf-patch-*.json`. ExifTool still extracts the same auxiliary, and libultrahdr linear decoder outputs are byte-identical to the originals. But ImageIO still returns ISO auxiliary absent and identical SDR/HDR 0.871337890625; Core Image still finds no gain image (`native/representative/`). That bit alone is not the cause.

## Conclusion and next decision

The independent reference establishes valid ISO/MPF decoding and measured >8 linear output in the reference codec, but **does not provide a positive native ImageIO control on A**. The native failure to expose its auxiliary occurs already for the 4× reference. It therefore cannot arbitrate whether A's ~8× ceiling is an ImageIO capacity/representation issue or an A-specific interoperability issue. No host-support or encoder-acceptance claim follows. A structural difference remaining for source review is Google ISO secondary flag `0x48` (common denominator) versus A `0x40` (explicit per-rational denominators), along with ICC/container ordering differences; no further mutation was performed. A separately authorized, single-field denominator-form diagnostic could localize native admission, while preserving both original files and the unchanged A core gate.
