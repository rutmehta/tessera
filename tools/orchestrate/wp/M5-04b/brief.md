# WP M5-04b — GPU-resident document rendering with performance gates (Opus)

Read crates/compositor (COMPOSITOR.md, gpu.rs, render/*, the region-update work and IMPLEMENTATION-STATUS.md from M5-04), crates/engine-api 1.2 (NodeMemoKey, premultiplied flag, level_count semantics), crates/pipeline-gpu (resident model, band rendering, buffer reuse), crates/gpu-core if it exists.
Goal: the compositor's interactive path is GPU-resident: layer rasters and mips live in GPU textures uploaded once per revision, the step list is a persistent buffer, a frame composites a whole level (or a dirty rect) on the GPU with no per-tile uploads, adjustment layers run on the GPU for the implemented set, results stay resident for presentation (IOSurface write like the develop session) and are read back only for export. Set the premultiplied flag correctly on group/root composites; override `level_count` for deeper levels; update COMPOSITOR.md (§11 and the engine-api version line). Targets: 100-layer 20 MP document: level-2 recomposite after a 64² brush dab < 16 ms; full L0 composite < 100 ms; document open (cold) < 1.5 s. Share the device with pipeline-gpu via `gpu-core` (split the device/queue/utilities out of pipeline-gpu if M5-04 did not) so the app has one GPU context. Gate vs CPU per docs/11 §1.3; determinism test; bench (ignored, prints) before/after.
`cargo test -p compositor -p psd -p pipeline-gpu --release`, clippy -D warnings, fmt. engine-api unchanged. Allowed: Cargo.lock, Cargo.toml, crates/compositor/**, crates/gpu-core/**, crates/pipeline-gpu/**, crates/image-core/** (only if the device split requires), tools/orchestrate/wp/M5-04b/**.
