# WP M2-23 — Design system and visual overhaul of the Mac app (Opus)

The owner reviewed the app and rejected the current look: "buttons are bubbles", weird spacing/sizing, overlapping elements, and a colour scheme that reads as Photoshop/Lightroom. It looks AI-generated and dated. This package replaces the visual layer with a coherent, modern, restrained design. Functionality and keyboard behaviour must not change.

## Process (non-negotiable)
1. Load and follow the skills `apple-design`, `emil-design-eng`, and `ui-ux-pro-max` (use the Skill tool) before touching code. Read docs/11 §1.5 (AppKit where it matters, SwiftUI elsewhere).
2. Audit first: launch the app (`--app-dir "$SCR/appdir"`, scratch copies of fixtures/raw and the sample folder) and capture window-only screenshots of every surface: grid, loupe/develop with each inspector panel, masks toolbar, compare, filter bar, sidebar states, sheets (smart album, import, export, print), toasts, status bar. Write `apps/mac/DESIGN_AUDIT.md`: a numbered list of concrete defects (overlaps, misaligned baselines, inconsistent radii/heights, pill overuse, contrast failures, off-grid spacing) with the screenshot each came from.
3. Write `apps/mac/DESIGN.md`: the design system. Requirements:
   - **Identity**: quiet, precise, modern pro tool. Not Adobe. Dark-first with a full light appearance (macOS system appearance is respected). Near-black canvas with warm-neutral graphite panels (define exact tokens), hairline separators at 1 px, one accent colour used sparingly for selection/focus/primary action (choose and justify; avoid Adobe blue), semantic colours for decisions (reject/keep/grade) that are desaturated and consistent.
   - **Type**: SF Pro with defined scale (11/12/13/15/17/22), tabular figures for all numeric readouts (SF Pro's monospaced digits), tracking rules per size, one weight system (regular/medium/semibold only).
   - **Layout**: 8-pt grid, 12-pt panel gutters, 4-pt micro spacing, fixed control heights (20/24/28), consistent corner radii (4 for chips/inputs, 6 for buttons, 8 for cards/sheets); no floating pills in the title bar: use a real `NSToolbar` with `NSToolbarItem`s / SwiftUI `.toolbar`, segmented control for Grid/Loupe/Compare, toggles for Auto-advance and Inspector as toolbar items with icons + labels.
   - **Components**: buttons (bordered / borderless / primary), segmented control, slider (thin track, 12-pt thumb, value readout aligned right in tabular figures, double-click resets, ⌥-drag fine), chips/badges (decision, mark, status, group, "suggested" – one family, one height, uppercase small caps only where meaningful), sidebar rows (source-list style with vibrancy material), inspector sections (collapsible disclosure headers, consistent header height, no "+/−" glyph mismatch), panels, sheets (consistent header/footer, primary action right), toasts, tooltips, empty states, focus rings, hover states, pressed states; motion: 150–200 ms ease-out, reduced-motion respected.
   - **Density**: pro density; grid cell chrome minimal (badges only on hover/selection or when set), filmstrip thinner, status bar one line with clear grouping.
   - Include token tables (colours for both appearances, spacing, radii, type) and do/don't examples.
4. Implement: a single `Theme` (Swift) that all views use (colours, spacing, radii, fonts), then refactor every surface listed in the audit to the system. Remove ad-hoc padding/radii/colours. Fix every defect in DESIGN_AUDIT.md and tick it off with an "after" screenshot.
5. Review loop: after implementation, re-capture every surface in both appearances at 1x and 2x, compare against DESIGN.md, iterate at least twice. Put before/after pairs in `tools/orchestrate/wp/M2-23/evidence/` (window-only captures).
Constraints: keep all keyboard shortcuts and behaviour; do not change engine or FFI code; Loupe rendering internals are being changed by M2-22 concurrently — apply only theme tokens to Loupe chrome (toolbar/overlays), not to the Metal presentation code. Tests: existing Swift tests must pass; add a test that every colour/spacing used in views comes from Theme (a lint script over Sources/ that fails on raw `Color(`/`.padding(<number>)` literals outside Theme is acceptable). `(cd apps/mac && ./build-ffi.sh && swift build && swift test)`.
Commit as "wp(M2-23): design system and visual overhaul". Report: the audit summary, the identity choices, before/after screenshot paths, and anything unfinished.
