# Calibrated Smart Preview GPU rollout assessment

Source-only review; no builds, measurements or source changes. Conditional recommendation: enabling calibrated backend selection for an explicitly selected Smart Preview is reasonable after the remaining actual Auto SDR/EDR and coherent native/Swift gates pass. Original must remain the source default; CPU override, unavailable-device handling and mapped/unsupported CPU fallback remain. No newly identified correctness blocker requires retaining the environment opt-in indefinitely, but current evidence is insufficient for an unconditional cross-device speed claim.

Opening cost is a material product tradeoff: observed ~0.6s calibration per proxy session versus ~39ms CPU opening is distinct from warm edit benefit. select_proxy constructs fresh backend/cache state on every session and measures CPU and GPU first/tone/WB work. gpu_is_faster compares warm tone/WB only; it does not amortize calibration or initial-open latency. Approximate break-even edits = additional open milliseconds / measured milliseconds saved per warm edit, separately for each measured workload. Do not describe automatic selection as faster for short one-frame opens.

Source guarantees: CPU override exits before GPU creation; unavailable GPU/context falls back CPU; failed calibration retains CPU. Capability and execution both exclude mapped proxy geometry. Develop recomputes capability on every edit, so crop/transform/lens cases use CPU and reset can restore residency if the session selected GPU. Source preference and original backend OnceLock are unchanged. Selected backend label includes CPU fallback and is not per-frame telemetry. HDR calibration uses temporary SDR policy; actual live HDR recipe remains intact.

Resource qualification: each proxy session has its own operators/resident cache and TileCache rather than the Original's shared selected backend. RendererConfig defaults to512MiB budget, applied separately to each cache, plus transient allocations. They are bounds, not upfront allocations; source inspection does not establish process-wide memory cap or release timing. Run bounded repeated open/edit/close/release checks for stale jobs/leases and memory growth before making a resource-efficiency claim. Existing single-image lease prevents same-image conflicting editors but is not a global multi-image cache cap.

Nonblocking optimization worth doing separately: known unsupported/mapped initial recipes currently calibrate two scalar paths. That cannot establish a resident benefit and adds needless latency; an early capability rejection can skip calibration. Do not fold unreviewed reuse/cache-selection architecture into this rollout. Calibration selectedCPU at open remainsCPU after geometryreset; calibration selectedGPU retains fallback as edits become unsupported. That is truthful behavior, not guaranteed dynamic backend reselection.

Minimum acceptance before removing opt-in:

1. Actual Engine Auto SDR and EDR on the preserved Sony fixture, matched viewport/recipe/output against Original and forcedCPU controls; record backend selection AND each delivered frame's resident receipt/submission/readback counters, final/adaptive level, pixel parity, and finite HDR0..4 with >1 highlight. Auto route must genuinely calibrate, not use forcedGPU. Publish coldopen/calibration separately from warm edits.
2. Existing full positive unmapped L0/coarse SDR/EDR and signedHDR fixtures, mapped geometry exactCPU fallback, capability/surface agreement through edit/reset, canceled/cache-zero/eviction cases, CPU override and unavailable/unsupported behavior. Preserve original failures and unchanged tolerances.
3. HDR build/journal/thumbnail/reopen tests plus generic SDR rejection controls; final affected native suites/strict/fmt. Coherent regenerated archive/bindings and focused actual Swift offline workflow/thumbnail tests, strict product/full Swift gates on frozen combined sources.
4. Exercise normal shipped open path with the environment gate absent, including CPU override and a mapped proxy; positive unmapped path should select via calibration, not by test-only env bypass. At least a bounded repeated session lifecycle check because per-session caches are newly made routine.

Single-camera limitation: actual measurements cover one Sony RAW/Compact asset and one Metal device. Synthetic tests broaden signed range, dimensions, calibration/lens cases, levels and cache policies, but do not establish all camera calibrations/GPU drivers or other active-tail workloads. Retain precise scoped performance wording and CPU fallback; do not claim DNG compatibility or universally faster interaction. Existing embedded/unsupported cases remainingCPU is intentional.
