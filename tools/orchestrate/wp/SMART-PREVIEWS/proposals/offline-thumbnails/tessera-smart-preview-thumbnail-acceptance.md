# Offline proxy thumbnail acceptance checklist

Source audit of existing journal/admission/PreviewJob. No implementation/builds performed. Review eventual candidate against these bounded requirements.

1. Read-only local authority: journal reads must not call current SmartPreviewJournal::open unchanged; it delegates to new and durable directory ensure. smart_dir itself only joins paths (earlier shorthand suggesting it creates was imprecise). Add a read-only existing-directory path that converges on the SAME canonical process lock. Never stat/open/hash original or consult original sidecars. Missing journal/assets fail without recreating directories.
2. Snapshot consistency: validate exact owner/source length+digest, full container identity, local recipe and prefix compatibility. Hold short ID read admission during capture; it permits active proxy editors. Use consistent ID -> journal -> request-state ordering; avoid taking journal then ID. Release all locks during expensive render and callbacks. Retaining a journal handle and calling snapshot already checks incarnation+revision; use that or equivalent token rather than generation-only ABA checks.
3. Delivery consistency: requests/cache keys include source role, owner, immutable asset digest, recipe digest, size, orientation/domain version and incarnation/revision as appropriate. Validate current local token before cache-hit return and before Ready publication; in-process edits/discard/rebuild cannot interleave between final check and publication. Cross-process mutation is outside existing admission guarantees; do not claim more. Bytes for an old snapshot may remain in content-addressed disk cache but must not be returned for current identity.
4. Scheduler semantics: same current request coalesces pending work. Success and failure publish terminal state before PreviewReady, without locks held during callback. Cancellation before run and queued job drop must terminate pending with notification; completed flag must be set BEFORE emit so callback reentry/replacement cannot be overwritten by Drop. Stale completion must neither replace a newer request nor leave old waiters permanently pending. Engine lifetime uses Weak; no work should keep an abandoned engine alive indefinitely.
5. CPU path: captured pre-WB proxy RGB uses original calibration and local recipe settings, then orientation/geometry/output consistently; cap request size, bound decode/allocations and JPEG bytes. Reject unsupported/corrupt data rather than silently falling back to original/default settings. Native export remains original-only. Every Swift cache tier must invalidate when source role/journal identity changes; native cache-key correctness alone cannot invalidate a previously returned UIImage/CGImage.

Focused actual-API acceptance cases (deterministic synchronization where race ordering matters):

- Valid local declaration with physically absent original: first response pending, bounded completion event, next response valid JPEG with capped dimensions; source/hidden folder hashes unchanged and original path absent. Repeat hits cache. Active proxy editor does not block read-only request.
- Edit recipe after successful thumbnail: new identity delivers changed pixels; no original I/O. Ordinary original preview API behavior/revision cache unchanged.
- Queue/block worker, edit journal, release worker: old job does not publish bytes as new state; current request succeeds and emits terminal event.
- Queue/block worker, discard clean preview and recreate same ID with generation1: old incarnation cannot publish/deliver; recreated asset request renders its own pixels. Discard without recreation produces terminal missing response and no directory recreation.
- Corrupt/truncate/delete pixels or corrupt journal after a warm cache: no warm byte return; explicit terminal failure. Corrected/new identity can retry rather than being poisoned by old failed state.
- Change asset while pending: exact identity recheck rejects old completion. Exercise stale cache-hit race as well, not only expensive-render completion.
- Pre-cancel and queued-drop: one terminal notification, no indefinite pending. Listener reenters request API from callback without deadlock, and an evicted-ready replacement is not failed by completed job Drop.

Keep main Swift offline Develop/save/reopen/sync test separate from thumbnail gate; new asynchronous proxy thumbnail must be polled, not asserted from one synchronous render call. Existing source fixture is copied and hash-protected. This checklist is not a request to implement new global scheduling or cross-process locking architecture.
