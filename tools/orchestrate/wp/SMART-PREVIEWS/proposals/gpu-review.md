# Independent camera-linear GPU proposal review

Reviewed `/tmp/tessera-smart-preview-gpu.patch`, `/tmp/tessera-smart-preview-gpu-review-notes.md`, and the existing image-core/scalar/resident backend implementations against which it is prepared. Source-only: no apply, builds, tests or shared-source changes. Proposed line references refer to the patch/new staging files.

## Result

**No actionable source-level correctness defect found in the scoped L0 resident route. Approve for controlled integration and numerical qualification, not as a passed GPU feature or performance result.**

## Audited behavior

- `pipeline-cpu/src/smart_preview.rs::resident_tail_plan` validates the immutable prefix and delegates to the captured `ResolvedLens`; it does not resolve new optics against the proxy. `lens_plan.rs::plan_in_frame` disables CA plan construction when `prefix_baked`, permits already-baked manual CA, and retains captured vignette/common geometry. Embedded dependencies are explicitly declined rather than stripped. Existing original-source wrappers pass the original crop dimensions and `prefix_baked=false`, preserving their prior path.
- Guided geometry receives actual proxy dimensions. Other geometry uses the existing normalized map/crop operations. The image-core resolver sets proxy sensor/crop addressing and clears CFA halos without rewriting original camera metadata or owner identity. Its call to `resolve` obtains calibration from metadata and does not dereference missing CFA pixels.
- `smart_preview_render.rs::resolve_camera_linear` retains original camera-profile and WB matrices from the shared resolver. `resident_render.rs::balanced_tiles` applies CameraProfile, then WhiteBalance, then captured vignette; subsequent Detail/Tone/Color/Effects/map/output order uses the existing resident tail. Lateral CA is not applied a second time.
- Camera-linear input uses `upload` followed by `cache_exact`, avoiding the backend's f16-rounding `upload_cached`/`cache` route. WhiteBalance and Detail checkpoints likewise remain exact. Backend inspection confirms upload copies F32 tile samples and `cache_exact` returns the original resident tile even when the budget refuses retention.
- Memo keys retain `RawImage::id()` (the separate immutable render identity), with an additional representation/generator/scale/frame domain chained into stage hashes. Prefix/calibration/payload identity still relies on the constructor's verified distinct render-ID contract; the patch does not pretend the recipe owner is the pixel identity. Downstream WB/tone/geometry changes retain the existing stage-chain invalidation structure. Captured tail parameters are tied to immutable proxy identity/prefix.
- Resident admission is L0-only. Higher levels preserve scalar reduction after nonlinear processing and geometry. Embedded tails, unsupported geometry/defringe and local masks retain scalar fallback. The original-only export-row and working-RGB-layer guards are unchanged. Other unqualified resident metrics/region APIs continue declining proxy execution.
- The surface branches validate representation/settings, decline coarse output, reject SceneLinear surface requests, and reuse the existing surface-target/histogram completion protocol. Cancellation is checked before submission through the shared resident pipeline and before tile delivery; no new independent surface ownership or unchecked completion path is introduced. Exact in-flight cancellation behavior still needs the existing backend tests plus the proposed surface tests.

## Qualification and integration prerequisites

1. Compile and run proposed CPU-vs-GPU tests across cold/warm/zero-budget/rejected-cache paths, HDR F32 fallback and macOS surfaces. Tolerances and the adversarial HDR fixture are proposed assertions, not observed results. Run existing original lens/resident regressions because the plan builder is refactored.
2. Add a genuinely reduced proxy case (scale greater than one, preferably a non-power-of-two scale when Compact lands) with non-square Guided geometry. Current new GPU fixtures are 269x67 and therefore scale one; the source correctly passes proxy frame dimensions, but the tests do not discriminate original-dimension misuse in that case. A DisplayLinear/float-surface comparison would qualify the newly reachable HDR display route beyond the current RGBA8 test.
3. FFI currently deliberately chooses a CPU renderer for camera-linear proxies in `Engine::renderer_for_image`. This patch does not change that selection. A separately qualified FFI selection change is needed before the desktop editor can use this GPU route; component capability alone does not change the measured app path. Keep original-default source selection until actual end-to-end measurements justify a policy change.
4. No runtime or storage measurement was performed. Compact remains an independent unapplied patch. Actual extent/scale use avoids assuming 2560 pixels or factor two, but merge/rebase and version-specific roundtrip tests remain necessary. The noted matched-output comparison requirements for Compact are correct: original power-of-two pyramid levels do not directly match 1640x1092.

These are qualification boundaries rather than demonstrated source defects. This review does not establish numerical parity, faster editing, low-memory behavior under execution, Metal availability or GUI acceptance.
