## Review findings

- **Rust shape/API:** The test module's parent-private `presence`, `luma`, `encode`, `guided`, `range`, and `ToneSettings` are accessible from child `eng1_conditioning_tests` via `use super::*`. `Vec`/array APIs, `f32::next_up/down`, `each_ref`, closure coercion from `&Vec<f32>` to `&[f32]`, and format captures are plausible on the repository's `stable` toolchain. This is source inspection only; compilation still must be observed. The `presence()` result is `()`, so the unwrapped call is type-consistent.
- **Cancellation triplet:** `[0.678_f32, -0.2627_f32, 0]` is designed to cancel exactly under the source's left-associated luma expression because the first two products have the same operands in reversed order and opposite sign. `next_down/next_up` on G should produce opposite-sign neighbors; the assertions explicitly validate the CPU classifier before tests rely on them. This is a good fixture-validity guard, not evidence of GPU classification (no GPU test is in this commit).
- **Request witness:** `RequestWitness` recomputes z with the same encode/luma; reuses `guided` and `range`; then independently expresses only the upstream texture request. It deliberately does not encode the disputed RGB gain/divisor formula. Operation order for texture delta and clamp matches `presence()` closely. This is valid as a fixture/branch-activation witness, not an independent oracle for neighborhood math or expected RGB. The test asserts a positive non-neutral request before interpreting sensitivity failures, so a clipped/vacuous fixture is called out as validity failure.
- **Almost-no-op selection:** Search is fixed and bounded at k=0..96, and uses request delta in `(0, 4 ULP]`, avoiding exact-zero request selection. It then independently searches halvings `1..=32` for a nonzero control whose computed adjusted value is exactly `z`; that exact case asserts bit identity for center signed RGB. Since the source's actual presence path also skips `adjusted == z`, this covers both exact identity and nearby changed request. However the witness can choose a nonzero control that rounds to exact no-op, intentionally; a future execution should log selected control and request delta. The 1–4 ULP branch still needs observed RED, not presumed failure.
- **Fixed eligible neighbor coverage:** The final test enumerates fixed R/G/B × down/up (six) neighbors for both the constructed cancellation vector and historical diagnostic vector. It skips only neighbors whose measured CPU luma is nonpositive, checks each base is positive and its request active, asserts each case has at least one eligible neighbor, evaluates every eligible full-frame pair, scans all output floats, and asserts only the worst after completing the set. Thus it does not cherry-pick one successful perturbation; report prints the worst and input delta. The requested follow-up adds one diagnostic line per eligible pair and a per-case eligible count (maximum 12 pair lines across both center cases), including perturbation direction, input/output delta and worst output coordinate.
- **All-pixel sensitivity:** `max_delta` scans all 3×27×27 planar samples and checks finite values, both for sign crossing and ULP neighbor outputs; reported `i/N`, channel, and x/y decoding are consistent with planar channels. This is scene-linear `1e-4`, stated distinctly in code and handoff from the encoded Camera Raw `0.01` requirement. The bound is coordinator-selected per task, not a result or Apple/Adobe standard.

## Risks / coverage remaining

1. The center cancellation tests directly call CPU `presence()`; they do not test GPU `presence.wgsl`, `tone_local.wgsl` mode 6, CPU/GPU classification disagreement, or backend parity. Handoff correctly lists these as remaining.
2. The authored center/request path exercises Texture only (`ToneSettings { texture, ..default }`). It does not yet cover Clarity-only, combined Texture+Clarity, positive Texture sign, or a clear Clarity-specific witness. Handoff correctly lists positive/darkening and Clarity witnesses as remaining.
3. These fixtures manually insert signed RGB; they do not prove a `detail()` sharpen operation produces the same witness. The planned deterministic detail→presence chain remains necessary before claiming integration coverage.
4. Test A's one-step transition `negative -> exact zero -> positive` is explicitly conditional on a fixture-valid active positive request. It can expose the preserved nonpositive skip discontinuity, and currently imposes the selected `1e-4` bound across full-frame outputs. Whether that bound is the accepted render contract is a design question, not settled by test validity.
5. `max_delta` compares full outputs for center perturbations, which is useful because guided windows propagate changes spatially. In `almost_noop...`, the assertion compares only center RGB, as intended for a center witness; do not describe it as all-pixel there.
6. The authored tests are CPU-only and no source contains changed numerical behavior. The tests may fail baseline (that is the planned diagnostic), but until the authorized compiler lane runs them, no claim about Rust compilation, fixture witness success, RED, or pass status is supported.
