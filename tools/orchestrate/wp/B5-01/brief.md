# WP B5-01 — FFI `DocumentSession`: layered documents for the mac app (Opus)

Read crates/tessera-ffi/src/develop.rs (the `DevelopSession` pattern: listener, `plan_surface`/`attach_surface`/`detach_surfaces`, IOSurface presentation, `set_settings(json_patch, interactive)`, history items/groups, snapshots, `flush`/`close`), crates/tessera-ffi/src/surface.rs (`Surface`, `create_rgba8`/`create_rgba16f`, `write_*`), crates/tessera-ffi/src/export.rs (encoders, full-resolution develop render), crates/compositor (document.rs `Layer`/`LayerKind`/`LayerProps`/`Mask`/`Fill`/`GroupMode`, edit.rs `Document`/`DocOp`/`History`/`paint_op`, adjust.rs `Adjustment`, format.rs `save`/`load`, psd.rs `ImportedPsd`, resident/mod.rs `render`/`present_iosurface`/`read_level`, COMPOSITOR.md §8, §11, §12), crates/psd (reader/writer), crates/gpu-core (shared device: the develop session already owns one; reuse it, never create a second device), engine-api 1.2 (`DocumentId`, `LayerId`, `DocumentHistoryEntry`, invariants 16–18), apps/mac/README.md (bridge conventions: ids and small records cross UniFFI, pixels never do).

Implement `crates/tessera-ffi/src/document.rs`, registered from lib.rs, mirroring `DevelopSession`:
- **Open/create on `Engine`**: `new_document(width, height, depth: DocDepth, profile: Option<String>)`, `open_document(path)` for `.tessera-doc`, `.psd`/`.psb` (through the psd adapter; unknown keys preserved for save-back), and flat JPEG/PNG/TIFF (one pixel layer named after the file), `open_document_from_image(image_id, developed: bool)` which renders the library image (its develop recipe when `developed`, at full resolution through the export path) into a single pixel layer and records the source image id in the document. Each returns `Arc<DocumentSession>`; a `DocumentId` string identifies it; the same path opened twice returns the same session.
- **Model reads**: `info() -> DocumentInfo { id, path, title, canvas w/h, depth, profile name, dirty, history head, selected layer ids }`; `layers() -> Vec<LayerNode>` flat pre-order with `id, parent, index, depth, kind (pixel/adjustment/fill/group/smart_object/text), name, visible, opacity, fill_opacity, blend_mode (stable string names matching COMPOSITOR.md §2), group_mode, clipped, locks, has_mask, mask_enabled, mask_linked, adjustment_json, fill_json, bounds`; `layer_thumbnail(id, max_px) -> u32` writes an RGBA8 IOSurface (created via surface.rs, cached per layer revision) and returns its id; `composite_thumbnail(max_px)` likewise.
- **Edits** (each is exactly one `DocOp` through `Document::apply` and returns `DocumentUpdate { layers changed, history head, dirty rect at level 0 }`): `add_layer(kind: NewLayer, name, parent, index)` where `NewLayer` covers pixel (blank), group, adjustment (from JSON), fill (from JSON), and `duplicate_layer`, `remove_layer`, `move_layer`, `set_props(id, LayerPropsRecord)`, `set_visible`, `set_opacity(id, value, interactive)` (interactive = no history node until `commit`), `set_blend_mode`, `set_group_mode`, `set_adjustment_json(id, json, interactive)`, `set_fill_json`, `set_mask_enabled`, `remove_mask`, `add_mask(id, MaskInit::RevealAll|HideAll|FromSelection)`, `set_clipped`, `merge_down(id)`, `flatten()`, `set_selection_rect(x, y, w, h, feather)` and `clear_selection` (the marquee only; other selection tools arrive with B5-04 once `crates/selection` lands), `commit(label)`.
- **History**: `undo`, `redo`, `history_items() -> Vec<DocHistoryItem>` (id, label, parent, is_current, author), `checkout_history(id)`, `snapshot(name)`, `snapshots`, `restore_snapshot`, memory cap from `set_max_states`.
- **Presentation**: `DocumentListener` (`on_frame(FrameInfo)`, `on_layers_changed`, `on_history_changed`), `plan_surface(width, height) -> SurfacePlan`, `attach_surface(iosurface_id, w, h)`, `set_viewport(level, x, y, w, h, zoom)`, `set_display_headroom`, `refresh`, `detach_surfaces`. Rendering uses the resident compositor on the shared `gpu-core` device and presents through `present_iosurface`; the interactive path (opacity drag, adjustment slider drag) must recomposite at the viewport level in < 16 ms on the 100-layer 20 MP bench document from COMPOSITOR.md §12.4. Checkerboard is drawn by Swift, so present straight alpha in the surface and say so in the doc comment.
- **Output**: `save()`, `save_as(path)` (`.tessera-doc`, or PSD/PSB when the path says so, including the flattened composite for compatibility), `export_flat(path, ExportFormat, quality, ExportColor)` reusing export.rs encoders and colour management, `close()`.
- Errors are `EngineError` variants like the develop session. Every mutation increments the document epoch and the listener fires once per coalesced frame, not once per op.

Tests (`crates/tessera-ffi/tests/document.rs`, headless: render with `read_level` instead of a surface): new document → add pixel + adjustment + group → `layers()` order and depths; undo/redo/checkout restore the tree; save/load `.tessera-doc` round trip; a PSD written in-test by `psd` opens with matching layer names/modes and saves back with unknown keys intact; `open_document_from_image` on `fixtures/raw/sample.dng` produces one pixel layer of the raw's developed size; `export_flat` PNG equals the compositor CPU composite within docs/11 §1.3; thumbnails are cached per revision (count renders); interactive `set_opacity` adds no history node until `commit`. Add `document` calls to `apps/mac/README.md`.

`cargo test -p tessera-ffi -p compositor --release`, clippy -D warnings, fmt, then `(cd apps/mac && ./build-ffi.sh && swift build)` so the regenerated bindings compile. engine-api unchanged.
