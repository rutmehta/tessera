# WP M2-07 — Sparkle auto-update, signed release builds, GitHub release pipeline

Read apps/mac (Package.swift, Support/make-app.sh, Info.plist, README.md), docs/13-licensing.md (Sparkle is MIT: allowed), ci.sh. The repo is public at github.com/rutmehta/tessera.
1. **Sparkle 2** via SwiftPM (`https://github.com/sparkle-project/Sparkle`, pin the latest 2.x tag). Wire `SPUStandardUpdaterController` into the app: "Check for Updates…" in the app menu, automatic checks on (daily), `SUFeedURL` = `https://github.com/rutmehta/tessera/releases/latest/download/appcast.xml`, `SUPublicEDKey` read from Info.plist. Include the Sparkle XPC services correctly in the bundle produced by `make-app.sh` (Sparkle's docs: the framework must be embedded and signed; the Installer and Downloader XPCs are inside the framework for SPM builds).
2. **Keys**: do NOT generate or commit a private key. Write `Support/release/README.md` explaining: run Sparkle's `generate_keys` once (stores the private key in the login Keychain), paste the printed public key into `Support/Info.plist` as `SUPublicEDKey`, and export it for CI with `generate_keys -x` into the GitHub secret `SPARKLE_PRIVATE_KEY`. Leave `SUPublicEDKey` empty with a build-time warning if unset.
3. **Signing**: `make-app.sh release` signs with `CODESIGN_IDENTITY` (default `-` ad-hoc); `Support/release/notarize.sh` runs `xcrun notarytool submit --wait` + `stapler` when `NOTARY_PROFILE` (a keychain profile name) is set and skips with a message otherwise. Hardened runtime + entitlements file (no sandbox for now) applied in both cases. Produce a DMG (`create-dmg`-free: `hdiutil`) named `Tessera-<version>.dmg`; version from `git describe --tags`.
4. **Appcast**: `Support/release/make-appcast.sh` runs Sparkle's `generate_appcast` over a `dist/` folder (uses the Keychain key locally or `SPARKLE_PRIVATE_KEY` in CI) and emits `appcast.xml` plus delta updates when previous versions are present.
5. **GitHub Actions** `.github/workflows/release.yml`: on `v*` tags, macOS runner: `rustup`, build FFI (`build-ffi.sh`), `make-app.sh release`, sign with Developer ID if `APPLE_CERT_P12`/`APPLE_CERT_PASSWORD`/`NOTARY_*` secrets exist else ad-hoc, DMG, appcast, then upload DMG + appcast.xml as release assets (`softprops/action-gh-release` or `gh release upload`). Also `.github/workflows/ci.yml`: on push/PR run `bash ci.sh` (with the fixture fetch cached) and `swift build && swift test` — the repo currently has no CI.
6. Tests: `swift build && swift test` still pass with Sparkle linked; a script test that `make-app.sh release` produces a bundle whose `codesign --verify --deep --strict` passes (ad-hoc) and that contains `Sparkle.framework`; `make-appcast.sh` on a fake `dist/` with an unsigned dummy zip fails clearly when no key exists (document expected output).
