# PERF-1 benchmark draft source review

Reviewed `/Volumes/betterSSD/tmp/perf1-benchmark-test.rs` against the b64e5e00 style-pass implementation and PERF-1 source plan. Read-only; no build/test/runtime run.

## Actionable blockers

- **Strict Clippy:** `assert!(!cfg!(debug_assertions), ...)` triggers `clippy::assertions_on_constants` because the cfg macro is a compile-time constant. Use the explicitly requested `if cfg!(debug_assertions) { panic!(...) }` form (or cfg-gated panic) before strict Clippy.
- **The documented 14MP run is not a parity gate against the frozen base.** `render(false)` calls the candidate's private uncached style-pass seam, so the test proves candidate cached-vs-uncached parity only. The draft correctly says this, but the plan's preimplementation numerical oracle remains mandatory and has to be captured/run separately on base `ebae08bb`; do not report this benchmark's digest as cross-revision parity.
- **Large untimed precheck creates allocator pressure before timings.** The 14MP path intentionally keeps the 226 MB uncached output alive while constructing the cached output/pass (roughly another 226 MB output plus ~648 MiB source/plane payload, in addition to fixture, scratch, compositor state). Dropping them before timing avoids live peer outputs, but allocator high-water/system paging can still contaminate the following timed runs. Prefer run exact full-bit parity only on smoke and perform the large candidate-vs-uncached digest validation in a separate process/lane before benchmark trials, or otherwise clearly record that the timed trials follow a high-water validation pass. Do not compare RSS from this combined test as if it were timed-render peak.
- **Benchmark boundary differs from source plan/export target.** This draft deliberately times premultiplied full-level tile rendering and excludes compositor construction, RGBA conversion/unpremultiply, and encoding. That can be a valid focused engine benchmark, but update/label the reported target accordingly; it is not the plan's full `render_level_rgba` cold-export boundary or end-to-end export. Both candidate control paths do use the same premultiplied method, so the internal comparison is fair.

## Plausibility and scope notes

- The entry payload estimate is correct for this fixture: dense F32 RGBA source + one shadow + one glow plane is `width*height*16*3` (about 648 MiB at 4608×3072), beneath the 1 GiB StylePass limit. The separate 64 MiB compositor-cache limit does not replace that pass limit. `render_level_premultiplied` gives the cached path the default pass; the private `None` seam makes a serial uncached control, and styled frames are serialized in both cases. For fresh compositors, expected source/style counts `(tile_count,tile_count)` versus `(1,1)` match the current counter increments/call structure, subject to actual test execution.
- Render timer encloses the full-level call, including StylePass destruction, while compositor construction, digesting and returned output teardown are outside. Returning tiles after local compositor destruction is safe because tiles own shared backing buffers. Every trial uses a new compositor, so these are cold frame-cache renders; one warmup only warms code/allocator. The draft accurately labels these boundaries and the synthetic single-raster/no-font/no-decode fixture.
- The fixture is not the B5 gradient-plus-text scene and contains no gradient background; keep it described as a synthetic raster workload, not an exact or close text-export reproduction. Its deterministic hole/fractional-alpha geometry is suitable for work/parity coverage.
- Full-bit same-candidate equivalence and digest checks are meaningful, but neither independently checks the blur/morphology kernel. Preserve the separate frozen baseline and analytic kernel tests. Three measured pairs are a modest diagnostic; source plan asked for five fresh-compositor trials. Increase to five if the runtime budget permits; otherwise report the reduced sample count and do not imply a stable benchmark.
- No additional Rust API/type blocker seen: the private helper is callable from this descendant test module; Tile samples/digest APIs, atomic counters, Duration sorting and fixture constructors are consistent with nearby source use. Compilation remains unverified.
