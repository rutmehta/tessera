# PERF-1 source-only plan

Inspected base `ebae08bb` (HEAD verified), updated phase-2 brief, and `git show origin/wp/B5-prof:tools/orchestrate/wp/B5-prof/REPORT.md`. No builds, edits to repository, application/GUI, or catalogs. Claude owns merge; Machine B owns app-side spans/routing.

## Evidence and root cause

The report's 83,080 ms styled export and 622,858 aggregate CPU ms in styles::blur are reused measurements under host load, not a clean baseline. Aggregate CPU samples are not elapsed duration. They cannot establish a current speedup or matched regression. The fixture is 4608x3072 (14,155,776 pixels), a gradient fill plus Helvetica 220 text, translated (600,2400), with drop-shadow distance30/size40 and outer-glow size30. Exact fixture is `apps/mac/Sources/Tessera/Document/Filters/FilterSelfTest.swift:316-332`. Its two effects have DIFFERENT blur radii, so intra-effect same-radius memoization alone does not fix this fixture.

Confirmed repeated work:

- Each output-tile compilation calls `TileJob::emit_styles`. `crates/compositor/src/render/effects.rs:79-90` clones the layer, resets props, clones DocState, creates an entirely new `next_doc_key()`, renders a FULL-CANVAS source raster, and calls full-canvas `styles::render`.
- It then samples just the current tile from those whole-image source/effect rasters (`effects.rs:91-103`). `effect_samples` also uses a fresh next_doc_key for every raster extraction (`effects.rs:50-56`), preventing mip/source reuse.
- `source_raster` loops every level-zero source tile (`effects.rs:34-47`). Fresh document namespaces mean repeated root/source caches cannot identify the same isolated source across output tiles.
- 4608x3072 at TILE_SIZE256 has 18x12 = 216 output tiles. Absent existing root-cache hits, a single styled layer can therefore cause 216 full source/style evaluations, not one. This is source-derived work amplification, not a measured count; instrumentation should prove it.
- `render_level_tiles` runs parallel output tiles unless smart filters or a small warm live frame select serial execution (`render/mod.rs:790-824`), so styled exports can have several full-canvas evaluations and buffers alive concurrently. New cache misses must be coordinated before expensive work or a cache will still duplicate the cold evaluation.
- `styles::blur` is ALREADY separable (`styles.rs:608-642`), with exact truncated Gaussian weights, ordered f32 sums and zero outside padded support. Do not replace it with box blur or combine successive Gaussian passes if the requirement is identical pixels.
- Source alpha uses input.pixel for every canvas pixel (`styles.rs:765-770`), and each effect emits a full F32 RGBA Raster (`styles.rs:777-795`). Avoiding 215 repeated invocations removes this repeated work without any new numerical algorithm.

## Smallest recommended correct change

First patch: bounded whole-style-result reuse, leaving numerical blur/morphology/compositing untouched. Cache one immutable `Arc<StyleEntry>` holding source Raster, ordered Vec<StylePlane>, stable runtime source/effect namespace IDs and charged byte count. Replace only the repeated whole-source construction in emit_styles with lookup/compute; keep run_styles pixel arithmetic and effect ordering unchanged.

Implement a frame-local `StylePass`, analogous to existing FilterPass (`smart_filters.rs:346-470`), created for full-level renders containing styles and threaded through DocRef. Pin each successful entry for that pass so cache eviction cannot recreate it for every tile. Use conservative snapshot/layer identity for keys; no disk or process-global cache. A small persistent runtime layer is optional second step for direct tile/preview calls and repeated exports on the SAME Compositor, but must not be necessary to meet single-export throughput. The exporter may create a new compositor, so benchmark cold frame benefit explicitly.

Smallest concurrency choice: serialize top-level output tile traversal when StylePass is active, just as smart-filter passes already do. This guarantees one build per key in a single pass and bounds active expensive work, while allowing nested numerical/library parallelism already present. Nested styled groups require reentrant pass traversal; NEVER hold a global cache mutex while source_raster recursively renders children. If preserving parallel output tiles is necessary, use per-key single-flight state with success/error/cancellation publication, not check-then-build races; this is a larger change and requires concurrency tests. Different calls/pass objects still need a declared concurrency/memory contract.

Use stable per-entry namespaces for source/effect mip reads. Never reuse a synthetic DocRef key with different layer content. For a minimal first patch, caching whole entries while leaving fresh effect_samples IDs is numerically safe and still avoids whole-image repeated blur; stable mip identities can be added only with a test proving level>0 reuse.

### Exact invalidation contract

Frame-local keys: `(original doc.key, snapshot state.rev, layer.id)` plus explicit context generation if styles can see mutable external font/filter providers during the same call. Canvas/depth/light/style/source are immutable within the pinned DocState, so key lifetime ends with the pass. If persistent reuse is added, include canvas dimensions/depth and renderer context generation or clear on provider changes, use state.rev conservatively, and retain stable Arc snapshot identity where public arbitrary DocState construction could reuse revision numbers. Caching by `layer.props_rev` alone is WRONG: source pixel edits, masks, children, smart filters, transforms and global light can change results without that revision.

A finer per-layer key is a later optimization: full-canvas maximum dependency stamp (all source tiles, nested children/smart-object state, props/content revisions), global-light values, canvas/depth and provider generation. `Layer::stamp` is TILE-LOCAL (`document.rs:534-547`), so reading stamp(0,0,0) is insufficient. Hashing only source RGB/alpha is also insufficient for effect settings. Conservative state.rev causes harmless over-invalidation on unrelated edits but is simplest and correct under normal immutable Document mutation APIs.

Test and preserve: paint on distant tile; raster/vector mask edits; live geometry/transform/font-provider changes; smart-object child edit; group child style edit; effect amount/order/enable/size/scale/light; canvas resize/depth change; undo/redo; two documents with same layer IDs/revisions. `Compositor::clear` must drop style runtime state; `clear_composites` should drop style entries as they are derived source composites. Every cache epoch/context reset must invalidate style entries. Cancellation/error must not publish partial planes and must release reservations.

### Explicit bound

Recommended first bound: per StylePass **1 GiB retained payload and 256 entries**, including in-progress reservations, mirroring existing FilterPass defaults. Charge BEFORE rendering source/effects with checked arithmetic: F32 planar full-canvas bytes = `16 * width * height * (1 + output_plane_count)` plus tile metadata/allocated padding where applicable. Count Bevel as 2 planes for Inner/Outer, 4 for Emboss/Pillow; other enabled effects one; disabled effects zero. Include Raster tile metadata/map overhead separately in accounting or clearly label bound as payload only. Reserve full predicted charge before allocating and reconcile measured retained bytes at publication. No saturating overflow that admits an entry incorrectly.

Reported two-effect fixture retains source+2planes = 679,477,248 bytes = 648 MiB payload, within 1 GiB. Padded alpha is (4608+84)*(3072+84)*4 = 59,231,808 bytes (checked arithmetic required; pad = ceil(max support40)+2 =42), about 56.5 MiB. Blur/morphology scratch is temporary and must be reported separately: the pass retained cap DOES NOT bound scratch, root/mip caches, output Vec/Tiles, other compositors, GPU or RSS. Existing styles MAX_PIXELS=16,777,216 bounds each scalar mask at 64 MiB, but up to 64 effects can emit many RGBA planes. A retained cap must refuse/reserve oversized cases before work, not compute then discard and repeat 216 times.

Resource policy needs coordinator review: explicit ResourceExhausted on over-budget styles is simplest and parallels FilterPass, but is a behavior limitation for previously valid multi-style documents. If all formerly valid exports must remain accepted, fallback to existing uncached serial rendering for oversized entries keeps pixels/availability and avoids simultaneous full-style builds, though no speedup and transient allocation remains high. Streaming by effect or bounded disk spill is a separate, larger design. Do not claim strict whole-process memory bound from this cache.

A frame-local pass can release all entries at call completion; no long-lived LRU required. If a persistent cache is added, share Arc payload ownership with pass and charge pinned bytes until last consumer drops; eviction from a map alone does not free memory. Never independently multiply a 1 GiB allowance per layer or per output tile. Multiple concurrent passes multiply per-pass allowance; either document this scope or add runtime-wide reservations, with recursion-safe behavior.

## Optional subsequent intra-style reuse

Only after first measurements: a render-local field memo keyed by alpha identity plus exact operation sequence `(morphology radius bits, dilate/erode, blur radius bits)` can reuse fields between equal settings or repeated effects. Shadows/glows share this pipeline (`styles.rs:803,826`); satin blur and first bevel blur may share when input/radius EXACTLY match (`styles.rs:880-901`). Bound this temporary cache (e.g. two scalar masks, at most128 MiB at MAX_PIXELS) and evict on insertion. No reuse between dilation and erosion, no blur-radius rounding, no collapsing blur(blur(a,r1),r2), no geometry cache keyed on effect color alone. Not required for the observed size40/30 fixture.

## RED tests and golden oracle

1. Small multi-tile synthetic RGBA input (e.g. 513x259) with nonuniform fractional alpha, holes and edges, shadow+glow. Instrument whole-style-source/style-render evaluations. RED: one full render should evaluate each styled layer once; baseline does it per tile. Assert exact count independently of wall timing.
2. Keep an explicitly uncached reference helper using baseline algorithms. Compare cache-enabled and uncached interleaved f32 output using `to_bits` for all channels, not an average-error metric. Golden fixture values/hash captured on base before refactor plus analytical impulse test protect against both paths sharing a changed blur bug. Existing analytical Gaussian impulse oracle is `styles.rs:outer_glow_gaussian_matches_impulse_kernel`; existing integration tests are `tests/layer_styles.rs`, `style_psd.rs`, `live_style_damage.rs`.
3. Cover U8/U16/F32 final conversions; level0 and level1/2; fractional radius/spread and scale; padding-edge shifted shadows; repeated effects and tie order; inside/outside stroke and all bevel kinds; satin; fill opacity0; layer opacity, BlendIf, knockout and masks. Compare exact old output, preserving reference's known non-Adobe approximation.
4. Invalidation cases listed above, each compared against a fresh uncached compositor. Assert a warm hit does not hide content changed in another tile, other document, or global light. Roundtrip and undo tests already exist; extend rather than replacing their expected values.
5. Tiny configured byte/entry caps: exact-fit accepted, one byte below rejected or documented fallback; overflow; disabled effects; nested styled groups; multiple entries; errors/cancellation release reservations; retained bytes return to zero on pass drop. If parallel single-flight, N waiters must cause exactly one build, and cancellation/failure must not deadlock or poison future success.
