## Findings

### No source blocker found in StylePass reservation/RAII accounting

`crates/compositor/src/render/style_pass.rs:33-45, 61-109` keeps entries, reserved+retained bytes, and reserved+retained count under a short `Mutex`. `get_or_build` does lookup then releases that lock; `reserve` returns an RAII guard; the `build` closure executes outside the lock. Nested calls can therefore reserve/use the same pass without self-deadlock. `Reservation::publish` reconciles actual bytes under the lock, changes the reservation charge to actual only if within limit, inserts the entry, and clears `active`; every early return leaves `active=true`, so Drop releases the original reservation. Build `Err` and post-build cancellation use `?` and also drop the guard. The tests in `style_pass.rs:207-309` cover reserved-byte/count accounting, overflow, build error, cancellation during build/final check, uncached fallback, nested closure lock release, actual-capacity refusal, exact fit, and cache reuse. This is source-plausible, not executed evidence.

### Estimate and actual-capacity claims are narrowly, accurately bounded

`predicted_bytes` at `style_pass.rs:152-181` reserves `canvas_width * canvas_height * 16 * (one source + enabled planes)` using checked arithmetic; the Bevel variants reserve 2 planes for Inner/Outer and 4 for Emboss/Pillow. `styles::render` emits one RGBA F32 raster per active non-bevel effect and two/four for those Bevel kinds (`crates/compositor/src/render/styles.rs:777-795, 800-900`), which matches this estimate for its known cases. The source is four-channel F32 (`effects.rs:81-95`); effect planes are also four-channel F32. `Entry::bytes` sums allocated sample-buffer capacity over all retained raster slots with checked addition (`style_pass.rs:21-30`), and `Tile::allocated_byte_len` includes Vec capacity (`engine-api/src/tile.rs:541-550`). `publish` refuses retention when actual retained capacity exceeds the global pass limit (`style_pass.rs:120-139`). Thus the pass enforces limits on admitted estimated payload plus retained actual payload, and refuses over-estimate results; it does **not** establish a hard bound on simultaneous transient capacity, style scratch/padded alpha, Vec/Arc metadata, allocator overhead, output, or all process memory. The handoff explicitly states these exclusions. Do not describe 1 GiB as an RSS or all-in-flight-allocation cap.

### Precise per-pass and mip namespaces appear sound

`StylePass::Key` is `(DocRef.key, state.rev, layer.id)` (`style_pass.rs:10, 61-68, 95-115`). `Document.key` is a process-unique runtime namespace (`edit.rs:1393-1413, 1487-1509`; allocator at `geom.rs:205-208`); child smart objects also carry process-unique keys (`document.rs:361-383`). State revision distinguishes snapshots and layer ID distinguishes layers within a namespace. Isolated style-source builds use a fresh source `DocRef.key` (`effects.rs:81-94`); retained source sample mips and each output plane receive distinct fresh `source_key`/`plane_keys` (`effects.rs:100-106`). Those namespaces are passed to `raster_level` with node 0, so different retained rasters do not collide in `(doc,node,part,stamp,coord)` mip-cache keys (`render/mod.rs:245-269`). The pass is per full-level render, so no cross-frame invalidation or persistent style-key lifetime is implied.

### Serial recursion and cache lifetime caveat

`render_level_premultiplied` creates one local pass for a tree with styles (`render/mod.rs:798-815`); recursively style-bearing documents are detected by `DocState::has_layer_styles`, including nested groups/smart objects (`document.rs:633-645`), and `styled` forces serial output-tile traversal (`render/mod.rs:823-849`). This supports the stated no-concurrent-duplicate-producer invariant. `style_entry` propagates the pass through nested source rendering only when its parent was admitted; declined parents pass `None` for the entire fallback subtree (`effects.rs:77-94`).

One memory-lifetime caveat is not a violation of the documented StylePass limit but matters for interpreting “uncached fallback”: building a style source calls `source_raster` with a fresh namespace, whose recursive `composite_premult` inserts tiles into the compositor's persistent `RenderCache` (`effects.rs:88-94`; `render/mod.rs:583-609`). Mip reads at level >0 are also cached there under the fresh source/plane keys (`render/mod.rs:257-322`). These entries outlive the local `StylePass` and survive until ordinary RenderCache eviction/clear; byte accounting in `StylePass::Entry::bytes` covers only the retained Raster objects, not these persistent cache duplicates/mips. The compositor cache has its separate cache budget (`render/mod.rs:124-147`), and the handoff explicitly excludes compositor caches, so this is bounded by another subsystem, not unbounded leakage. Still, “overbudget ... falls back to serial uncached rendering” should be read as **uncached by StylePass**; if it is intended to mean no persistent compositor cache retention, current code does not meet that stronger meaning. The cache can accumulate entries under new ephemeral keys until eviction, consuming the separate cache budget.
