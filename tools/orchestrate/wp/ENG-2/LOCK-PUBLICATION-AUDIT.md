Read-only source inspection, no repository changes or runtime/build/test/GUI activity. No AGENTS.md found in repository tree or ancestor locations. ## Findings that constrain the design

1. **The normal viewport render already releases the document mutex before rendering.** `document/render.rs:1011-1035` snapshots `live_shared`, viewport, epoch, ring generation and surface, then explicitly drops the guard. Filter preparation (`1063-1064`), backend acquisition (`1067`), CPU compositing (`1119`, `1128`), GPU presentation/wait (`1108-1114`) happen afterwards. Final ring validation uses a separate short reacquisition (`1141-1158`). Do not claim that the existing normal viewport holds `Shared::state` throughout GPU rendering. The brief's observed stalls may be from a different path or older baseline; establish the runtime cause during the exclusive handoff.
2. **A single committed DocState pointer is insufficient for current getter contracts.** `document.rs:815-842` combines committed document/history, scratch, pending edits, saved node/path/title, selected layers, epoch, tool/advanced state and viewport. `live()` deliberately selects scratch (`845-853`); `layers()` promises live drag state (`1396-1408`); `info()` combines live pixels with committed history, pending flags, metadata and selection (`1350-1393`). Publish committed and live pointers plus coherent metadata together; do not return mixed generations.
3. **Export Flat currently captures live scratch, without committing it.** `document.rs:2208-2226` promises what the document shows and clones `st.live().state()`. Switching this to committed-only silently changes exports during an interactive edit. In contrast, rasterized PSD copy intentionally takes `st.doc.state()` in its worker (`document/psd_copy.rs:228-240`). The new publication should expose both choices, preserving each caller's contract. Confirm-time means the short publication read is the capture point; host work queued before that read can still change the captured state.
4. **There are actual long document-lock holders.** `info()` can scan selection pixels under the lock (`document.rs:1352-1359`). Smart-filter mutation validates full-resolution or level-aware pixels while holding `State` (`document/filters.rs:3091-3145`). Stroke rasterization occurs while holding it (`document/tools.rs:1446-1498`). Merge/flatten construct operations under the lock (`document.rs:1778-1793`). Test-only `read_presented_level` holds it while synchronously reading the render backend (`document/filters.rs:4092-4096`), unlike already-correct `read_level` (`document.rs:2403-2405`). Merely renaming the current mutex or swapping it for RwLock cannot make getters independent.

## Existing ordering and ownership

- Registry entries are weak; the session owns shared state and its worker; renderer worker owns an Arc<Shared> (`document.rs:530-543,868-902,1105-1114`). Duplicate opens recheck under registry lock, then shut down the redundant session after dropping that lock (`582-610`). Initialize publication before spawning/registering a session.
- CowDoc wraps `Arc<Document>`, with `Arc::make_mut` on mutation (`780-811`). Retaining `Arc<DocState>` is cheap and sufficient for export pixel ownership. Retaining an extra permanent `Arc<Document>` for a publication would force document/history COW on every subsequent edit; avoid introducing that hidden cost merely for getters.
- Writers serialize under State. Ordinary edit commits pending work, then applies the requested op, then `update` increments epoch and schedules render (`1135-1198`). Keyed interaction applies scratch while dragging and folds the final value into a history node (`1203-1236`). History moves commit a drag before undo/redo/checkout (`1257-1266`; wrappers `1917-1923,1945-1949,1980-1984`). Preserve this writer sequencing.
- `DocState.rev`, history node and session epoch are different concepts. History may revisit old states; scratch/metadata can change without a new history node. `update` always increments epoch (`1164`), but metadata setters and saved-node updates do not. Never use only state revision or epoch to decide whether a publication needs refresh.
- Saves serialize with `Shared::saving`; they commit pending edits and capture `(Arc<Document>, history node)` under State, write outside it, then mark that captured node saved (`2156-2166,2338-2340,2373-2393`). This correctly keeps later edits dirty. Save As changes path/title only after a successful result and updates the registry after dropping State (`2341-2361`). Preserve ordering and outcome handling; publishing current history as saved after I/O would lose later edits.

## Minimal architecture recommendation

Keep the current State mutex as the **writer serialization gate**, and add a separate `Mutex<Arc<PublishedDocument>>` (or appropriate atomic Arc swap). `PublishedDocument` contains committed `Arc<DocState>`, live `Arc<DocState>`, closed flag, epoch, and an immutable coherent projection of the session metadata needed by getters (path/title/source, dirty/history head/undo-redo availability, selected ids, unlinked-mask state; cached history/snapshot records and tool status as demanded by the consumer audit).

Prepare the new projection while writer serialization is held, outside the publication mutex. Replace the Arc under the publication mutex, release that mutex immediately, then drop the old Arc **outside** it. Destruction of old trees/history/pixel buffers must not happen inside the short critical section. Readers clone the Arc and immediately release the publication mutex; selection scans, record conversions, traversal, thumbnail preparation, callbacks, render/filter work and I/O must happen after release. Precompute/cache selection bounds by selection-raster identity off the publication mutex; otherwise `info()` may be render-independent but still fail the microsecond goal for its own work.

Publish before releasing writer serialization so two writers cannot install snapshots out of order. Publish before public mutation returns and before corresponding callbacks can be observed. Readers never acquire State/backend/filter/save locks while holding the publication lock. Use one ordered publication object rather than independent atomics for state/closed/epoch, to avoid torn snapshots. Preserve existing render pipeline and cache identity for the minimal change; do not replace its stable Arc<Document> with freshly `Document::new` reconstructed objects on every frame (thumbnail/cache behavior explicitly relies on document identity, `document/render.rs:1328-1339`). Render may clone the new publication when useful, but must not hold its guard while acquiring any other lock.

**Do not place the only publish call in `update()`.** Either introduce a carefully scoped mutation guard that refreshes publication on all exits, or explicitly route every mutation through a transaction helper that publishes actual resulting state on success AND on failure that changed state. A generic read guard publishing on every drop is undesirable: it serializes readers back through writer state and may rebuild large metadata. A custom mutation guard must support internal `&mut State` reborrows and avoid fallible/panicking work in Drop; explicit transaction finalization is easier to reason about. Pre-existing partial-commit behavior should be preserved or deliberately repaired with dedicated tests, never silently hidden by stale publication.

| Path | Source | Publication obligation |
|---|---|---|
| Open/new/adopt | `document.rs:1068-1114,2458+` | Publish initial committed/live/metadata before availability. |
| Ordinary/keyed/source edits | `document.rs:1189-1236,1289-1341` | Publish committed and scratch together after actual mutation. |
| Commit/history move | `document.rs:1257-1266,1842-1852` | Preserve pending-first ordering and history metadata. |
| Named snapshot/history pruning | `document.rs:1953-1965,1989-1991` | Bypass `update`; publish snapshot/history projection even when pixels do not change. |
| Selection/mask linkage | `document.rs:1419-1426,1760-1771` | Publish metadata even without epoch increment. |
| Source preview cancel | `document.rs:1861-1889` | Drops/rebuilds scratch, may discard invalid remaining ops; publish actual live result. |
| Stroke preview/finish/cancel | `document/tools.rs:1444-1555` | `stroke_points` increments epoch and requests directly; finish clears scratch before fallible apply. |
| Transform preview/cancel/apply | `document/tools.rs:2010-2038,2168-2218`; `document/transform.rs:945-977,982+,1130-1159` | Preview may bypass update; apply error can restore advanced state but leave scratch cleared. |
| Filter/retouch checked apply | `document/filters.rs:3030-3046,3091-3109`; `document/retouch.rs:1401-1412` | Pending commit happens BEFORE stale revision/cancel/error check; publication cannot remain at pre-commit history on Err. |
| Save/save-as completion | `document.rs:2341-2351,2378-2392` | Pending commit is observable even if I/O fails or destination exists; saved node/path/title only change on successful outcome. |
| Close/shutdown | `document.rs:1118-1130,2239-2243` | Publish closed consistently with writer gate; no new export admissions after it, existing export Arc survives by current contract. |

`commit_pending` itself consumes pending and drops scratch before fallible `apply` (`document.rs:1140-1150`); therefore even an unsuccessful call can alter the live view. `edit` can successfully commit a drag and then fail the second apply (`1193-1194`). A success-only publisher causes permanently stale history/live/dirty data. This is the highest-risk correctness trap in a small patch.

## Deadlock and race constraints

- Lock order should remain writer State -> short publication; publication readers must release before any State/render/filter acquisition. Never introduce publication -> writer or publication -> backend while a writer might publish.
- Keep callback execution after all publication/writer locks are released. Existing history callback deliberately drops State (`document/render.rs:910-913`). A callback may synchronously query or edit the session.
- Preserve final surface generation/membership/cancellation checks (`document/render.rs:1136-1158`) and renderer's final ownership gate; document snapshot publication does not replace frame validity checks. Superseded epoch is not equivalent to obsolete ring generation.
- Close and snapshot need one linearization point. Read a coherent published closed+state snapshot, and allow a captured export to continue if close linearizes afterwards, consistent with `begin_export_flat` documentation (`2213`). Do not separately read an atomic closed flag and a pointer without an explicit protocol.
- Cancellation/revision validation must still happen under writer serialization just before applying a computed result (`filters.rs:3034-3044`, `retouch.rs:1405-1410`); reading the publication is not permission to commit a stale calculation.
- Saves retain the saving gate across snapshot/write/post-save metadata update. Do not hold publication over filesystem work or acquire saving from a publication getter.
- Permanent live DocState snapshots preserve COW pixel data; large numbers of export handles can retain old pixels, as current exports already do. Avoid an extra unbounded publication history.

## Verification when runtime handoff is granted

Use deterministic barriers that hold an actual render/backend operation in flight and require every in-scope session getter plus begin_export_flat to complete while that barrier remains held. Include held writer/filter-validation paths to prove independence from writer latency; a no-contention latency benchmark alone does not prove it. Capture export A at confirm, commit B, run A and compare against A; include pending scratch then cancel/commit, undo/redo/checkout, save success/failure/destination conflict with concurrent edit, closed admission, and partial-commit error paths. Test correctness with barriers, not flaky microsecond deadlines; measure microsecond latency separately under release builds. No tests or measurements were executed in this audit.
