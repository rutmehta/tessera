# WP M2-52 — AI Denoise that works on a normal install

Problem (from M2-51): AI Denoise uses our self-trained CFA network (`enhance/cfa-unet-fp32/fp16` in crates/ml-runtime/models.toml) whose entries are `local_path` artifacts under tools/orchestrate/wp/M3-16/artifacts that do not exist on user machines, so `ModelDownloads.request` fails and the panel shows "Failed" on every normal install. Read crates/ml-runtime/models.toml, crates/ml-runtime (registry, ModelDownloads from M2-49), crates/ml-enhance (DRUNet colour denoiser `enhance/drunet-color`, MIT, downloadable from Hugging Face at a pinned revision; CFA denoise path; README), crates/image-core (denoise stage, stage memoisation, CFA denoise adapter from M2-49), crates/pipeline-gpu (resident CFA denoise handoff), crates/export (denoise hooks), crates/engine-api/src/recipe/settings.rs (DenoiseSettings: method, amount, model ref).
Deliver:
1. A model-resolution policy: AI Denoise prefers the CFA network when its weights are present in the model cache (or a local artifact resolves); otherwise it uses **DRUNet colour** on the demosaiced scene-linear image at the equivalent pipeline point (convert to the model's expected encoding and back; noise level from the M2-49 automatic noise estimate mapped to DRUNet's sigma input; amount blends), in both the interactive render (resident or CPU, whichever is supported — document) and export. Recipes record which model ran (existing model ref field) so re-renders are stable; changing availability later does not silently change an existing edit's look without a documented rule.
2. `ModelDownloads` for AI Denoise requests `enhance/drunet-color` when the CFA artifact is not available, so the app's download flow succeeds on a clean install. The CFA entries become optional "local research" entries that never cause a user-facing failure.
3. Tests: resolution policy (CFA present / absent), DRUNet path on fixtures/raw renders non-black with lower noise in flat patches vs. no denoise (skip cleanly without weights; if weights are downloadable in this environment, fetch them once into the test cache and run for real), recipe model ref persistence, export parity with the interactive path at L2 within tolerance.
