# WP M2-01 — Lightroom Classic catalog importer (`import-lrcat`)

Read docs/05 §3 (tables and translation rules), docs/06 §2.1 (selection mapping), and crates/engine-api/CONTRACTS.md (recipe, crs, selection). Implement `crates/import-lrcat` (already a workspace member, currently a stub):
- Open a `.lrcat` read-only (`rusqlite`, `?mode=ro`, copy to temp first if `-wal`/`-lock` files exist, never write). Detect catalog schema version from `Adobe_variablesTable`.
- Read: roots/folders/files (`AgLibraryRootFolder/Folder/File`), images + virtual copies (`Adobe_images`: masterImage, copyName, orientation, captureTime, pick, rating, colorLabels), develop settings XMP text (`Adobe_imageDevelopSettings.text` + processVersion), history/snapshots, keywords with hierarchy and synonyms, collections (regular/smart/sets via `creationId`; smart rules as serialized Lua in `AgLibraryCollectionContent`), stacks, face regions/people names, GPS from `AgHarvestedExifMetadata`.
- Produce an `ImportPlan` in memory: for every image a `(path, Recipe, Selection, keywords, collections)` where `Recipe.settings` is filled by parsing the crs: XMP text through the `CrsKey` table (write a small XMP-text parser for the `crs:` attribute style Lightroom uses; unknown keys collected in a report), `process_version` mapped from Adobe PV, and `Selection` mapped per docs/06 §2.1 (pick=-1 → Reject, pick=1 or 1★ → Keep, 2★→grade1, 3–4★→2, 5★→3, colour label → mark name).
- Smart-collection rules: parse the Lua table syntax (`{ criteria = "rating", operation = ">=", value = 3 }` style with and/or/none combine) into a `SavedSearch` AST (define it here; it will move to the search crate later).
- `library.json` writer: albums, album groups, smart albums, keyword tree, people names, per docs/05 §2 (define a serde struct `Library`).
- Fixture: no real catalog is available, so write `tests/make_fixture.rs` support that **creates a synthetic .lrcat** with the real table/column names above (minimal schema) containing 3 images (one virtual copy), 2 folders, keywords with hierarchy, one regular and one smart collection, ratings/picks/labels, and PV6 develop XMP text with Exposure2012=+0.5, Contrast2012=10, a ToneCurvePV2012 and a MaskGroupBasedCorrections block. Tests assert the plan (paths, selections, recipe values, keyword tree, smart rule AST, virtual copy naming). Also a test that a catalog with unknown extra columns still imports, and that a missing table yields a clear `EngineError`.
- CLI hook: expose `import_lrcat::inspect(path) -> Summary` (counts) for `tessera-cli` later.
`cargo test -p import-lrcat --release`, clippy -D warnings, fmt. Do not modify engine-api.
