# LR-2 Adobe primary-source schema research

Date: 2026-10-01. Scope: focused search for public Adobe documentation of `ConvertToGrayscale`, `GrayMixer{Red,Orange,Yellow,Green,Aqua,Blue,Purple,Magenta}`, PV2010 applicability, `AutoToneDigest*`, and `DepthMapInfo`. This reports documented UI semantics separately from absent serialized-value schemas. The research pass inspected no private catalog and edited no repository files. This report is subsequently preserved as documentation only; UI-level evidence does not authorize translation implementation.

## Evidence found

- Adobe Help describes B&W conversion and per-color mixing of the resulting gray tones; an automatic mix is available. This documents UI behavior, not the `ConvertToGrayscale`/`GrayMixer*` serialized key types, ranges, eight-channel formula, or activation rules. Nonzero mixer values alone do not establish that grayscale mode is enabled. [Adobe Help, Work in grayscale](https://helpx.adobe.com/ie/lightroom-classic/desktop/process-and-develop-photos/image-tone-color.html), retrieved lines 690–706.
- Adobe documents Process Version as the Camera Raw technology used to adjust/render, and states available options/settings depend on process version. PV2012 has the listed modern tone controls; PV2010 was Lightroom 3’s default and is described as improving sharpening/noise reduction over PV2003. Adobe also explicitly warns updating to PV2012 may cause significant visual changes. [Adobe Help, Process versions](https://helpx.adobe.com/uk/lightroom-classic/desktop/process-and-develop-photos/develop-module-options.html), lines 307–360.
- Adobe Help explicitly tags tone controls by applicability: Exposure and Contrast are “(All)”; legacy Blacks, Recovery, Fill Light, Brightness are “(PV2010 and PV2003)”; Highlights/Shadows/Whites/Blacks are “(PV2012)”. PV2010 Brightness mainly affects midtones, with sequencing advice after Exposure/Recovery/Blacks. No numeric migration formula is specified. [Adobe Help, tone controls](https://helpx.adobe.com/ie/lightroom-classic/desktop/process-and-develop-photos/image-tone-color.html), lines 507–553. Thus test the version/applicability distinction and do not alias legacy values to modern controls absent algorithm/golden evidence.
- Adobe documents Auto Tone and Auto Black & White Mix as user-selectable Develop preset settings, and documents automatic mix on first grayscale conversion. It does not describe serialized `AutoToneDigest` or `AutoToneDigestNoSat`, their types/domains, or whether either is a render input. [Adobe Help, removed preferences/workaround](https://helpx.adobe.com/lightroom-classic/desktop/kb/apply-auto-tone-mix-converting-black-white-preferences-removed.html), lines 307–323.
- Adobe’s Lens Blur help says Lens Blur creates a depth map using Adobe Sensei, can visualize/refine it, and supports device depth from images such as HEIC. Its depth-range-mask help says depth-range masking is available only where embedded depth-map data exists. These are feature-level facts; they do not establish that a serialized `DepthMapInfo` key has this content, whether it is a resource, metadata, mask input, or active render directive. [Adobe Help, Lens Blur](https://helpx.adobe.com/lightroom-classic/desktop/process-and-develop-photos/lens-blur.html), lines 318–368; [Adobe Help, Depth Range Mask](https://helpx.adobe.com/uk/lightroom-classic/desktop/process-and-develop-photos/apply-local-adjustments.html).

## Schema gaps and safe test implications

The searched public Adobe developer/API pages expose Lightroom asset workflows and external XMP Develop settings as RDF/XML, but no schema for these Develop properties. The Classic SDK landing page describes Lua plug-in capabilities but does not publish the requested key schemas. No authoritative Adobe documentation found for the value grammar/type/domain of any exact key in scope (`ConvertToGrayscale`, eight `GrayMixer*`, `AutoToneDigest*`, `DepthMapInfo`), nor an activation condition connecting the mixer to a B&W mode. This is a documentation gap, not evidence these keys are unsupported by Adobe Lightroom.

On current source-plan evidence, the importer recognizes these Lua key names but the recipe codec lacks mappings and there is no grayscale recipe stage. Proposed RED tests may safely establish recognition, exact raw retention, unsupported diagnostics, and no accidental recipe/render translation. Do not claim an Adobe-equivalent grayscale output oracle yet. Once key schema is evidenced, use synthetic color patches to separately test the activation flag and each of eight independently varying mixer values; use PV2010/PV2012 paired fixtures for legacy-vs-current tone routing. Keep `AutoToneDigest*` and `DepthMapInfo` retention-only until Adobe documents type/meaning or a supported implementation sample is obtained. Absence/default/present values should be distinguished from active settings.
