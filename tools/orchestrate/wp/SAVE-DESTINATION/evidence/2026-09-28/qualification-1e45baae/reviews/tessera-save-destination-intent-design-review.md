Reviewed `f426c9de:tools/orchestrate/wp/B5-16/SAVE-DESTINATION-INTENT-DESIGN.md` against current native `document.rs`, `document/io.rs`, `compositor/format.rs`, and the pinned `tempfile 3.27.0` implementation. ## Verdict

The additive `CreateIfAbsent` / `ReplaceConfirmed` intent and typed `Saved` / `DestinationExists` result are appropriate for the narrowed bug. Legacy `save_as(path)` and ordinary `save()` remain replacing; actual confirmed Replace remains path-authorized, with no invented identity-CAS requirement. The UI must latch CreateIfAbsent when Save was chosen and ReplaceConfirmed only after the exact Replace invocation completes and drains. The design correctly treats collision as a typed non-success, not a message parsed from `BridgeError`. It also correctly preserves the actual admitted writer outcome through cancellation.

Two implementation-plan corrections merit action before product code:

1. **Prefer the pinned `NamedTempFile::persist_noclobber` for CreateIfAbsent over hard-link-only publication** (`SAVE-DESTINATION-INTENT-DESIGN.md:129-151`). The pinned Unix code tries an atomic `renameat_with(..., NOREPLACE)` first and falls back to hard-link creation only if the rename form is unavailable. Hard-link-only would reject a filesystem that supports exclusive rename but does not support hard links, a compatibility loss unrelated to the reported overwrite bug. The fallback's ignored staging-name unlink error is real but is a **cleanup-observability limit after successful publication**, not a no-clobber safety failure. Capture the staging path before commit if useful for a read-only diagnostic; do not convert a committed save to DestinationExists/generic failure because a leftover temp is seen, and do not unlink a path later without proof that it still names the owned stage. Normal local-filesystem tests should check no residue, while unsupported-filesystem behavior remains a documented limit. If A chooses hard-link-only despite this, make the narrower filesystem contract explicit rather than calling it a safety necessity.
2. **Acquire the StubDocumentBackend save gate before resolving `save()`'s current path** (`design:170-176`). The current stub reads `path` under its model lock and then calls `saveAs(path:)` (`StubDocumentBackend.swift:904-910`). If the proposed `save()` keeps that read outside the new save gate, a concurrent checked/legacy Save As can change the path before `save()` enters the gate, and the latter may write the old destination. Match native `DocumentSession::save` (`document.rs:2095-2107`): gate first, read current path/snapshot under the model lock, then call a private common writer that does not reacquire the gate. A tiny held-gate path-change control belongs in the later B Stub tests.

## Native-first patch scope

The smallest independent A slice is `crates/tessera-ffi/src/document/io.rs` plus `crates/tessera-ffi/src/document.rs` and focused Rust tests; leave B-owned Swift/Document files and generated bindings to the coordinated follow-up. Use a private `CommitMode { Replace, CreateIfAbsent }` and a unique same-parent `NamedTempFile` for **both** `compositor::format::to_bytes` native output and PSD/PSB bytes. This removes the fixed `*.tessera-doc.tmp` collision for DocumentSession writes without changing the public compositor formatter or PSD-copy cancellation transaction. Pre-commit write/sync failures remain errors. Classify `DestinationExists` only from the atomic no-clobber publication's `EEXIST`/`AlreadyExists`, never from a later `exists` check or localized error text; other I/O errors remain errors. A stage that fails before publication must be cleaned by its owned temp guard.

`DocumentSession::save_as_checked(path,intent)` can be added additively with the two UniFFI enums (the same derive style already exists in `document.rs`), while legacy `save_as`/`save` route through Replace mode. Hold `Shared::saving` across the snapshot/commit/path update as today. On DestinationExists, do not advance `saved_node`, path/title, or engine path registry; pending edit commitment into the snapshot may already have happened, as the design states. After publication, a staging cleanup diagnostic must not be surfaced as an outcome implying untouched destination; record the captured history node and update the session using the established sequence. Existing post-publication model-lock/close errors can still leave file and session markers out of sync; this bounded slice should document that residual instead of misclassifying it as a destination collision.

Meaningful first Rust gates: a per-call held commit after sync where a sentinel appears for each of native/PSD/PSB; two independent sessions racing the same initially absent path (one Saved, one DestinationExists, valid winning file, distinct stage names); existing file, dangling symlink and directory controls; ordinary/confirmed Replace after external path change; precommit I/O failure vs postcommit cleanup distinction; and path/title/saved-node/registry controls. Keep tests tiny and deterministic, with direct exit and source freeze. Test `persist_noclobber` on the target macOS filesystem, including actual errno mapping. Later B/Swift gates must test the typed mapping, Stub implementation, exact UI intent latch and native drain; the standalone AppKit probe does not substitute for those product gates.

The source design appropriately excludes ordinary `compositor::format::save` callers, PSD-copy `write_copy_atomic`, direct legacy `DocumentWorkspace.write`, and full presenter acceptance. Do not claim the fixed temp collision is removed for **all** compositor callers if only DocumentSession is migrated.
