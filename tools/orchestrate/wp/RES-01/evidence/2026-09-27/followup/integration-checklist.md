1. Run the eight-case extra gate and bounded CPU compositor/strict checks after compiler handoff. Preserve exact source/log/exit manifest; commit the two tests only after they pass. Keep GPU and large stress separate.
2. Integrate only after the resource branch gate is green and reviewer accepts the changed CPU scheduling behavior. The detector recursively sees enabled smart filters even on hidden/offscreen layers, so such a frame can be serialized without evaluating those layers. Normal tile reachability remains unchanged.
3. The pass is call-local and retains `Arc<Cached>` unmasked results under an explicit 1 GiB/256-entry per-pass allowance independent of the persistent cache budget. `ResourceExhausted` is a new explicit behavior for a reached source that exceeds that allowance; no partial output frame is published. Direct tiles, two concurrent frame calls, GPU/resident work, evaluator allocations, transform intermediates, tile output and overall host memory are not globally bounded. Do not claim the Machine B swap cause is established or closed.
4. The cancellation branch currently changes `transform::TransformOp::apply_with_cancel` and `seam::apply_with_cancel`, with `transform::Error::Cancelled`, but does not bridge a caller token into the compositor. After merging source branches, extend the resource branch's `DocRef { state, key, pass }` with the caller token, preserving pass propagation at every constructor. Pass the same token through `render_tile_premultiplied_in_pass`, `render_live_scene`, `source_raster`, `smart_tile`, `emit_styles`, and `filtered_source`; check before source tiles and stages. Map `transform::Error::Cancelled` to `EngineError::Cancelled`, while keeping invalid transform errors distinct. Do not create a new token inside a method that received one. Keep the public direct tile API source-compatible and pass-free unless using a new explicit cancellable variant.
5. `SmartFilterEvaluator` remains a third-party extension point. A default `evaluate_with_cancel` can check before/after legacy `evaluate`, but mid-algorithm cancellation for the filters adapter requires forwarding the real token into its algorithms; a new one-time `AtomicBool` snapshot does not do that. `prepare()` and public-image validation scans in transform also remain late-cancellation boundaries.
6. Existing `FilterEvaluationStats` count attempted stacks/stages, persistent-cache duplicate publication, oversized accepted stacks, and active/peak stack attempts. They are relaxed, non-transactional work counters. A requested true working-memory counter requires separate scoped instrumentation of pass-reserved/retained bytes and measured transient allocations; this branch does not provide total working-set telemetry.
