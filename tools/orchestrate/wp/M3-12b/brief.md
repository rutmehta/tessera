# WP M3-12b — Tethered capture UI (Opus)

Read docs/01 §2.21, docs/06 §3 (tethered/ingest culling), crates/tether (backend trait, ImageCaptureCore backend, fake backend, live queue), crates/tessera-ffi/src/tether.rs, apps/mac (DESIGN.md/Components, Cull views, status strip, Identifiers appendix).
App: **File ▸ Tethered Capture…** opens a non-modal Tether panel (sheet-less, docked at the top of the grid area or as a separate window): device list with connect/disconnect and battery/storage if available, session folder + naming template (live example), capture button (⌘⇧T) and interval timer, a live "incoming" strip of the latest frames with focus/eyes badges as scores arrive, auto-advance option so the newest frame opens in the loupe, per-frame decisions with the usual keys, and a "session" smart album auto-created and scoped. Errors (no camera, permission) shown inline. Uses the fake backend behind `--fake-tether <folder>` (drops files from a folder on a timer) for tests and the acceptance section; ACCEPTANCE section with identifiers.
Tests: Swift for the incoming-strip model and naming template; Rust FFI tests with the fake backend. `cargo test -p tessera-ffi -p tether --release`, clippy, fmt, `(cd apps/mac && ./build-ffi.sh && swift build && swift test -c release -Xswiftc -enable-testing)`. Theme/Components only; --app-dir for app runs; engine-api unchanged; do not touch crates/compositor, crates/agent, crates/tessera-mcp, image-core, pipeline-*.
