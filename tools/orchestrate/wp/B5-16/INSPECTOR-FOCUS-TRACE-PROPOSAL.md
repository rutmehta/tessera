## Proposed source locations and API

- New App/InspectorFocusTrace.swift: @MainActor internal diagnostic collector; disabled by default. Only explicit --inspector-focus-trace <new-output-path> enables it. Parse once when KeyRouter is created; do not add @Observable properties, SwiftUI modifiers, focus bindings or shared singleton ownership. Normal launch allocates no collector and performs no semantic AX reads.
- App/KeyRouter.swift: existing install local monitor at lines38–46 is the only event interception point. Inside its EXISTING MainActor.assumeIsolated block, immediately before the existing handle/handleKeyUp invocation, capture a scalar diagnostic record; invoke that existing handler exactly once; append its handled result immediately afterward; keep the existing handled ? nil : event return unchanged. No second monitor, dispatch/post/synthetic event, focus setter, keyEquivalent, sendEvent, swizzle or routing branch.
- Scope to keyDown and key codes48/49/36/76 (Tab/Space/Return/keypad) without Command/Control/Option, including ShiftTab. The trace itself never sends an activation event; the initial A GUI run uses Tab/ShiftTab only, so Load cannot open its chooser. Ignore non-document events and events whose window is not the current owned key document window, or is modal/sheet/panel. Do not trace typed text.
- Internal proposed capture(event, window) -> value-only Snapshot; finish(snapshot, handled) -> Void. Limit32 captured events/64KiB serialized output; emit one truncation marker and stop collecting. Lifetime is one explicitly launched process. Fail diagnostic enablement if output cannot be created exclusively; never overwrite an existing file or change app behavior due to trace I/O failure.

## Semantic capture at the same event boundary

Use public in-process AppKit accessibility APIs from the installed SDK, not AXUIElement cross-process calls to self (which can block/reenter), private SwiftUI classes, KVC or selector guessing.

SDK reference: AppKit.framework/Headers/NSAccessibilityProtocols.h at453–454 declares accessibilityApplicationFocusedUIElement for the application's AXFocusedUIElement query;251 declares focused,362 identifier,386 children,389–390 navigation-order children. NSAccessibility.h at160–163 declares unignored element helpers. These APIs expose semantic objects; their result is Any/object, NEVER assumed to be NSView. Confirm Swift importer names during A compilation; use NSAccessibility protocol accessors only where the returned object supports that public protocol.

Primary capture: NSApplication's public application-focused accessibility element immediately before routing, alongside event.window.firstResponder from the SAME synchronous monitor call. Extract public role/subrole, static identifier, focused Boolean and containing accessibilityWindow identity when available. No accessibilityValue/text contents, file paths or arbitrary labels. Record native responder type and process-local identity, whether NSText/NSTextField/NSControl/KeyOwningControl, event/window identity, sequence/eventNumber/timestamp/keyCode/modifiers, keyWindow match and read-only fullKeyboardAccess policy. Do not infer semantic focus from native class.

Validate focused element's containing window against the captured event window via public accessibilityWindow; if unavailable, bounded accessibilityParent traversal may establish membership. Missing/inconsistent membership is UNKNOWN, not viewport focus. Never hold either object beyond capture. Record absence/unsupported accessor/error explicitly.

Only if primary semantic focus is absent/incomplete, bounded traversal may inspect event window's public accessibilityChildren / navigation-order children (prefer navigation-order; no duplicate traversal). Use identity-based visited set, maximum64 objects and depth8. Traverse semantic objects, including non-NSView accessibility elements. Read only role/identifier/focused/window/parent metadata and children; unsupported protocol objects are recorded as opaque. Limit native responder nextResponder ancestry to8 with a visited set too. Multiple focused candidates, cycle, truncation or conflicting membership => AMBIGUOUS/INCOMPLETE. Never select the first labelled button as proof. Cap iteration of returned child arrays; API materialization itself is not a timing guarantee.

All semantic reads and native capture run before the route handler, without actor hops/await. Snapshot stores strings/numbers/Booleans only; no retained view/window/AX object references. finish adds handled/drop decision, not a fabricated after-dispatch focus. If handler drops Tab, a same-event record still identifies the pre-routing focus. Next input event captures any subsequent native focus after a passed event. If post-dispatch observation is later needed, explicitly design a distinct public boundary; an async callback is not proof of completed native traversal.

AX getters can lazily materialize accessibility state and affect timing. Do not call them from SwiftUI body/update or add new tracked reads. Record that limitation and compare trace-disabled and trace-enabled reproduction on the same candidate. Treat a failure disappearing with trace enabled as instrumentation-sensitive, not fixed. Do not increase event traffic or add polling to force a reproduction.

## Output and lifetime safeguards

Serialize bounded JSONL snapshots to the explicit new artifact only after capture+existing routing result, never raw keystroke strings or document names. Include configuration/version/source hash in header supplied by A's packaging manifest. Retain no responder closures/observers/notifications, add no monitor beyond existing KeyRouter monitor, and introduce no timer. Collector owns only a bounded output handle/value buffer; close on disable, quota exhaustion or teardown. An I/O error disables collection and records an error through the bounded diagnostic channel if possible; it must not swallow/redispatch user events. A reviews writer lifetime before integration.

Suggested fake collector tests (future source, not authored/run here): disabled path never invokes AX provider; excluded events never invoke provider; semantic non-NSView button with matching window captured; missing/opaque/multiple focus yields unknown; parent/child cycles terminate; node/depth/event/byte caps terminate; no raw text/value output; handler exactly once with identical return for pass/drop; collector deallocation releases no windows. These tests cannot establish the actual SwiftUI focus path.
