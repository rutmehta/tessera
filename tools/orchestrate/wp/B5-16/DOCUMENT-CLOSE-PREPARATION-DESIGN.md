## Proposed API and ownership (names provisional)

All public coordination is MainActor; backend work retains its current queue affinity. Types do not mention SaveGate.

- prepareClose(documents: [DocumentController], reason: tab/window/quit, requestID: UUID) async -> PreparationOutcome: ready(DocumentCloseTicket), cancelled, or blocked(DocumentPreparationFailure).
- commitClose(ticket) -> CommitOutcome: committed or stale/blocked. It consumes a ready ticket at most once; duplicate calls return the cached result, never close twice.
- cancelClose(requestID/ticket) async -> CancelOutcome: retained or blockedRestoration. Idempotent; cancels preparation intent, dismisses only that request's prompts, waits for admitted operations to drain, releases reservations and restores editing. It does not undo a completed file save.

A workspace-owned request registry strongly retains the exact workspace, each controller/backend and each draft adapter until preparation reaches terminal state AND in-flight cleanup settles. Controller/backend handles already retain their own engine context; do not resolve a replacement backend through current AppModel.library during completion. Capture both controller object identity and doc.id, a document-lifetime UUID, request UUID, per-document mutation/draft generation, and workspace membership generation. Store ordered documents, previous active tab/selection/focus bookmark, staged decisions, save receipts and reservation handles. An opaque ready ticket refers to that registry entry; a dropped UI task cannot abandon in-flight ownership. A global Quit caller must explicitly commit or cancel its ready ticket. Ordinary duplicate close requests for a reserved document join the existing preparation result or report busy, never create competing prompts.

One terminal PreparationOutcome per request, atomically latched before invoking observers/continuations. Save/prompt child operations have their own IDs and one settlement each. A cancelled caller does not cancel a backend save underneath another observer. Stale child callbacks only settle owned work/resources; they cannot dispose, change a new sheet, or deliver a second preparation result. Retrying a terminal blocked/cancelled preparation creates a new request; saved document state remains available.

## Preparation protocol and choices

1. Capture and deduplicate exact controllers in stable tab order. Reserve them before any await. For Quit/window scope also reserve workspace membership: prevent opening/closing/replacing tabs while the ticket is live, or invalidate the entire ticket if an external membership change arrives. A tab-close ticket need only reserve its target. Do not switch active tabs as an implementation shortcut; prompts name their captured document.
2. Freeze mutating admission, not just disabled buttons. Snapshot local Text/IME, brush/coalescer, transform/retouch and controller debounce/live-adjustment state. Drain already admitted backend operations and callbacks with result-bearing queue fences; callbacks may not silently schedule another generation behind the fence. Keep local unsent drafts recoverable. Read backend dirty state only after drain; effective dirty is backend dirty OR local draft/pending edit. A clean backend with unsent text must still prompt.
3. Prompt each effective-dirty document serially (one sheet at a time): Save, Cancel, Don't Save. Save finalizes retained drafts through result-bearing adapters, waits for acknowledgements, then writes. Don't Save stages permission to dispose THIS captured generation at final commit; do not cancel/remove drafts or close a controller yet. Cancel aborts the whole preparation and restores all surviving documents, including earlier staged Don't Save decisions.
4. Save success records path, accepted mutation/draft generation and refreshed dirty state; controller remains open. A saved document may now be clean even if later preparation is cancelled; saving is a real side effect, not rolled back. Reject generation drift, unresolved draft, save error, or dirty-after-save as blocked. Already-clean documents receive a no-save decision only after fences/generation checks, never merely from stale info.dirty.
5. Return ready only when every captured document has a valid decision, no unresolved prompt/save/draft work remains, and every reservation is still valid. Keep reservations/controller ownership until global caller commits or cancels. Never dispose earlier documents while prompting later ones.

Missing window: dirty/draft-bearing preparation returns blocked(presentationUnavailable), retaining everything. Never use legacy close's discard fallback or saveAs's default-folder write fallback. Headless tests inject prompts and explicit destinations. Clean documents may prepare without a window after fences. If a window disappears while prompting, settle cancelled/presentationUnavailable and retain docs; no hanging callback. Restore/reveal a suitable window is the global caller's responsibility.

Save As: explicit typed outcomes saved(receipt), cancelled, failed(error). Sheet Cancel, interactive sheet dismissal, parent-window loss and Replace Cancel all settle exactly once. Replace acceptance must match request/child IDs before writing. Existing-file replacement requires that captured approval; no fallthrough default path. Save As may update document path/title and lastSaveFolder only for a confirmed write of that request; a late successful admitted write after cancellation still updates accurate document state, but never revives ready/commit or a superseded sheet. Cancelling before write admission prevents the write. Cancelling after asynchronous save admission waits for its actual outcome, retains the controller and reports saved-or-failed reality without rollback promises. The current backend save is synchronous, but prompt scheduling and a future off-main save must use the same lifecycle contract.

## Draft adapters are prerequisites, not hidden behavior

Introduce small Document-owned participant interfaces: captureAndQuiesce(document, generation), finalizeForSave(capture) -> Result<receipt, failure>, restoreAfterCancel(capture) -> Result, and disposeAfterCommit(capture). Exact implementation stays with the owning Text/tools/retouch/controller sources. Preserve snapshot ownership until backend acknowledgement; do not reuse today's destructive local-state clearing helpers unchanged.

Text must capture marked composition and pending latest text, drain older previews, and acknowledge commit before save; rejection retains/restores the local draft instead of silently replacing it with committed text. For Don't Save, retain the draft/IME state through preparation; dispose only at final commit. Brush must drain acknowledged batches and latest unsent points in order, acknowledge stroke end for Save, and never replay accepted points after a failure. Transform must retain its model until commit succeeds; cancel-preparation is not equivalent to cancel-transform. Debounced controller edits must be captured/fenced rather than dropped by close. Generation tracking increments at mutation admission (including local drafts and queued tools), not when UI reloads; DocumentController.revision is unsuitable.

An active Remove/model download or other unbounded tool job must not make Quit launch downloads or expensive completion work implicitly. Return blocked(toolPending), leave job/draft retained, and offer returning to the editor to finish or explicitly cancel that tool through its existing flow. A separately authorized cancellation must drain before retry. Apply the same conservative blocked rule to any participant without a proven result-bearing fence/restoration path. Inventory filters, smart bake/copy operations and all other queued writers before enabling production preparation; unsupported busy participants fail closed, not 'clean'. No promise of full draft support based only on Text and brush inspection.

## Commit and cancel invariants

commitClose performs an all-document preflight in one MainActor turn: same workspace/lifetime/controller identity, exact membership set for Quit, same reserved mutation/draft generation, successful Save receipts or explicit Don't Save decisions, no in-flight admitted work. Failure disposes ZERO controllers and invalidates/blocks the ticket. Read-only redraw/reload does not invalidate a mutation-generation token. Pending work or external mutation that bypasses admission must invalidate the ticket, not be accepted under old Don't Save consent.

After preflight, mark ticket committing/consumed before callbacks can reenter. Keep reservation active and perform disposal once per captured controller in deterministic order; suppress/reject nested close requests and batch workspace current-tab notifications until the batch is settled. Only here call documentClosing hooks, remove tabs and DocumentController.close. Current backend.close is void; this is a host disposal ordering guarantee, not transactional backend shutdown or recoverable partial close if a future throwing teardown is introduced. No disposal should launch a new edit or unresolved cancellation: those must be fenced in prepare. Releasing ticket ownership is last.

cancelClose before commit latches cancellation, invalidates outstanding prompt tokens and prevents new writes, then drains admitted saves/edits. Restore unsaved local state and prior active tab only under the same workspace/request identity; do not steal a newer workspace. Successfully saved drafts may remain accepted/clean, and paths stay saved; cancel is not undo. Failed draft/save work remains retained with actionable error. If restoration itself fails, retain a blocked restoration record, keep affected controls disabled and expose retry; do not report an editable document falsely. Cancel after commit reports alreadyCommitted and does not try to resurrect disposed documents. A late global Quit veto must cancel a READY Document ticket, while A separately restores any already-closed Develop editor; this API does not implement that AppModel recovery.

## Proposed deterministic tests (all UNRUN)

Use a dedicated DocumentClosePreparationTests.swift with injected prompt/save/draft continuations, mutation counters and close spies; no native sheets, disk writes, fixed sleeps or GPU. Tests exercise adapter contracts as well as coordinator state.

1. Clean doc: ready leaves close/detach/tab-removal counts zero; commit closes once; repeated commit/cancel does not double-close.
2. Dirty Save: pause save callback; no ready/disposal. Success -> ready -> cancel keeps document usable and accurately clean/saved; commit path disposes only after explicit commit.
3. Dirty Don't Save: ready preserves draft and dirty doc; Cancel retains it. Commit disposes only captured generation. Dirty no-window returns blocked with zero save/dispose.
4. Save As Cancel/dismissal, Replace Cancel, window loss, and write error each settle once, retain controller, never invoke legacy success fallback. Duplicate/late callbacks cannot affect newer request.
5. Cancel during admitted async save: controller retained until callback; success updates path/dirty truth but cannot revive ready; failure retains error. Cancel before write admission yields zero writes.
6. Multiple docs: A Save succeeds, B Don't Save staged, C Cancel/error -> all remain open; A stays saved and B's draft remains. All-ready commit closes exact ordered set once. Membership/generation drift preflight closes zero.
7. Pending Text on backend-clean doc: prompt required; Save waits for preview/commit fence; rejected commit preserves text/IME; Don't Save + preparation cancel preserves draft.
8. Brush/transform: accepted prefix is not replayed on retry; Save does not run before pending points/end/transform acknowledgement. Busy retouch/model-wait or unsupported writer returns blocked without launching work.
9. Concurrent close callers, prompt reentry, abandoned consumer, active-tab change attempt, callback from old document lifetime: single settlement and ownership preserved; no wrong-controller close.
10. Global integration: ready Document ticket plus successful Develop close then later Quit veto cancels Document ticket without any disposal; A's independent test proves Develop reopen. No AppModel type coupling in Document tests.
