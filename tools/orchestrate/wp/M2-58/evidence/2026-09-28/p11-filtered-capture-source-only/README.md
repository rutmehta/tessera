# Filtered ScreenCaptureKit capability helper — UNRUN source

Source: /tmp/tessera-p11-filtered-capture-capability.m. No compile, stream or capture was executed during preparation. Uses installed public AppKit, CoreGraphics, ScreenCaptureKit, CoreMedia, CoreVideo, QuartzCore and mach APIs. Future build requires ARC and those frameworks (Foundation included through AppKit); CommonCrypto supplies frame SHA256. Use an external BetterSSD executable/output and preserve source/binary hashes and direct exits in the separately granted lane.

Run takes one JSON configuration path. Required keys: output_dir (new directory with existing parent under /Volumes/betterSSD), bundle_id (must start dev.tessera.m258.), app_path (resolved .app under BetterSSD), pid, launch_epoch (exact NSRunningApplication launchDate.timeIntervalSince1970), window_id, display_id, and roi_display_points object with x/y/width/height. Numeric identifiers must be positive; ROI must be finite, nonnegative, nonempty and at most512×512 points. Resolve identity and geometry from the actual newly launched isolated test app; never invent the IDs or date. ROI is display-local in the display's logical coordinate system; the helper validates the equivalent global rectangle against the exact current test window and display.

Before enumeration or capture it checks CGPreflightScreenCaptureAccess for its own process, records the result and exits if unavailable. There is no permission request call. It rejects any normal production bundle, app path outside BetterSSD, wrong PID/bundle/path/launchDate, nonregular/inactive app, wrong window owner/layer, offscreen window, out-of-window ROI, or subsequent window movement/foreground/identity change.

The SCContentFilter includes only the one validated test window on the selected display. It excludes the menu bar, cursor and audio. It never creates an unfiltered desktop stream. This protects other applications' pixels, but deliberately does NOT prove that a privately filtered window was unobscured on the physical desktop. Capability label is repeated in preflight/config/result. No input/revision matching, expected-detail comparison, P11 latency evaluator or acceptance decision exists.

Capture window is2 seconds after successful start, with2 seconds each for enumeration/start and1 second for stop. A9-second process watchdog writes watchdog.json and exits124 if bounded completion fails. It saves at most8 complete frames and256 callback metadata records. Main-runloop pumping services serialized callbacks; sample delivery uses a dedicated serial queue and synchronous handoff, avoiding an unbounded retained-buffer queue. Identity/foreground/current window bounds are checked immediately before saving. Failed guards disable saving and lead to stop. Every pixel payload is tightly packed BGRA (row padding deliberately omitted), with width/height/source and saved strides/SHA256. Frame records retain raw status, raw WindowServer displayTime mach ticks, callback ticks and geometry/scale attachments; preflight retains mach timebase. Output is intentionally1 pixel per ROI point for a bounded API capability check, not a claim of pixel-exact physical detail resolution.

Outputs: preflight.json, stream-config.json, frames.json plus frame-NNN.bgra, result.json (or early error/watchdog evidence). Direct0 requires a successful start and stop, no guard failure, and at least one saved complete frame. Direct0 is API/pixels/timestamp capability only. A later actual-visible P11 oracle remains separate. If a metadata write, unsupported layout, authorization, enumeration or stop fails, preserve the result and direct exit; do not silently retry or expand capture scope.
