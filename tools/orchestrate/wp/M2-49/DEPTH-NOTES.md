# M2-49 depth and bokeh implementation

`ml_depth::CachedDepthEstimator` is the reusable interactive/export adapter. `from_support` uses `models/models.toml`, verified `models/cache` weights (override `TESSERA_DEPTH_MODELS`), and a 256 MiB lossless raster cache in `previews/depth-cache`. `estimate(&RgbImage)` first uses cached inference and lazily loads Depth Anything V2 Small with no downloads. Model identity, source pixels/dimensions, and preprocessing/refinement revision determine cache identity. Focus, amount, and aperture settings do not alter depth inference and intentionally reuse the plane. A missing model yields a clear Lens Blur message; failed session loading preserves the cache for retries.

`DepthMap::near_to_far` returns recipe/pipeline convention near=0/far=1. `histogram` returns 256 near-to-far bins including both endpoints. `visualisation` returns RGB grayscale near white/far black. `focus_range_for_subject` validates a same-size subject alpha raster and selects alpha-weighted 5th–95th percentiles. Empty masks fail clearly. `CachedDepthEstimator::subject_focus` uses ml-segment's subject cache and inference; a cached subject needs no weights, while fresh subject inference currently needs U2Net plus both SAM models because Segmenter loads all three. Registry policy prohibits downloads even if weights disappear between verification and loading.

The scalar layered blur now supports circle/disc, hexagon, octagon, bubble, 5-blade/five-blade/pentagon, ring, cat-eye/cat_eye/cat eye, and oval/anamorphic. Bubble has an emphasized rim; ring has hollow central support; oval has fixed 2:1 vertical aspect; cat-eye clips the pupil radially toward corners. Runtime cat_eye strength accepts finite 0..=1. Recipe schema remains unchanged. Inclusive focal-range pixels remain exact copies. These are discrete aperture approximations, not physical lens simulation; the existing O(pixels * occupied_layers * radius²) CPU performance limit remains.

No Swift changes. M2-50 may expose new shapes; its existing BokehShape enum currently lists circle/hexagon/octagon only. The schema has no persisted boost or cat-eye strength field; runtime options expose those controls.

Validation evidence: depth-helpers-red.log records missing helper APIs; bokeh-red.log records rejection of the new shape. depth-bokeh-green.log records the focused regression result. depth-fmt.log records formatting validation. Existing model fixture tests skip when pinned weights are unavailable; no weights were downloaded.

Follow-up verification: depth-edge-green.log passes four depth tests (including corrupt cache recovery) and the model fixture entrypoint; pinned weights are absent so that entrypoint exits via its existing clean skip. depth-model-availability.log records no weights/no photograph fixture. bokeh-edge-green.log passes all eight aperture types under maximum clipping for constant negative, positive, and f32::MAX values. depth-bokeh-clippy.log passes ml-depth and pipeline-cpu all-target clippy with warnings denied. The public MISSING_MODEL_MESSAGE constant is the stable missing-weights classification for export; corruption/inference errors do not use it.

## Image-core wrapper follow-up

`depth-wrapper-red.log` observed three integration failures before fixes: zero amount required a provider, cached inference ignored explicit model provenance, and a failed new-image estimate exposed the prior histogram. `depth-wrapper-green.log` passes seven depth-hook integration tests after fixes. Zero amount validates the CPU blur contract and returns an exact clone without inference/provider access. Model-backed providers accept only the pinned explicit model reference; supplied camera/ready maps remain caller-owned. Failed estimation clears the latest histogram; subject-focus estimation also publishes its depth histogram. Cached rasters are verified to work without model weights and no weights appear in the model cache.

`depth-display-endpoints-green.log` verifies display visualization near=255/far=0; direct RGB linear visualization retains near=1/far=0. Provider replacement and visualization toggling use distinct memo entries. No changes to rgb_render.rs were needed for these additional tests; the root agent had already integrated provider identity and visualization mode into memo keys.

## Current-recipe histogram freshness

The FFI histogram API no longer returns the provider's last histogram without checking the current recipe. It renders the current recipe's pre-geometry model input, reuses the content-addressed depth estimate, and returns that estimate's own histogram directly. This also avoids a second shared-state read racing another estimate. `histogram-freshness-observed-red.log` records the regression failing when a cached histogram bypassed an unsupported updated process version; `depth-histogram-freshness-green.log` passes the regression after the change, using a seeded depth raster and no model weights.

Read-only stage comparison found ordinary and AI-mask exports infer depth after detail/tone/color/locals and before blur, point effects, and geometry, matching the interactive barrier. Viewport/histogram proxy inputs and full-resolution export inputs have different content/dimension cache keys; identical numerical depth across scales is not guaranteed.
