1. **P13 — viewport-only composition.** Wire the existing `resident.render_viewport` into the FFI render path for scenes it supports, using the visible source rect the FFI already computes plus the documented halo; keep the full-level path as fallback only for operators that need a full halo, and log which path each frame took. Acceptance: at 100 % zoom on the 20 MP/100-layer bench document, the rendered region equals viewport + halo (assert in a test, not just a log), pixel parity with the full-level render for pan, resize and incremental updates, and p95 < 50 ms for a 4K viewport measured to completed frame (separate from display).
2. **P14 — render from an immutable snapshot.** Take a COW snapshot of the document state under the lock, release the lock, then do filter prep and composition from the snapshot and publish generation-checked results (drop stale frames). CPU fallback (styles) must no longer hold the live lock through `cpu_present`; save must not do file I/O under the live lock. Acceptance: with a slow style/filter frame in flight, synchronous UI mutations (opacity, rename, visibility, text edit) have p95 < 2 ms and max < 8 ms; race tests for save/render/undo keep history and surfaces valid.
3. **P17 — resource policy.** Register document render and filter-worker pressure with the jobs resource policy (`jobs::pressure`), with bounded yielding/admission, without merging separate GPU queues. Acceptance: while a photo export runs, document input-to-present p95 ≤ 1.25× the idle baseline, and the export still completes with bounded progress; log memory and each pool's occupancy.
