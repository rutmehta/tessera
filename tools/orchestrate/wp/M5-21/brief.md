# WP M5-21 — `transform` crate: free transform, warp mesh, perspective warp, puppet warp, content-aware scale

Read docs/02 §6 (Transform & geometry) and its implementation notes, crates/compositor (document.rs SmartObject affine transform, raster.rs, edit.rs DocOp, COMPOSITOR.md §3 and §9), crates/filters (how a filter exposes CPU + Metal evaluation and plugs into the smart-filter stack via compositor_adapter.rs), crates/lens (composed geometry map, resampling kernels — reuse, do not duplicate), crates/gpu-core.
Build `crates/transform` (Apache-2.0, workspace member) providing, on planar f32 premultiplied RGBA rasters at any level:
1. **Free Transform**: affine + homography (scale/rotate/skew/distort/perspective/flip about a reference point) via inverse mapping with nearest/bilinear/bicubic/Lanczos-3 and an "automatic" chooser; exact bounds computation; alpha-correct edges.
2. **Warp**: Bézier mesh (4×4 default, subdividable, presets arc/arc lower/arc upper/arch/bulge/shell/flag/wave/fish/rise/fisheye/inflate/squeeze/twist with bend parameter; split lines) inverted per pixel by Newton iteration with a pre-rasterised displacement field fallback; tests for round-trip of identity, monotone meshes, and out-of-mesh regions.
3. **Perspective Warp**: user quads → per-quad homographies with shared-edge continuity, bilinear blend across quads.
4. **Puppet Warp**: triangulated alpha shape (normal/rigid density, expansion), pins with rotation, ARAP deformation solved by local/global iterations; deterministic.
5. **Content-Aware Scale**: seam carving (forward energy = gradient magnitude + protect mask + optional skin-protect hook), both axes, amount parameter.
All non-destructive: define `TransformOp` (serde, versioned) that the compositor stores on a layer/smart-object as a smart-filter-like stage; wire it into the compositor's smart-filter stack (crates/compositor/src/edit.rs DocOp, format.rs, psd.rs — for PSD map affine transforms of smart objects to the placed-layer `PlLd`/`SoLd` records and leave warp meshes as native-only with a documented degradation). GPU port of free transform + warp via a displacement texture in the resident renderer is required (bit-exact vs CPU within 1e-4 after the same kernels; use gpu-core precise compilation). Benchmarks: 36 MP affine bicubic CPU < 400 ms, GPU < 30 ms. Write `crates/transform/TRANSFORM.md` with formulas, limits and what is not done. Gate: `cargo test -p transform -p compositor --release && cargo clippy -p transform -p compositor --all-targets -- -D warnings && cargo fmt --check`. Allowed: Cargo.toml,Cargo.lock,crates/transform/**,crates/compositor/**,tools/orchestrate/wp/M5-21/**. Do not edit engine-api or resident GPU files other than to add the displacement stage.
