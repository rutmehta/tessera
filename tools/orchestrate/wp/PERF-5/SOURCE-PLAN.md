# PERF-5 source-only plan (base `ebae08bb7c11a956ba3ec4c10a7087c6c190b645`)

## Evidence and boundaries

`docs/coordination/CODEX-BRIEF-2026-09-30.md` defines PERF-5 as memory ceilings for Camera Raw preview and Export Flat; PERF-2 owns compatible-intermediate caching for Camera Raw and PERF-1 owns style-plane/blur reuse. `origin/wp/B5-prof:tools/orchestrate/wp/B5-prof/REPORT.md` is diagnostic under load, not a clean limit: 24 MP Camera Raw 100% preview with global vignette is reported as 10,244 ms, +2,564 MB incremental heap, and ≤7,074 MiB whole-process RSS. The benchmark measures the full call's requested live Rust heap via a process-wide allocator; RSS includes process setup and other resident allocations. Export Flat's 7,471 MiB is explicitly RSS for the **entire UI perf suite** (18 MP smart-filter and 14 MP styled cases), not one Export Flat job. The closest isolated value is a distinct 24 MP engine worker run at 1,351 MiB process RSS. Do not report either RSS number as a live-heap ceiling or attribute suite RSS to one export.

`crates/tessera-ffi/tests/document_camera_raw_preview.rs` already has a process-global `Counting` allocator (`alloc/realloc/dealloc`) and `peak_during`; ignored `bench_camera_raw_24mp` prints (does not assert) peak heap for local/global fit/100% preview. A regular test asserts a local 256×192 viewport's peak remains below 24 MiB and tests work count; it only prints the global fit preview's pixel count. `crates/tessera-ffi/tests/document_export_flat.rs` has a CPU-composite pixel golden for a small PNG plus cancellation/snapshot checks, but no allocation counter or explicit memory bound. Existing isolated count-allocator patterns are in `crates/tessera-ffi/tests/document_adaptive_memory.rs` and `crates/filters/tests/adaptive_lattice_memory.rs`; these also count Rust heap, not OS/Metal/stack memory.

## Camera Raw live buffers

- Whole-image work is required for global settings by `crates/tessera-ffi/src/document/filters.rs::camera_raw_halo`: lens/CA/defringe, Dehaze statistics, placed effects, geometry, locals and non-default raw stages return `None`, causing the worker to render the whole image at the requested level. At level 0, a visible 1600×1000 viewport with a global effect still means the whole 6000×4000 source.
- `crates/filters/src/camera_raw.rs::evaluate` is the dominant conversion path. It reads the entire tiled RGBA raster to `Buffer.pixels: Vec<[f32;4]>` (16 B/px), allocates three full planar f32 images (12 B/px), creates an `image_core::RawImage`, renders a second three-plane developed image (at least another 12 B/px live), clones the interleaved source for the result (another 16 B/px), then writes the clone back to a copy-on-write raster tile-by-tile. It also hashes exact source rows. Thus a 24 MP call has several hundred MiB of simultaneously live frame buffers before caches, tiles, row-hash scratch or output slots; this is directly consistent with the large allocator peak.
- The image-core `Renderer` is configured with a 256 MiB cache at the call site, but that bounds only that cache, not total transient live buffers or process RSS. The global `profile_curves` cache holds up to 16 small transfer tables and is not the dominant frame allocation.

**Minimal PERF-5 candidate:** bound temporary working memory by converting source tiles/rows directly into the required planar RGB source (no full `Buffer` RGBA copy); hash incrementally without a row-sized temporary; render as today; then read input tiles and developed pixels to construct output tiles directly (preserve source alpha and encoded opacity blend), avoiding `source.clone()` and full result `Buffer`. Preserve current global full-image math and cache identity. Add an area-based checked estimate/admission limit for any unavoidable full-frame working set, with a clear recoverable resource error before allocation; a fixed `Vec` cap alone does not bound other caches or RSS. PERF-2 owns cache-key/intermediate reuse and the shared `filters/src/camera_raw.rs` preview path; coordinate before touching it. PERF-5 should own the peak-allocation oracle/test and buffer-lifetime contract, while PERF-2 owns caching. If both modify `camera_raw.rs`, agree on one shared patch owner first.

**Correctness oracle:** on a synthetic 24 MP tiled raster with a varying non-sRGB ICC profile and alpha, compare full global-vignette preview output against pre-change full-frame pixels (exact or stated f32 tolerance), assert unaffected alpha, check crop/output extent and one-pixel edge samples. Assert `camera_raw_pixels_developed` equals the whole-level pixel count for global work and remains viewport+halo for local settings. In an isolated serial allocator test, construct document before measurement; measure the cold and warm global preview separately with a declared live-heap growth ceiling. The same test's unchanged output golden ensures the bound comes from reuse/lifetime changes, not skipping global pixels. Do not turn RSS into the allocator assertion.

## Export Flat live buffers

- `crates/tessera-ffi/src/document/io.rs::export_flat` eagerly materializes full-frame interleaved RGBA f32 (`render_rgba`, 16 B/px). A profile conversion additionally allocates full RGB `[f32;3]` (12 B/px). PNG/TIFF allocate a complete quantized 8/16-bit image (4 or 8 B/px); JPEG allocates complete RGB u8 (3 B/px). Encoded file bytes accumulate in `out: Vec<u8>` through encoding and `write_atomic`. At 24 MP, the RGBA float buffer alone is 384 MB; simultaneous quantized/output buffers add materially to peak.
- `render_rgba` does not retain all tiles and the final image together: workers feed a sync channel and the receiver interleaves tiles immediately. However queue capacity is `2 * available_parallelism`, and `available_parallelism` is not capped here; each worker may also hold a tile/render temporaries. `coords` is an O(tile-count) list. The compositor is created with a nominal 256 MiB budget, but `Compositor::new` gives that budget separately to live, smart-filter runtime and render caches; `FilterPassLimits::default()` separately permits 1 GiB retained CPU smart-filter results and explicitly excludes evaluator/temp/tile/GPU allocations. These are not a single aggregate process ceiling.
- Canvas validation in `crates/tessera-ffi/src/document.rs::Engine::new_document` only caps each side at 300,000, not total pixels or export working bytes. Existing `transform::MAX_IMAGE_PIXELS` and style-filter pixel limits apply to their own operators, not generic Export Flat admission.

**Minimal PERF-5 candidate:** first cap export worker concurrency and in-flight tile queue (e.g. fixed small worker/buffer count) so tile working memory has a hard bound independent of host core count. The larger bound needs row/band streaming: composite a bounded number of tile rows, convert ICC color and quantize that band in place, feed a streaming encoder, then release it. Avoid holding full-frame RGBA plus full-frame `rgb`/quantized arrays plus `out`. Stream to a same-directory temporary file and atomically publish on success; cancellation must leave the destination untouched. PNG/TIFF support should use row/strip encoding if the current encoder APIs allow it. JPEG currently receives a full RGB `&[u8]`; until a bounded incremental path is proven, give JPEG an explicit checked pixel/working-set cap or implement an incremental encoder. Do not promise a total process-RSS ceiling: third-party encoders, allocator arenas, file mappings, compositor caches and OS/GPU memory sit outside a Rust live-heap counter. PERF-1 owns style blur/effect-plane caching in `compositor/src/render/styles.rs`; PERF-5 can bound export's shared tile/encode buffers and must coordinate if its memory work changes style materialization.

**Correctness oracle:** extend `document_export_flat.rs` with a medium/large multi-tile F32/U16 synthetic document and run allocation measurement only around `DocFlatExport::run` (fixture/document creation outside measurement). Assert a fixed peak Rust heap growth budget, monotone progress/cancel semantics, and decoded pixels + ICC equal the existing CPU composite. Compare PNG/TIFF pixels exactly after quantization; JPEG needs the existing encoder's deterministic decoded-pixel tolerance. Run a separate peak test for opaque and translucent layers and a non-Document export profile to cover the ICC conversion buffer. Report allocation-counter peak and separate external RSS sampling; never claim the counter includes RSS, Metal, C stacks or memory retained before the measured baseline.

## Ownership recommendation

PERF-1: style rendering/reuse, styled-export algorithm and its pixel parity. PERF-2: Camera Raw compatible-intermediate caching, cache invalidation and preview work reuse. PERF-5: explicit memory budgets, transient-buffer lifetime reductions, streaming/export worker caps and isolated counting-allocator acceptance. `filters/src/camera_raw.rs` is the obvious overlap: PERF-2 should own cache design there; PERF-5 may change source/output conversion only by coordinated small hunks or with PERF-2 as co-owner. Avoid attributing the 7.5 GiB suite RSS to Export Flat or treating the 7 GiB process peak as 7 GiB of live Rust heap.
